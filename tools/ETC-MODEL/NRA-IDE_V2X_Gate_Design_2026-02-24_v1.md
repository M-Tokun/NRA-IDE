## 0. 本文書の目的 / Purpose



V2X（Vehicle-to-Everything）環境において  

複数車両間で NRA-IDE Gate の情報を共有する際の  

**アーキテクチャ・禁止事項・通信断時の安全設計・信頼性**を定義する。



> **V2X での最大の危険：**  

> 他車の Gate 情報を受信して**自車の τ を変更する**こと。  

> これは因果ダイオードの逆流であり、絶対に禁止する。



---



## 1. V2X における Gate の本質的な問題

## Core Problem of Gate in V2X Context



V2X と NRA-IDE を組み合わせると、以下の誘惑が発生する。



```

誘惑 1: 集合知による τ 最適化

  「前方10台がすべて R=0.2 なら

   自車の τ を少し緩めても安全では？」



  → τ を他車情報で変更 = 混用（NG）

  → 「みんな安全だから私も安全」は保証ではない



誘惑 2: 他車の FAIL-CLOSED を自車判断に使う

  「前方の車が FAIL-CLOSED を発動した

   = 危険なので自車も止まろう」



  → これは接続（OK）の範囲内

  → ただし「他車の情報だから信頼できる」は危険

  → 通信が偽造されている可能性がある



誘惑 3: インフラからの τ 更新

  「道路管制システムが "この区間は τ=5m に変更せよ"

   と V2X で送信してくる」



  → τ の変更は OTA クラス A プロセスを通過した場合のみ許可

  → V2X 経由のリアルタイム τ 変更は禁止

```

## 2. V2X における Gate 情報の分類

## Classification of Gate Information in V2X



Gate に関連する V2X 情報を**受信してよいもの / 禁止のもの**に分類する。



### 2.1 受信・利用可能な情報（観測データ）



```

他車から受信する情報:

  ├─ 他車の位置・速度         → 自車センサー入力として利用可

  ├─ 他車の FAIL-CLOSED 発動  → 自車への「危険警告」として利用可

  ├─ 他車の Zone 情報          → 周辺状況の観測として利用可

  └─ インフラの路面状況        → 自車 μ 算出の参考として利用可



インフラから受信する情報:

  ├─ 工事区間・速度制限変更   → 制御層への入力として利用可

  ├─ 気象情報（積雪・凍結）   → 路面 μ 選択の参考として利用可

  └─ 緊急車両接近             → 制御層への入力として利用可

```



### 2.2 受信禁止・τ 変更に使用禁止の情報



```

禁止:

  ✗ 他車の R 値を根拠にした自車 τ の変更

  ✗ インフラからの「τ を X に変更せよ」指令

  ✗ 他車の Gate 状態を学習データとして使用

  ✗ 周辺車両の平均 R 値による自車閾値の動的調整



理由:

  V2X 経由の情報は

  ① 遅延がある（通信遅延 50〜200ms）

  ② 偽造の可能性がある（なりすまし攻撃）

  ③ 部分的にしか見えない（見えない車両がある）

  

  これらの不確実性を含む情報で τ を変更すると

  保証の基盤が通信品質に依存してしまう

```

## 3. 正しい V2X × Gate アーキテクチャ

## Correct V2X × Gate Architecture



### 3.1 情報流の設計原則



```

【V2X 情報の処理パイプライン】



V2X 受信

    ↓

[通信信頼性検証層]    ← 認証・遅延チェック・整合性確認

    ↓

[制御・判断層]         ← 他車情報を使って速度・経路を調整

    ↓                     ここで自車センサーと統合

[NRA-IDE Gate]         ← 自車センサー値のみで R 計算

    ↓                     V2X 情報はτに触れない

[アクチュエーター]

```



**核心：Gate は自車センサー値のみを入力とする。**  

V2X 情報は制御層への入力として使うが、Gate の τ・ロジックには届かない。



### 3.2 他車 FAIL-CLOSED の利用方法



```

【正しい利用（接続 OK）】



他車 FAIL-CLOSED 受信

    ↓

[制御層が速度を下げる判断]

    ↓

速度が下がる → 自車の停止距離が短くなる

    ↓

自車の δ が小さくなる → 自車 R が下がる

    ↓

自車 Gate が独立して判定



= 他車情報は制御層を経由して間接的に Gate に影響する

= Gate は自車の物理値だけで判定している

= これは接続（OK）

```



```

【禁止（混用 NG）】



他車 FAIL-CLOSED 受信

    ↓

「他車が止まったから自車の τ を緩めよう」

    ↓

自車 Gate の τ が変わる



= V2X 情報が Gate に直接触れている

= 混用（NG）

```

## 4. 通信断時の安全設計

## Safety Design for Communication Loss



V2X で最も重要な設計課題は**通信が途切れたときの動作**である。



### 4.1 通信断の分類と対応



| 断絶種別 | 継続時間 | Gate の動作 | 制御層の動作 |

|---------|---------|-----------|------------|

| 瞬断（< 100ms） | 極短 | 変化なし（自車センサーで継続） | 最後の受信値を保持 |

| 短断（100ms〜1s） | 短 | 変化なし | 「他車情報なし」モードに切替 |

| 長断（1s〜） | 長 | 変化なし | τ は固定のまま・速度を下げる指令 |

| 完全切断 | 無期限 | 変化なし（Gate は自律動作） | V2X なしの安全走行モード |



```

設計原則:

  V2X が切れても Gate は止まらない

  Gate は V2X に依存してはならない



  「V2X がないと Gate が機能しない」設計は

  通信障害 = 安全装置消失 を意味する

  これは最も危険な設計パターン

```



### 4.2 フェイルセーフ階層



```

通信状態に応じた安全階層:



Level 1（V2X 正常）:

  自車センサー + 他車情報 → 制御層 → Gate

  → 最も情報が多い状態



Level 2（V2X 瞬断）:

  自車センサー + 直前の他車情報（キャッシュ）→ 制御層 → Gate

  → Gate は変化なし



Level 3（V2X 長断）:

  自車センサーのみ → 制御層（保守的な速度設定）→ Gate

  → Gate は変化なし・制御層が速度を下げて補償



Level 4（V2X 完全切断）:

  自車センサーのみ → Gate（単独自律動作）

  → V2X 導入前と同等の安全性を保つ



どのレベルでも Gate の τ は固定・R の計算は変わらない

```

## 5. 信頼性・セキュリティ設計

## Reliability and Security Design



### 5.1 なりすまし攻撃への対処



V2X 通信は偽造・なりすましのリスクがある。  

Gate が V2X 情報に依存すると、攻撃者が Gate を操作できる。



```

攻撃シナリオ:

  攻撃者が「前方車両 FAIL-CLOSED 発動」を偽送信

    ↓

  「他車が止まった = τ を緩めてよい」という

  混用設計の場合 → Gate が意図的に弱体化される



NRA-IDE の構造的防御:

  Gate は V2X 情報を τ に反映しない

  = 攻撃者が Gate を操作する経路が存在しない

  = 構造的に攻撃が無効化される

```



### 5.2 V2X 情報の信頼性検証層



Gate には届かないが、制御層への入力として使う V2X 情報は  

以下の検証を通過したもののみ使用する。



```

検証項目:

  □ メッセージ認証（PKI / C-V2X セキュリティ）

  □ 遅延チェック（受信タイムスタンプ - 送信タイムスタンプ ≤ 閾値）

  □ 位置整合性（送信元の主張位置と実測位置の照合）

  □ R 値の物理的妥当性（R > 10 は物理的にありえない等）



検証失敗の場合:

  → その情報を制御層への入力から除外

  → Gate には影響なし（もともと届かない）

  → 異常検知ログに記録

```

## 6. V2X × Gate の構成図

## V2X × Gate Configuration Diagram



```

【複数車両 + インフラの全体像】



車両 A                    車両 B                  インフラ

┌──────────┐              ┌──────────┐           ┌──────────┐

│センサー   │              │センサー   │           │路面状況  │

│  ↓        │    V2X       │  ↓        │  V2X      │速度制限  │

│制御層     │ ←─────────→ │制御層     │ ←──────── │緊急情報  │

│  ↓        │              │  ↓        │           └──────────┘

│Gate(A)    │              │Gate(B)    │

│τ固定      │              │τ固定      │

│R=δ/τ     │              │R=δ/τ     │

│FAIL判定   │              │FAIL判定   │

└──────────┘              └──────────┘



重要:

  ← V2X → は制御層にのみ接続

  Gate（A）と Gate（B）は直接通信しない

  各 Gate は自車センサーのみで独立動作

  τ は V2X で変更されない

```

## 7. V2X 共有が「できること」「できないこと」

## What V2X Can and Cannot Do with Gates



| V2X でできること | V2X でできないこと |

|----------------|-----------------|

| 他車の位置・速度を制御層の入力に使う | 他車の R 値で自車の τ を変える |

| 他車の FAIL-CLOSED を速度制御の参考にする | 他車の Gate 状態を自車 Gate に転送する |

| インフラの路面情報を μ 選択の参考にする | インフラから τ 変更指令を受け付ける |

| 危険区間情報を制御層の経路選択に使う | V2X 通信の有無で Gate の動作を変える |

| Gate の R 値・Zone を他車に送信する（観測共有） | 他車の Gate ログを自車の学習に使う |

## 8. まとめ / Summary



```

V2X × NRA-IDE の設計原則:



原則 1: Gate は自車センサーのみを入力とする

        V2X 情報は制御層への入力として使うが

        Gate の τ・ロジックには届かせない



原則 2: V2X が切れても Gate は止まらない

        通信依存の Gate は通信障害 = 安全装置消失



原則 3: 他車情報は「間接的に」Gate に影響する

        他車情報 → 制御層（速度調整）→ センサー値変化

        → Gate が自律判定（これは接続 OK）



原則 4: τ は V2X 経由で変更しない

        たとえインフラからの正規の指令でも

        τ 変更は OTA クラス A プロセスのみ



原則 5: V2X なりすまし攻撃は構造的に無効化される

        Gate が V2X に依存しない設計が

        最強のセキュリティ対策になる



最終確認:

  V2X 環境でも NRA-IDE の保証は変わらない

  「R ≥ 1.0 のとき必ず止まる」

  この保証は通信状態に依存しない

```
