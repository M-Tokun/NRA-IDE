# NRA-TCM Extractor 1.0

NRA-TCM Extractorは、大規模なUTF-8 Markdownまたはプレーンテキストから、人間が確認する候補行を説明可能な形で抽出するツールです。

決定論的なテキスト処理補助であり、意味要約器、NRA-IDE構造評価器、測定器、安全ゲートではありません。出力は必ず原文と照合して確認してください。

現行実装は、旧来の日英別Crystallizerを一つの共通エンジンへ置き換え、日本語、英語、日英混合のキーワードプロファイルを明示的に提供します。

## 特徴

- Python標準ライブラリだけで動作
- 入力を逐次処理
- 原文の順序と行番号を保持
- 観測可能なテキスト特徴に基づく説明可能なスコア
- 日本語、英語、日英混合のキーワードプロファイル
- 値を高くすると必ず厳しくなる単調な閾値
- 日時に依存しない決定論的なMarkdownレポート
- `--force`を明示しない限り既存出力を差し替えない

## 動作環境

- Python 3.10以降
- 外部パッケージ不要
- UTF-8入力

## 使用方法

リポジトリルートから実行します。

```console
python nra-tcm-parser/extract.py INPUT.md
```

既定では入力と同じディレクトリに`INPUT_extracted.md`を生成します。

言語プロファイル、閾値、出力先は明示的に指定できます。

```console
python nra-tcm-parser/extract.py INPUT.md `
  --language ja `
  --threshold 0.70 `
  --output RESULT.md
```

### オプション

| オプション | 意味 |
|---|---|
| `--language auto` | 日本語と英語を合わせたプロファイル。既定値 |
| `--language ja` | 日本語キーワードプロファイル |
| `--language en` | 英語キーワードプロファイル |
| `--threshold VALUE` | `0`から`1`のうち、抽出する最低スコア。高いほど厳しい。既定値は`0.80` |
| `--output PATH` | レポートの出力先を指定 |
| `--force` | 既存の出力ファイルを明示的に差し替える |

`--force`がない状態で出力先が存在する場合、既存ファイルを保持して競合エラーで終了します。入力ファイルを出力先として指定することは常に拒否します。

## スコア契約

Extractorは、次の観測可能な特徴から`0`から`1`の`content_score`を計算します。

- 東アジア文字と英単語群を比較可能な単位へ換算した、対数尺度による内容の長さ
- 空白以外の文字に占める文字・数字の割合
- Markdownの見出し、箇条書き、引用
- 選択した言語プロファイルのキーワード
- 直前に強く評価された行から減衰する小さな文脈ボーナス

抽出された各行には、スコアと判定理由を記録します。閾値は抽出判定だけに使い、特徴スコア自体を変えません。そのため、閾値を高くして抽出が緩くなることはありません。

英語キーワードは単語・フレーズ境界で一致させ、日本語キーワードは部分一致で扱います。コードフェンス内またはインデントされたコードでは、Markdownの見出し、箇条書き、引用ボーナスを停止します。コード行に対するキーワードと内容のスコアリングは継続します。

このスコアが表すのは抽出候補としての優先度です。事実の正しさ、意味的重要性、危険性、NRA-IDEの境界状態は表しません。

## Python API

`nra-tcm-parser`ディレクトリからPythonを実行するか、このディレクトリをモジュール検索パスへ追加します。

```python
from nra_tcm import ExtractorConfig, TextExtractor, render_markdown

config = ExtractorConfig(language="ja", threshold=0.70)
result = TextExtractor(config).extract(["# 結論\n", "重要な確認事項です。\n"])
report = render_markdown(result, source_name="example.md", config=config)
```

## 出力契約

Markdownレポートには次を記録します。

- 入力ファイル名
- 言語プロファイルと閾値
- 全行数と非空行数
- 抽出行数と抽出率
- 各候補の原文行番号、スコア、判定理由

候補行は原文の順序を維持し、行末の改行コードを除く先頭・末尾空白も保持します。候補テキストは、内容に応じて長さを変えるMarkdownコードフェンス内へ出力するため、原文中のMarkdownやHTMLがレポート構造として解釈されません。複数行の統合や意味要約は行いません。

## 規模と校正の境界

入力行は逐次的に読みますが、選択された候補はすべて`ExtractionResult`へ保持し、最終Markdownレポートもメモリ上で構築します。そのため、メモリ使用量は抽出結果の大きさに応じて増加します。大量の行が残る処理では、入力を適切な単位へ分割してください。

既定閾値`0.80`は説明可能なヒューリスティックの開始値であり、領域ごとの精度検証結果ではありません。文書種別ごとに、人間が確認した例を使って調整してください。異なる領域のスコアを校正済み測定値として比較してはなりません。

## 開発と検証

リポジトリルートから実行します。

```console
python -m unittest tests.test_nra_tcm_extractor -v
```

期待結果は`Ran 21 tests`に続いて`OK`と表示されることです。このテストは、リポジトリ全体の`python -m unittest discover -v`とCIワークフローにも含まれます。

テストは、閾値の方向、言語プロファイルと単語境界、Markdownとコード領域、原文保持、レポートの安全な表現、CP932端末フォールバック、UTF-8エラー、出力競合、明示的な差し替え、旧版削除を確認します。

## 旧版からの移行

共通`nra_tcm`パッケージは、旧日本語v3.1版と英語v2版を置き換えます。旧版の`delta`、`tau`、`R`、`momentum`という名前は、新しいテキスト抽出APIへ意図的に引き継ぎません。このツールは正典NRA-IDEの構造変数を計算しないためです。

旧実装は競合する現行ファイルとして残さず、必要な場合はGit履歴から復元できます。

旧実験版v33 LLMパイプラインは責務が異なり、Extractor 1.0には含まれません。この実験版も現行ツリーから削除済みで、過去の実装はGit履歴から確認できます。
