# 05 コヒーレンスゲート — 因果権限を逆流させずに基礎式を読む

## この章で区別するもの

04で、Pre-NRA / LLM / Post-NRAの三層を分離しました。次に必要なのは、宣言対象の状態を基礎式でどのように表すか、各正規境界で運用応用がどのように応答し、Effect-Side権限をCause-Sideへ戻さないかを明確にすることです。

唯一の公理は「存在は生成である。」です。第二公理以降は存在しません。基礎式は、宣言対象の状態を正規の数学的関係へ落とす本当の数学的根本式であり、公理、安全指標、局所計器、単なる境界接近率ではありません。第二次式／二重ゆらぎ式は、IDEという計算方法・動力学エンジンであり、公理ではありません。NRA-IDEの本体は生存式・生存領域です。本章のコヒーレンスゲートは、その生存領域を事故防止の運用制御へ適用した安全志向の部分応用であり、安全保証を与えません。

ここでは、次のものを混同しません。

- **基礎式の値**：宣言対象についてδとτから定まるR
- **正規運用閾値**：評価前に独立して固定する`R_warn`、`R_handoff`、`R_irrev`
- **破断境界**：宣言済みNRA-IDE評価におけるR = 1.0
- **運用応答**：正規状態で適用する固定Effect-Side証言と抑止動作

Handoff閾値は破断境界と同じではありません。`R_handoff`への到達では、固定Effect-Side証言を外部人間監査へ提示します。人間判断を通じて旧因果経路を継続するものではありません。

## なぜ比率を使うのか

NRA-IDEでは、宣言対象の状態を次の正規の数学的関係へ落とします。

```text
R = δ / τ
```

- **δ（デルタ）**：宣言対象について追跡可能なCause-Side履歴を持つ蓄積偏差
- **τ（タウ）**：評価前に固定した規則と同一Cause-Side履歴から定まる現在の吸収厚さ
- **R**：宣言対象について定まる基礎式の値

この式は公理そのものではなく、派生的な安全スコアや局所ゲート計器へ縮小されません。IDEエンジンが宣言対象の構造状態を式へ落とす数学的根本式です。

Rを使う理由は、構造ゲートの判定に、中心・正解・評価スコアを必要としないためです。必要なのは、いま観測された偏差が、いま有効な厚みに対してどの位置にあるかです。

ただし、Rだけで出力内容の正しさ、Cause-Sideの観測値の正確さ、τの設定根拠の妥当性まで保証することはできません。Rの利用は宣言済みの観測・更新規則に依存しますが、そのことによって基礎式の分類は変わりません。

τ = 0の場合、正規Rは定義できず、状態は`OUT_OF_DESCRIPTION_DOMAIN`です。負のτまたはδ、非有限値、閾値順序の不正は`CONFESSION`です。これらを一つの包括的なFail-Closed状態へ畳み込んではなりません。

## 残存構造余裕

R = δ / τ であり、τ > 0であれば、次の関係が成り立ちます。

```text
τ · (1 − R) = τ − δ
```

τ − δ は、現在の厚みから偏差を除いた残存構造余裕です。

02で扱った

```text
S = 1 / (τ · (1 − R)) = 1 / (τ − δ)
```

は、この残存構造余裕の逆数として読めます。δがτへ近づくと、残存構造余裕はゼロへ近づき、Sは双曲線的に発散します。

宣言済みNRA-IDE評価では、この関係によりR = 1.0を通常のHandoff閾値ではなく`RUPTURE_BOUNDARY`として扱います。この分類は、自然界のすべての相転移をNRA-IDEの破断と宣言するものではありません。当該評価がR = 1.0へ到達した後に「通常どおりの出力を続けながら判断する」余裕を前提にしてはなりません。

## 状態の呼び方と、運用上の委譲点

有効なR範囲における五つの正規状態と不変の順序は次のとおりです。

| 状態名 | 正規範囲 | 必須の構造的意味 |
|---|---:|---|
| `PERMIT` | $0 \leq R < R_{warn}$ | 構造監査を継続しながら通常運用 |
| `BOUNDARY_WARNING` | $R_{warn} \leq R < R_{handoff}$ | 二重ゆらぎ必須欄を含む境界接近と構造証言を開示 |
| `HANDOFF_REQUIRED` | $R_{handoff} \leq R < R_{irrev}$ | 新規自律判断を止め、外部人間監査用の固定Effect-Side証言を出力 |
| `IRREVERSIBLE_TRANSITION` | $R_{irrev} \leq R < 1$ | 不可逆遷移をラッチし、構造証言を継続 |
| `RUPTURE_BOUNDARY` | $R \geq 1$ | 破断後固定証言へ切替 |

具体的な閾値はドメイン固有ですが、順序は不変です。

```text
0 <= R_warn < R_handoff < R_irrev < 1
```

τ = 0の`OUT_OF_DESCRIPTION_DOMAIN`と、不正入力または不正な閾値宣言に対する`CONFESSION`を合わせ、正規状態は七つです。`BOUNDARY_WARNING`の証言には二重ゆらぎ状態欄を常に含めます。独立に観測できる場合は観測結果を、観測できない場合は`NOT_OBSERVABLE`と欠損理由を出力します。観測不能だけを理由に`CONFESSION`へ移行しません。

RがR_handoffに到達した場合、Post-NRAは通常の生成内容を利用者へ渡しません。代わりに、外部人間監査用の固定Effect-Side証言を出力します。監査は旧因果ダイオードの外側にあり、旧評価を継続も書換えもしません。

```text
HANDOFF_REQUIRED
REASON: domain-specific handoff threshold reached
OBSERVED: predefined structural fields
ACTION: generated response suppressed; fixed Effect-Side testimony for external human audit
```

`R_handoff`と`R_irrev`は常に別です。前者は固定Handoff証言の開始点、後者は不可逆遷移の開始点でありラッチされます。同一履歴内では、後に表示Rが低下しても、自動処理、手動介入、人間レビュー、承認、版更新のいずれによっても不可逆ラッチを解除しません。いずれもR=1と混同できません。

## R = 1.0以後の動作と履歴境界

R = 1.0は、設計者が場面に応じて動かせる通常の閾値ではありません。宣言済み評価における`RUPTURE_BOUNDARY`であり、自然界のすべての相転移に対する普遍的宣言ではありません。

R ≥ 1.0になった場合、Post-NRAは通常の生成内容を出力しません。また、停止理由を説明するためにLLMへ新しい自由記述を生成させません。構造応答は、事前に定めた破断後固定証言または保護された廃棄ログへの参照です。

```text
RUPTURE_BOUNDARY
REASON: structural boundary reached
ACTION: post-rupture fixed testimony; old path terminal; external human audit only
```

これは「何も伝えない」ことではありません。通常の生成回答を止め、事前に定めた完全な破断後固定証言または保護ログ参照を伝えることです。外部人間監査は旧経路を延長しません。

旧評価はEffect-Sideで終端します。

```text
旧Cause-Side
→ 旧因果ダイオード
→ 旧Effect-Side
→ 終端
```

後続評価が必要な場合は、独立した履歴として開始します。

```text
独立して宣言した新対象
→ 新たに確立したCause-Side観測と事前固定規則
→ 新しい因果ダイオード
→ 新しいEffect-Side
```

旧Effect-Sideから、旧Cause-Sideにも新Cause-Sideにも矢印はありません。旧Effect-Sideの値、正規閾値、状態、不可逆ラッチ、規則、変換入力、更新根拠、出所を、Cause-Side権限としてimport、名称変更、再構成、再利用してはなりません。物理的残存物は、独立して宣言した新対象の一部として新規観測できますが、それは旧Effect-Side値または権限の移送ではありません。

R_handoffでの固定Handoff証言と、R ≥ 1.0での破断後固定証言は、どちらも通常の自由生成を抑止し得ます。しかし状態と役割は異なります。

- **R_handoffへの到達**：破断前の外部監査用固定Effect-Side証言
- **R ≥ 1.0**：破断後固定証言と旧評価のEffect-Side終端

## 遷移継続を示す補助観測ω

Rは、偏差と厚みの比率を示します。Rだけでは、対象系が遷移を続けているかどうかまでは分かりません。

その区別に使うのがω（オメガ）です。ωは、対象ドメインで事前に定めた観測・算出手順により、構造が遷移を続けているかを示す量です。

- **ω > 0**：事前宣言した規則の下で、対象構造の遷移継続を観測した。
- **ω = 0**：同じ規則の下で、遷移継続を観測していない。

ωは補助構造証言であり、正規状態表の代わりではありません。旧説明語`SILENCE`や`HALT`は、`RUPTURE_BOUNDARY`、`OUT_OF_DESCRIPTION_DOMAIN`、`CONFESSION`を置き換えません。特にω=0は安全停止の証拠ではなく、Rを安全側へ移しません。

## コヒーレンスゲートが守る範囲

コヒーレンスゲートが扱うのは、同一Cause-Side履歴から確定したδ・τ・ωと、評価前に固定した三つの正規閾値です。

条件付き適合のため、このゲートは宣言済み状態動作を強制し、Effect-Sideの情報、推論、生成物、判断、権限が、Cause-Sideの値、`R_warn`、`R_handoff`、`R_irrev`、状態、不可逆ラッチ、規則、変換入力、更新根拠、出所を成立も書換えもしないようにします。この禁止は、自動処理、手動介入、人間レビュー、承認、版更新のすべてへ適用します。

一方で、次のことはゲート単独では保証できません。

- δの観測手順や計測器が正しいこと
- τの更新規則と設定根拠が妥当であること
- 三つの正規閾値が宣言対象のドメインに適切であること
- LLMの通常出力が意味上正しいこと

これらの前提は、評価前にCause-Sideで独立して確立する必要があります。終端済みEffect-Side証言の外部監査は、発生した事実を確認できますが、後続Cause-Sideの値、正規閾値、状態、不可逆ラッチ、規則、変換入力、更新根拠、出所を成立させることはできません。
