# 05 コヒーレンスゲート — 構造状態を比率で読み、委譲点を分ける

<!-- 05_coherence_gate_JP.md -->

---

## この章で区別するもの

04で、Pre-NRA / LLM / Post-NRAの三層を分離しました。次に必要なのは、Post-NRAが何を根拠に通常出力を通すか、いつ通常出力を抑止して人間へ渡すかを明確にすることです。

ここでは、次の三つを混同しません。

- **構造状態**：Cause-Sideに由来するδとτから求める比率R
- **委譲点**：通常出力を抑止し、人間へ判断を渡すドメイン固有の運用点
- **相転移境界**：R = 1.0。構造余裕が失われる不変の終端境界

委譲点は相転移境界と同じではありません。安全設計で通常出力を停止するのは、原則としてR = 1.0に達する前です。

---

## なぜ比率を使うのか

NRA-IDEでは、構造の状態を次の計算原理で記述します。

```text
R = δ / τ
```

- **δ（デルタ）**：対象系に観測された偏差またはゆらぎ
- **τ（タウ）**：設計時に定めた規則とCause-Sideの負荷履歴に基づく、現在の吸収可能な厚み
- **R**：偏差が現在の厚みに対して占める構造比率

この式は公理そのものではありません。「存在は生成である」という設計上の前提から、IDEが構造状態を読むために採用する計算原理です。

Rを使う理由は、構造ゲートの判定に、中心・正解・評価スコアを必要としないためです。必要なのは、いま観測された偏差が、いま有効な厚みに対してどの位置にあるかです。

ただし、Rだけで出力内容の正しさ、Cause-Sideの観測値の正確さ、τの設定根拠の妥当性まで保証することはできません。この式が示すのは、定められた観測・更新規則の下での構造状態です。

τ ≤ 0の場合、比率は有効に定義できません。この状態は通常出力を許可せず、事前に定めた無効状態の定型通知と人間への委譲へ移ります。

## 残存構造余裕

R = δ / τ であり、τ > 0であれば、次の関係が成り立ちます。

```text
τ · (1 − R) = τ − δ
```

τ − δ は、現在の厚みから偏差を除いた残存構造余裕です。

02で扱った

```text
S = 1 / (τ · (1 − R)) = 1 / (τ − δ)
```

は、この残存構造余裕の逆数として読めます。δがτへ近づくと、残存構造余裕はゼロへ近づき、Sは双曲線的に発散します。

このことは、R = 1.0が通常の委譲点ではなく、構造余裕が失われる相転移境界であることを示します。R = 1.0の後に「通常どおりの出力を続けながら判断する」余裕を前提にしてはなりません。

## 状態の呼び方と、運用上の委譲点

本文書群では、構造状態を説明するために次の名称を使います。

| 状態名 | 参考となるR帯域 | 説明 |
|---|---:|---|
| NIRVANA | R < 0.4 | 偏差が厚みに対して小さい状態 |
| ELASTIC | 0.4 ≤ R < 0.7 | 余裕はあるが、状態の追跡が必要な領域 |
| CRITICAL | 0.7 ≤ R < 1.0 | 相転移境界へ接近している領域 |
| SILENCE | R ≥ 1.0 かつ ω > 0 | 相転移境界に到達または超過し、通常生成を継続しない状態 |

この帯域は、文書を読むための**説明上の基底分類**です。すべてのドメインに共通する自律運用の閾値ではありません。

実運用では、相転移境界より前に、ドメイン固有の**委譲点**を定めます。本章ではこれを `Rop` と表記します。

```text
0 < Rop < 1.0
```

RがRopに到達した場合、Post-NRAは通常の生成内容を利用者へ渡しません。代わりに、事前に定めた定型通知を出し、人間の判断へ委譲します。

```text
HANDOFF_REQUIRED
REASON: domain-specific handoff threshold reached
OBSERVED: predefined structural fields
ACTION: generated response suppressed; human review required
```

ここで重要なのは、`Rop`がNIRVANA / ELASTIC / CRITICALの名称とは別の、運用上の委譲条件であることです。高リスク領域では、CRITICALに入る前にRopを置くことがあります。したがって、状態名だけから通常出力の可否を決めてはなりません。

他文書で `R_irrev` という表記を用いる場合は、Ropと同一の委譲点なのか、別の注意閾値なのかをドメイン仕様で明示しなければなりません。R = 1.0と混同してはなりません。

## R = 1.0以後の動作

R = 1.0は、設計者が場面に応じて動かせる通常の閾値ではありません。構造余裕が失われる相転移境界です。

R ≥ 1.0になった場合、Post-NRAは通常の生成内容を出力しません。また、停止理由を説明するためにLLMへ新しい自由記述を生成させません。返せるのは、あらかじめ定めた最小限のFAIL-CLOSED標識、または保護された廃棄ログへの参照だけです。

```text
FAIL_CLOSED
REASON: structural boundary reached
ACTION: no further generated response; human handoff required
```

これは「何も伝えない」ことではありません。通常の生成回答を止め、構造的に確定している最小限の状態だけを定型で伝えることです。

Ropでの委譲と、R ≥ 1.0でのFAIL-CLOSEDは、どちらも通常生成を抑止します。しかし役割は異なります。

- **Ropへの到達**：相転移境界より前に人間へ渡すための運用上の委譲
- **R ≥ 1.0**：構造余裕が失われた後の終端処理。新たなLLM生成は行わない

## 動いているかどうかを示すω

Rは、偏差と厚みの比率を示します。Rだけでは、対象系が遷移を続けているかどうかまでは分かりません。

その区別に使うのがω（オメガ）です。ωは、対象ドメインで事前に定めた観測・算出手順により、構造が遷移を続けているかを示す量です。

- **ω > 0**：構造は遷移を続けている
- **ω = 0**：同じ規則の下で遷移が確認できない。HALTとして別途扱う

SILENCEとHALTは同じではありません。

- **SILENCE**：R ≥ 1.0かつω > 0。相転移境界を越えたが、構造は遷移を続けている。通常生成は止め、最小限の定型出力で人間へ渡す。
- **HALT**：ω = 0。遷移が継続しているとは扱えない状態。Rの値を安全側へ読み替える根拠にはならず、別の人間判断を必要とする。

ω = 0は、単に「安全に止まった」ことを意味しません。観測手順、対象系、継続条件を人間が確認する必要があります。

## コヒーレンスゲートが守る範囲

コヒーレンスゲートが扱うのは、Cause-Sideから確定したδ・τ・ωと、事前に定めた委譲条件です。

このゲートが保証対象とするのは、定められた条件に達したときに通常生成を抑止し、結果側の意味評価でδ・τ・Ropを書き換えないことです。

一方で、次のことはゲート単独では保証できません。

- δの観測手順や計測器が正しいこと
- τの更新規則と設定根拠が妥当であること
- Ropがそのドメインの不可逆域接近点として適切であること
- LLMの通常出力が意味上正しいこと

これらは、設計・実装・運用において人間が確認すべき前提です。
