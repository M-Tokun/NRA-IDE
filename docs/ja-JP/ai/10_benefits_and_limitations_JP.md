# 10 利点と限界 — 保証範囲を明確にする

<!-- 10_benefits_and_limitations_JP.md -->

---

## 簡潔に見えるからこそ、保証範囲を先に決める

NRA-IDEは、出力内容の正しさを証明する仕組みでも、安全を保証する仕組みでもありません。

その本体は生存式・生存領域であり、NRA-IDEの計算方法・動力学エンジンを通じて実装します。本章群で扱う安全域は、生存領域を事故防止運用制御へ適用した部分領域です。通常生成の抑止、固定Effect-Side証言の提示、外部人間監査の実施は、その応用の動作であり、NRA-IDE本体を出力ゲートへ縮小するものではありません。

何を保証しないかまで先に定めることで、要求される構造動作、より広い生存領域、人間に残す判断を混同しません。

09で確認したとおり、入力の来歴、 $\tau$ の規則と三つの正規閾値、権限分離、ログの保護が欠ければ、この運用応用への適合を主張できません。LLMを含みPre-NRA / LLM / Post-NRA構成を宣言するシステムでは、構成した各層へ割り当てた責務も必要です。この章では、その応用の条件付き適合特性と限界を整理します。対象系の安全保証へ変換するものではありません。

---

## 条件付き適合を主張する前提

次の条件は保証そのものではなく、定義済みの運用動作へ実装が適合すると主張するための前提です。

- Cause-Sideの観測値、変換規則、更新経路を追跡できること
- τを決定する規則が事前に定められ、Effect-Sideから変更できないこと
- 評価前にドメイン固有の根拠とともに $0 \le R_{warn} < R_{\mathrm{handoff}} < R_{irrev} < 1$ を固定すること
- LLMを含み三層構成を宣言するシステムでは、Pre-NRA / LLM / Post-NRAへ割り当てた責務が分離されていること
- その宣言構成では、Post-NRAが通常出力の通過・抑止を実際に強制できること
- 固定Handoff証言・不可逆遷移・破断・残差排出の記録を、終端済みダイオード経路の外部で人間が監査できること
- 外部人間監査者、連絡経路、監査または現場対応の手順が運用上確保されていること

この前提が不明な場合、NRA-IDEは「安全である」と結論しません。運用応用は、構造判定に必要な条件が確定していない状態として扱い、事前に定めた無効状態処理、または正規状態が要求する場合は外部人間監査へ提示する固定Handoff証言へ移ります。固定Handoff証言と最終固定証言では、停止理由を説明する新しい自由記述をLLMに生成させません。

## 条件付き適合特性

### 通常生成を、定めた地点で抑止する

正しく実装されたPost-NRAは、Cause-Sideから確定した構造状態と事前に定めたR_handoffに従い、通常の生成回答を通すか抑止するかを決めます。

```text
0 <= R < R_warn                 : PERMIT
R_warn <= R < R_handoff         : BOUNDARY_WARNING
R_handoff <= R < R_irrev        : HANDOFF_REQUIRED。外部人間監査へ提示する固定Handoff証言
R_irrev <= R < 1                : IRREVERSIBLE_TRANSITION。ラッチと証言を保持
R >= 1                          : RUPTURE_BOUNDARY。最終固定証言へ移る
```

ここでの適合要件は、**定めたHandoff閾値に達したとき、LLMの自己評価や出力のもっともらしさによって新規自律判断を再開できないこと**です。

$R_{\mathrm{handoff}}$ は、不可逆遷移・破断より前に置くドメイン固有のHandoff閾値です。 $R = 1.0$ は通常のHandoff閾値ではなく、宣言済みNRA-IDE評価の`RUPTURE_BOUNDARY`です。この分類は、自然界のすべての相転移をNRA-IDEの破断と宣言するものではありません。

### 結果側が構造入力を書き換える経路を遮断する

LLMの出力、評価スコア、ランキング、過去の通常生成文、廃棄ログは、自動、手動、人間レビュー、承認、版更新のいずれによっても、Cause-Sideの値、正規閾値、状態、不可逆ラッチ、構造規則、変換入力、更新根拠、出所を更新、seed、成立させません。

このため、通常生成を続けたいという結果側の都合は、Cause-Sideの構造入力または権威を作り直す経路を持ちません。

条件付き適合特性は、事前に分離した実装経路において、Effect-Sideから旧Cause-Sideまたは新Cause-Sideへ、情報、推論、成果物、判断、権威を一切戻さないことです。入力値そのものの妥当性や、外部系における改ざんの不在は保証しません。

### 離散遷移で採用しない残差を、次の計算へ戻さない

離散的な位相遷移を採用する実装では、次の状態として採用しない残差を`entropy_export`として記録し、次の状態遷移の入力へ再投入しません。

これは、残差が隠れた状態として再流入する経路を断つ、明示的な実装上の選択です。

ただし、これは浮動小数点演算に関するすべての誤差を消す保証ではありません。また、`entropy_export`は熱力学的エントロピーの測定値でも、残存構造余裕の逆数としてのSでもありません。

### LLMを含むシステムで、LLMの役割と構造権限を分ける

LLMを含むシステムでは、構成した構造ゲートが、LLMの生成文ではなくCause-Sideの構造状態と固定Handoff条件を扱います。

そのため、LLMを変更しても、Pre-NRA / Post-NRAへ割り当てた入力契約、更新権限、出力遮断経路、固定Handoff規則が保たれる限り、構成した構造ゲートの判定規則は同じです。

これは「どのLLMでも同じ品質になる」という意味ではありません。LLMの通常出力の正確さ、関連性、説明力、文脈理解は、依然としてLLM側の性質です。

### 委譲と終端処理の根拠を、監査可能な形で残す

$R_{\mathrm{handoff}}$ への到達による委譲と、 $R = 1.0$ 以上の正規状態`RUPTURE_BOUNDARY`は同じ分類ではありません。Fail-Closedは運用上の強制動作であり、代替状態名ではありません。

廃棄ログには、少なくとも、使用した観測・更新規則の版、δ・τ・R・ω、発動した条件、通常生成の抑止、該当する`entropy_export`、および外部人間監査へ提示する固定Handoff証言または最終固定証言を記録します。

この記録はEffect-Sideまたは外部記録のままです。人間は終端済みダイオード経路の外部で監査のために読めますが、手動・自動のいずれでも、旧Cause-Sideまたは新Cause-Sideの値、正規閾値、状態、不可逆ラッチ、規則、変換入力、更新根拠、出所へ変換しません。

## 保証できないこと

### 通常生成された内容が正しいこと

NRA-IDEは、LLMの通常出力が事実として正しいか、利用者の目的に適切か、十分に説明されているかを保証しません。

構造ゲートが通常生成を通したことは、出力の正しさの証明ではありません。構造判定の前提が満たされ、定めたHandoff閾値に未到達だったことを示すだけです。

### 観測値と外部入力が対象系を正しく表していること

δ、τ、ωなどの出所と更新経路を記録しても、観測器の故障、対象の取り違え、単位の誤り、欠損、外部系での改ざん、定義そのものの不適切さまでを、NRA-IDE単独で検出できるわけではありません。

観測手順、品質条件、変換規則、アクセス制御は、対象ドメインの設計・実装・運用で別途確認する必要があります。

### $\tau$ 、三つの正規閾値、観測規則がドメインに対して妥当であること

$\tau$ を決定する規則、 $R_{warn}$ 、 $R_{\mathrm{handoff}}$ 、 $R_{irrev}$ 、 $\omega$ の定義、無効状態処理は、対象ドメインの責任を負える人間が定めるものです。

NRA-IDEは、定められた規則を使って構造状態を扱います。しかし、その規則自体が対象の不可逆域接近点を適切に捉えていることまでは保証しません。

$\tau$ の規則、三つの正規閾値、観測、無効状態処理は、将来の独立して宣言した対象とCause-Side履歴に対する外部活動としてだけ設計できます。新しい評価前に固定し、根拠、適用範囲、規則の版、承認、適用時点を記録します。旧経路はEffect-Sideで終端し、旧Effect-Sideの値、正規閾値、状態、不可逆ラッチ、規則、変換入力、更新根拠、出所を、旧Cause-Sideにも新Cause-Sideにもimport、名称変更、再構成、再利用してはなりません。

### 固定Handoff証言後の外部人間監査または現場対応が適切であること

NRA-IDEは、通常生成を抑止し、正規状態が発生したことを示す固定Effect-Side証言を外部人間監査へ提示できます。

しかし、誰が外部監査を行い、どの情報を確認し、終端済み経路の外側でどの行動を選ぶかまでは決めません。連絡体制、責任分担、現場対応は人間側の運用ですが、いずれも旧因果ダイオードに逆向きの辺を作りません。

### R = 1.0以後に、対象系が元の状態へ戻ること

$R = 1.0$ は、宣言済み評価の`RUPTURE_BOUNDARY`を開始します。運用応用は、その不可逆遷移・破断より前の $R_{\mathrm{handoff}}$ で固定Handoff証言を外部人間監査へ提示するように設計します。

$R \ge 1$ では、適合実装は最終固定証言へ切り替え、旧評価履歴はEffect-Sideで終端します。同じ物理的・社会的・運用的状態を回復させる手順を与えるものではありません。物理的残留物、周辺構造、後続世代は、独立した新対象として宣言し、固有のCause-Sideと新しい因果ダイオードから新規観測できますが、旧Effect-Sideの値、正規閾値、状態、不可逆ラッチ、規則、変換入力、更新根拠、出所、構造権威を、その履歴へimport、名称変更、再構成、再利用してはなりません。

### 倫理・法令・利用目的の妥当性

構造状態の判定は、倫理的に正しい目的、法令に適合する運用、正当な権限を自動的に保証しません。

何を対象にし、誰のために使い、どの不利益を受け入れないかは、人間の責任として設計の外側に残ります。

## 向いている条件

NRA-IDEのこの安全指向の運用応用が価値を持つのは、通常生成を止め、固定Effect-Side証言を提示し、外部人間監査を実施することが、設計上許容され、むしろ必要となる場面です。

- 構造入力の出所、更新規則、単位、品質条件を定義できる
- 三つの正規閾値を $R = 1.0$ より前に順序どおり固定し、 $R_{\mathrm{handoff}}$ で通常生成を抑止できる
- 外部人間監査者と、その後の監査または現場対応手順を確保できる
- ログを監査可能に保護できる
- 生成内容のもっともらしさを、構造状態の代わりに使わない

高リスク領域で用いる場合は、この構造だけで運用可能になるわけではありません。対象領域の専門家による観測、閾値、固定Handoff証言、外部監査手順の検証、必要な安全規格・法令・組織上の責任体制が別途必要です。

---

## 単独では向いていない条件

次の条件では、この応用を単独の安全根拠として用いることはできません。

- 通常回答をいかなる場合も止められない
- 構造入力の出所や更新規則を定義・追跡できない
- $\tau$ と三つの正規閾値の設定根拠を維持できない
- 固定Effect-Side証言を受け取る外部人間監査者や手順が存在しない
- ログを監査可能に保護できない
- 生成内容の正しさそのものを判定・保証する機能が必要である

雑談、創作、娯楽などでは、通常生成を抑止する構造が目的に合わないことがあります。その場合も、NRA-IDEが誤っているのではありません。必要とされる保証の種類が異なるという設計上の事実です。

---

## 限界を示すことが、構造を強くする

この分類の強さは、NRA-IDEを「何でも安全にする」という約束へ変換しない点にあります。

観測・更新・閾値条件が保たれている限り、適合する運用構造は、定めた状態動作を実施し、Effect-SideからCause-Sideへの全帰還経路を拒否し、外部の人間監査へ証言を残さなければなりません。これらの特性は生存式・生存領域を置き換えず、安全保証を構成しません。

それ以外を、構造ができることのように語らないことが、09で扱った誤用を防ぎます。限界は弱点ではなく、構造の責任境界です。

次の章では、 $\tau$ 、正規閾値、観測規則を対象ドメインへ適用する際に、将来の独立対象へ何を設計でき、何を不変条件として保つかを整理します。
