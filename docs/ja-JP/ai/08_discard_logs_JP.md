## ログは書き込み専用

06で確認した通り、ログは書き込み専用です。

記録します。しかし読み返しません。過去の出力を次の計算の入力として使いません。なぜなら過去の出力を入力に使った瞬間に、Π⁻¹の経路が生まれるからです。
結果から原因への逆算が始まります。結果ログ→原因の推定→次の結果の推定
ログの役割は次の計算を助けることではありません。「何が起きたかを記録する」ことだけです。

## 残差を捨てる

NRA-IDEの計算の中に、こういう処理があります。

```python
raw_next_phase = prev_state.phase + prev_state.omega
next_phase_int = math.floor(raw_next_phase)
entropy_export = raw_next_phase - next_phase_int
```

`raw_next_phase`から整数部分だけを取り出して、余りを`entropy_export`として切り捨てます。

浮動小数点の残差を次の計算に持ち越しません。残差は熱として排出されます。
これは精度を諦めているのではありません。残差を蓄積させないという設計上の決断です。
01で見た通り、浮動小数点の誤差はステップを重ねるごとに発散します。切り捨てることで、誤差の連鎖を構造的に断ち切ります。

## 誤差の熱排出

物理の世界では、散逸とはエネルギーが熱として外部に逃げることです。完全に閉じたシステムは存在しません。在るものは必ず壊れます。エネルギーは必ず逃げます。
NRA-IDEはこれを計算に取り込みます。残差を蓄積させずに外部へ排出する。これが`entropy_export`の意味です。
蓄積しないから発散しません。発散しないから構造が保たれます。

従来の機械学習は誤差をゼロに近づけようとします。最適化とはその試みです。しかし誤差はゼロになりません。
在るものは必ず壊れるからです。NRA-IDEは誤差をゼロにしようとしません。排出することで構造の中に貯めない・留まらせないという選択をします。

時計の歯車は、摩耗しても誤差を累積しないで正確な時を刻むことがなぜ可能なのでしょう？

## 廃棄の記録が証言になる

07で確認した通り、Fail-Closedが発動したとき、ログには構造の状態が記録されます。

```
R = 1.032、τ = 0.14、δ = 0.15、出力停止
entropy_export = 0.0034
```

何を出力したかではなく、何を捨てたかが記録されます。

これは証言です。
06で出てきた「証言の義務」の実体です。計算の中で何を使い、何を切り捨て、どの時点で限界を超えたかが、構造の状態として正確に残ります。

意志で正直であろうとするのではありません。構造が自動的に記録します。

---

## 廃棄ログが持つ二つの役割

廃棄ログは二つの役割を同時に果たします。

一つは**誤差の連鎖を断つ**ことです。残差を次の計算に持ち越さないことで、浮動小数点の発散を構造的に防ぎます。

もう一つは**限界超過の根拠を残す**ことです。バトンを受け取った人間が「なぜここで止まったのか」を確認できます。
推測ではなく、構造の記録として読めます。

廃棄することと記録することは矛盾しません。
計算には使わない。しかし証言としては残す。
この二つが同時に成立するのが廃棄ログです。
