# 08 廃棄ログ — 計算へ戻さず、証言として残す

## ログは終端済みEffect-Side記録、ただし外部の人間監査は妨げない

06で確認した通り、NRA-IDEでは値の名称だけでなく、出所と更新経路を区別します。廃棄ログも同じです。

ここでいう**書き込み専用**とは、記録されたログが終端済みEffect-Sideまたは外部記録に留まり、旧Cause-Sideにも新Cause-Sideにも決して戻らない、という意味です。ログを読めないという意味ではありません。人間の監査者は、Handoff、不可逆遷移、破断が起きた理由を確認するために、終端済みダイオード経路の外側でのみ記録を参照できます。

禁止されるのは、次のような還流です。

```text
旧廃棄ログ → Effectからの推定 → Cause-Side更新の試行 → BLOCKED
```

旧廃棄ログをCause-Sideの値、正規三閾値のいずれか、状態、不可逆ラッチ、規則、変換入力、更新根拠、出所へ変換する試みは、03で扱ったΠ⁻¹の経路です。自動、手動、人間レビュー、承認、版更新のいずれを介しても禁止されます。

一方で、次の二つは区別します。

- **構造判定の実行系**：ログを旧Cause-Sideにも新Cause-Sideにも再投入しない。
- **外部の人間監査**：終端済み経路の外側でログを証言として読めるが、その内容を将来規則の根拠、Cause-Side資料、変換入力、出所へ変換できない。

人間が読むことによって逆向きの辺は生じません。手動レビュー、承認、版管理も例外を生じさせません。

## 廃棄するのは、次の遷移へ採用しない残差である

NRA-IDEの離散的な位相遷移では、次のような処理を置けます。

この節は、IDE動力学エンジンによる同一履歴内の計算を説明します。旧Effect-Sideから新Cause-Sideへの移行を説明するものではなく、因果ダイオードを越える権限を与えません。

```python
raw_next_phase = prev_state.phase + prev_state.omega

next_phase_int = math.floor(raw_next_phase)

entropy_export = raw_next_phase - next_phase_int
```

`raw_next_phase`には、次の位相として採用する整数部分と、採用しない小数部分が含まれます。`next_phase_int`だけを次の離散遷移へ渡し、小数部分は`entropy_export`として記録します。

重要なのは、**すべての情報やすべての誤差を捨てるのではない**ことです。ここで扱うのは、事前に定めた離散化規則において、次の状態遷移へ持ち越さない残差だけです。

```text
次の遷移に採用する値：next_phase_int
次の遷移に採用しない残差：entropy_export
```

この処理は、採用しない残差が同じ計算履歴内で隠れた状態として次の位相へ再流入する経路を断ちます。残差の記録そのものはΠ⁻¹ではありませんが、廃棄ログを終端済みEffect-Side境界からCause-Sideへ戻せば、禁止された接続になります。

## `entropy_export`は熱力学的エントロピーの測定値ではない

`entropy_export`は、離散化で次の遷移へ採用しなかった残差を示す**実装上の記録項目**です。

これは、熱力学的エントロピーを直接測定した値や、物理的な熱量そのものを意味しません。したがって、本文書群で`S`を残存構造余裕の逆数として使う場合、`entropy_export`を同じ記号で表してはなりません。

```text
S = 1 / (τ · (1 − R)) = 1 / (τ − δ)
```

- **S**：残存構造余裕の逆数としての構造感度
- **entropy_export**：離散遷移で採用しなかった残差の記録項目

両者は役割も生成経路も異なります。

## 局所計算不変条件とその限界

残差を次の離散遷移へ持ち越さないことは、計算構造における明確な選択です。しかし、この処理だけで計算全体が無誤差になるわけではありません。

局所計算不変条件は、**この規則で採用しないと定めた残差を、その計算履歴内の次の状態遷移の入力へ再投入しないこと**です。これは安全保証ではなく、履歴間の権限移送を説明するものでもありません。

保証対象ではないものもあります。

- 計測器やCause-Side観測値が正しいこと
- 浮動小数点演算に関わるすべての誤差が消えること
- `math.floor`以外の実装箇所に数値上の問題がないこと
- 離散化規則そのものが対象ドメインに妥当であること
- 通常生成されたLLM出力が意味上正しいこと

したがって、廃棄は「精度を捨てる」ことでも、「誤差一般を消滅させる」ことでもありません。次の状態遷移に何を残し、何を残さないかを、事前に固定した規則として明示することです。

## 廃棄ログは、抑止と終端処理の根拠を残す

05・07で区別した既知の数値進行内で、この節が扱う通常出力の抑止状態は三つです。

- **`HANDOFF_REQUIRED`**： $R_{\mathrm{handoff}} \le R < R_{\mathrm{irrev}}$ 、外部人間監査へ提示する固定Handoff証言
- **`IRREVERSIBLE_TRANSITION`**： $R_{\mathrm{irrev}} \le R < 1$ 、不可逆ラッチと継続する構造証言
- **`RUPTURE_BOUNDARY`**： $R \ge 1$ 、宣言済み評価の最終固定証言

`CONFESSION`と`OUT_OF_DESCRIPTION_DOMAIN`も、Fail-Closed処理によって対象となる通常出力を抑止します。これらは数値進行の状態ではなく入力例外であり、数値進行と混同せず`INPUT_EXCEPTION_LOG`へ分離して記録します。

$R=1$ は、宣言済みNRA-IDE評価の`RUPTURE_BOUNDARY`です。この分類は、自然界のすべての相転移をNRA-IDEの破断と宣言するものではありません。

ログは、数値進行内のこれら三状態を混同しないために必要です。事前に定めた記録形式には、少なくとも次の情報を残します。

```text
EVENT: HANDOFF_REQUIRED、IRREVERSIBLE_TRANSITION、または RUPTURE_BOUNDARY
REASON: 発動したHandoff条件または構造境界
OBSERVED: δ, τ, R, ω と必要な出所識別子
THRESHOLDS: R_warn、R_handoff、R_irrev
DISCARD: entropy_export（該当する離散遷移がある場合のみ）
ACTION: 通常生成の抑止、外部人間監査へ提示する固定Handoff証言、継続する構造証言、または最終固定証言
RULE_VERSION: 使用した観測・更新・Handoff規則の版
```

たとえば、R_handoffでのHandoffは次のように記録します。

```text
HANDOFF_REQUIRED
REASON: domain-specific handoff threshold reached
OBSERVED: δ, τ, R, ω
THRESHOLD: R_handoff
ACTION: generated response suppressed; fixed Effect-Side testimony presented for external human audit
```

固定Handoff証言と最終固定証言では、停止理由を説明するためにLLMへ新しい自由記述を生成させません。あらかじめ定めた固定Effect-Side証言、または保護されたログへの参照だけを返します。

```text
RUPTURE_BOUNDARY
REASON: structural boundary reached
ACTION: final fixed testimony; old evaluation history terminated at Effect-Side
```

これにより、Handoff、不可逆遷移、破断境界での最終固定証言を記録上でも区別できます。

## 記録は終端済み証言であり、いかなる評価のCause-Side資料でもない

廃棄ログには、「何を出力したか」だけでなく、「何を構造計算へ採用せず、どの条件で通常生成を抑止したか」を残します。

記録が証言になるためには、少なくとも次の運用条件が必要です。

- 追記専用であること
- 記録後の改ざんを検出できること
- 観測・更新・Handoff規則の版を対応付けられること
- 人間が監査できること
- 自動処理でも手動処理でも、ログ内容をCause-Sideの値、正規三閾値のいずれか、状態、不可逆ラッチ、規則、変換入力、更新根拠、出所として再投入しないこと

τを動的に変化させるCause-Sideの負荷履歴は、設計時に定めたτ更新規則の入力です。これは、前回の結果を記録した廃棄ログとは区別します。廃棄ログを、Cause-Side履歴の代用品として扱ってはなりません。

旧経路はEffect-Sideで終端します。後続評価が必要な場合は、独立して宣言した対象、新たに確立したCause-Side観測と規則、新しい因果ダイオードから開始します。物理的残存物はその対象の一部として新たに観測できますが、旧Effect-Sideの値、正規閾値、状態、不可逆ラッチ、規則、変換入力、更新根拠、出所を、旧Cause-Sideにも新Cause-Sideにもimport、名称変更、再構成、再利用してはなりません。

廃棄することと、記録することは矛盾しません。

```text
計算へは戻さない。
外部の人間監査には残す。
```

この二つを同時に成立させることが、廃棄ログの役割です。

## 次章への接続

廃棄ログは、構造判定の証言を残します。しかし、入力の出所、τの設定、ログの保護、必要な権限分離の欠落といった問題は、ログだけでは防げません。LLMを含むシステムでは、構成されたPre-NRA、LLM、Post-NRA各層の欠落もこれに含まれます。適合性はログや層数だけではなく、正規挙動、証拠、テストによって判定します。
