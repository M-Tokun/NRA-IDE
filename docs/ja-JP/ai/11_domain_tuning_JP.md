# 11 ドメインチューニング — Handoff閾値・固定証言・観測規則を設計する

---

## この章の位置

10章で、運用応用の条件付き適合特性と、NRA-IDEが保証しない範囲を分けました。次に必要なのは、独立して宣言した対象とCause-Side履歴に対して、何を構造入力として扱い、どこで通常生成を抑止し、固定Effect-Side証言を外部人間監査へ提示するかを、設計として定めることです。

ドメインチューニングは、適用対象の評価前に完了する外部設計活動であり、終端済みダイオード経路を継続しません。この章は、新しい評価履歴の観測規則、$\tau$の決定規則、正規閾値、固定Handoff証言、外部監査の連絡経路を設計・承認する担当者向けです。医療、航空、インフラなどの高リスク領域では、NRA-IDE単独で設定値を決めることはできません。各領域の責任者、検証手順、法令・規格、終端済みダイオード経路外の外部監査または現場対応体制が別途必要です。

---

## 正規閾値と破断境界

ドメインチューニングでは、三つの正規閾値と破断境界を混同しません。

- **$R_{warn}$**：`BOUNDARY_WARNING`を開始するドメイン固有の警告閾値
- **$R_{\mathrm{handoff}}$**：通常生成を抑止し、固定Handoff証言を外部人間監査へ提示するドメイン固有のHandoff閾値
- **$R_{irrev}$**：必須の不可逆遷移開始閾値。具体値はドメイン固有
- **$R = 1.0$**：宣言済みNRA-IDE評価の`RUPTURE_BOUNDARY`

$R_{warn}$、$R_{\mathrm{handoff}}$、$R_{irrev}$は、評価前に根拠とともに固定するドメイン固有の設計パラメータです。$R = 1.0$は宣言済み評価内で調整対象になりません。$\tau$またはいずれかの閾値を変更しても、この境界の意味を動かすことはできません。この分類は、自然界のすべての相転移をNRA-IDEの破断と宣言するものではありません。

$R_{irrev}$は共通の既定値を持ちませんが、適合する状態表は具体的なドメイン値と根拠を定義します。何を不可逆的挙動と呼ぶのか、どの観測と検証に基づくのかをドメイン仕様へ明記します。

$$0 \le R_{warn} < R_{\mathrm{handoff}} < R_{irrev} < 1$$

通常運用では、$R$が$R_{\mathrm{handoff}}$へ到達した時点で通常生成を抑止し、固定Handoff証言を外部人間監査へ提示して自律処理を停止します。停止理由を説明する新しい自由記述をLLMに生成させません。$R = 1.0$は、通常のHandoff閾値として用いません。

## 調整できるものと、不変に保つもの

### 調整できるもの

将来の独立して宣言した対象とCause-Side履歴に対して、根拠・適用範囲・版管理・承認を記録したうえで設計できるものは、次に限られます。新しい評価の開始前に固定し、旧履歴の調整にはしません。

- **$\tau$を決定する規則のパラメータ**：Cause-Sideの観測量、単位、品質条件、負荷履歴に基づいて$\tau$を更新する規則
- **$\tau$の初期条件と有効範囲**：対象系、計測条件、使用期間、対象外とする状態
- **$R_{warn}$**：`BOUNDARY_WARNING`を開始する警告条件
- **$R_{\mathrm{handoff}}$**：$R_{irrev}$と$R = 1.0$より前に置く、通常生成のHandoff条件
- **観測・変換・品質確認の規則**：$\delta$、$\tau$、$\omega$などの値の出所、変換手順、欠損・異常値・単位不一致の扱い
- **固定Handoff証言のスキーマと提示経路**：証言項目、外部監査の連絡経路、責任者、終端済み経路外の確認手順
- **$R_{irrev}$**：不可逆遷移開始の定義と根拠を伴う具体的なドメイン値

### 不変に保つもの

次の条件に触れた場合、それはチューニングではなく正規NRA-IDEへの適合を主張できなくする変更です。

- **$R = 1.0$を宣言済み評価の`RUPTURE_BOUNDARY`として扱う原則**
- **Effect-SideからCause-Sideの値、正規閾値、状態、不可逆ラッチ、規則、変換入力、更新根拠、出所を一切更新しない原則**
- **Cause-SideからEffect-Sideへの一方向だけを持ち、すべての$\Pi^{-1}$経路を遮断する因果ダイオード**
- **層数に依存せず、Cause-SideとEffect-Sideの権限、正規状態動作、証拠、テストを分離する原則**
- **LLMを含みPre-NRA / LLM / Post-NRA構成を宣言するシステムでは、構成した各層へ割り当てた責務を分離する原則**
- **$R_{\mathrm{handoff}}$で通常生成を抑止し、固定Handoff証言を外部人間監査へ提示する原則**
- **固定Handoff証言と最終固定証言のいずれにも、LLMが生成する自由記述の停止説明を用いない原則**
- **廃棄ログを旧Cause-Sideまたは新Cause-Sideの値、正規閾値、状態、不可逆ラッチ、規則、変換入力、更新根拠、出所にしない原則**
- **旧経路をEffect-Sideで終端し、後続評価を新しい因果ダイオードから始める原則**

## 設計の順序

設計は次の順序で進めます。

### 1. 対象と、自律処理の責任境界を定める

対象系とその新Cause-Side履歴を独立して宣言し、どの処理をNRA-IDEが通し、どの閾値で固定Effect-Side証言を外部人間監査へ提示するかを定めます。旧Effect-Side記録は、この対象または構造権威を成立させません。

### 2. Cause-Side入力と無効状態を定める

$\delta$、$\tau$、$\omega$などについて、新Cause-Sideの出所、単位、変換手順、品質条件、およびEffect-Sideからの隔離経路を記録します。物理的残留物は、独立して宣言した新対象の一部として新規観測できますが、旧Effect-Sideの値、正規閾値、状態、不可逆ラッチ、規則、変換入力、更新根拠、出所を、旧Cause-Sideにも新Cause-Sideにもimport、名称変更、再構成、再利用してはなりません。

### 3. $\tau$の決定規則を定める

$\tau$の初期条件、更新に使用するCause-Side入力、更新頻度、有効条件、規則の版、適用開始時点を明記します。

### 4. $R_{\mathrm{handoff}}$、固定Handoff証言、外部監査経路を定める

不可逆遷移・破断までに必要な対応余地を根拠に定めます。外部人間監査と現場対応は、終端済みダイオード経路の外側で行います。到達時の固定証言には、次の項目を固定スキーマとして含めます。

```text
HANDOFF_REQUIRED
REASON: domain-specific handoff threshold reached
OBSERVED: predefined structural fields
ACTION: normal generation suppressed; fixed Effect-Side testimony presented for external human audit

```

### 5. $R_{irrev}$と不可逆ラッチを定義する

$R_{irrev}$は`IRREVERSIBLE_TRANSITION`を開始します。その根拠を定義し、同じ履歴内では、自動、手動、人間レビュー、承認、版更新のいずれによってもラッチを解除できないことを確保します。通常生成を$R_{\mathrm{handoff}}$より後まで継続する理由にはできません。

### 6. $R \ge 1.0$後の固定動作を確認する

$R \ge 1.0$では通常生成を再開せず、次の最終固定証言のみを返します。

```text
RUPTURE_BOUNDARY
REASON: structural boundary reached
ACTION: final fixed testimony presented for external human audit

```

## 領域別に確認すること

数値だけを共通表として配ることはせず、以下のように各領域の責任境界と確認事項を定義します。各状態における詳細な出力挙動の制御については、12章に定義された「最小整合表」の基準に一元的に従います。

### 医療・救急領域

- **設定前に必要な確認**: 計測品質、患者・施設ごとの適用範囲、臨床責任者、終端済みダイオード経路外の外部監査または緊急対応経路
- **NRA-IDEが単独で決められないこと**: 診断、治療、トリアージ、患者固有の閾値

### 航空・移動体・制御領域

- **設定前に必要な確認**: センサー故障時の扱い、冗長系、既存安全設計との整合、終端済みダイオード経路外の現場対応時機
- **NRA-IDEが単独で決められないこと**: 運航・操縦・制御の安全認証、規制適合の判定

### インフラ管理領域

- **設定前に必要な確認**: 負荷履歴、計測器の校正、保全判断者、連鎖障害時の連絡手順
- **NRA-IDEが単独で決められないこと**: 構造健全性の専門判定、補修・停止の意思決定

### 言語生成支援領域

- **設定前に必要な確認**: $\delta$・$\tau$を何のCause-Side量として定義するか、通常生成を抑止する目的、固定Handoff証言を受け取る外部監査者
- **NRA-IDEが単独で決められないこと**: 出力の事実性、利用者への適合性、幻覚の完全な防止

## 変更管理と廃棄ログ

規則やパラメータを変更する場合は、次の項目を設計変更記録として残します。

- 変更対象と適用範囲
- 旧版と新版の規則
- 変更の根拠と確認に用いたCause-Side資料
- $R_{warn}$、$R_{\mathrm{handoff}}$、$R_{irrev}$の順序関係
- 想定される固定Handoff頻度・運用影響
- 承認者、適用時点、検証手順
- 新しい評価が、独立して宣言した対象、固有のCause-Side、新しい因果ダイオードから始まること
- 旧Effect-Sideの値、正規閾値、状態、不可逆ラッチ、規則、変換入力、更新根拠、出所を、旧Cause-Sideにも新Cause-Sideにもimport、名称変更、再構成、再利用しないこと

廃棄ログは、終端済みダイオード経路の外部で人間が監査のためにだけ読めます。Effect-Sideまたは外部記録のままであり、自動処理、手動レビュー、承認、版更新のいずれも、その内容を旧Cause-Sideまたは新Cause-Sideの値、正規閾値、状態、不可逆ラッチ、規則、変換入力、更新根拠、出所へ変換しません。将来設計は、新履歴のために独立して確立したCause-Side根拠だけを用います。

---

## 共通の原則

分野が変わっても、次の原則は変わりません。

- 評価前に$0 \le R_{warn} < R_{\mathrm{handoff}} < R_{irrev} < 1$を固定する
- $R = 1.0$を宣言済み評価の`RUPTURE_BOUNDARY`として扱い、自然界のすべての相転移へ一般化しない
- $\tau$の値はCause-Sideの履歴で変わり得るが、Cause-Sideの値、正規閾値、状態、不可逆ラッチ、規則、変換入力、更新根拠、出所をEffect-Sideから変更しない
- Handoff閾値の根拠、固定証言、外部監査の連絡経路、記録を設計時に定める
- 設定値そのものではなく、その根拠・出所・版・承認を証言として残す
- 旧経路はEffect-Sideで終端し、後続評価は独立して宣言した対象、新Cause-Side、新しい因果ダイオードから始める
