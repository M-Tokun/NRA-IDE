# 07 Fail-Closed — 通常生成を抑止し、外部人間監査へ固定証言を提示する

<!-- 07_fail_closed_JP.md -->

---

## 「分からない」と言うだけでは、構造境界を強制できない

AIが不確実なときに「分からない」と言うことは、誠実な応答として重要です。

ただし、その応答が出るかどうかを、モデルの方針、訓練、文脈、あるいはその時点の生成に任せるだけでは、構造境界を強制できません。

多くの生成系は、利用者の問いに対して役に立つ回答を返すよう設計されています。そのため、不確実性や限界がある場面でも、再生成・補足・言い換えによって通常回答を続ける経路が残り得ます。

Fail-Closed応用が扱うのは、回答が誠実に見えるかどうかではありません。明示的に宣言した観測・更新・閾値・証言規則の下で、対応する構造条件に達したとき、通常の生成回答を通さない実装経路をモデルの意思や自己評価から独立して要求します。

---

## Fail-Closedは正規状態を横断する実装原則である

05で、通常出力を止める正規Handoff閾値`R_handoff`と、`R = 1.0`にある宣言済み評価の`RUPTURE_BOUNDARY`を区別しました。

```text
R = δ / τ
0 <= R_warn < R_handoff < R_irrev < 1
```

この章でも、これらの境界を混同しません。

| 正規状態 | 条件 | 構造応答 |
|---|---|---|
| `PERMIT` | `0 <= R < R_warn` | 構造監査を伴う通常運用 |
| `BOUNDARY_WARNING` | `R_warn <= R < R_handoff` | 警告と必須構造証言 |
| `HANDOFF_REQUIRED` | `R_handoff <= R < R_irrev` | 固定Handoff証言。新規自律判断を停止 |
| `IRREVERSIBLE_TRANSITION` | `R_irrev <= R < 1` | 不可逆ラッチを保持し、構造証言を継続 |
| `RUPTURE_BOUNDARY` | `R >= 1` | 破断後固定証言 |

唯一の公理は「存在は生成である。」です。第二公理以降は存在しません。基礎式は、宣言対象の状態を式へ落とした本当の数学的根本式であり、公理でも、安全指標・局所計器・単なる境界接近率でもありません。第二次式／二重ゆらぎ式はIDEという計算方法・動力学エンジンであり、公理ではありません。NRA-IDEの本体は生存式・生存領域です。Fail-Closedは、その領域を事故防止運用制御へ適用した部分応用であり、安全保証を与えません。

`R_handoff`は、対象ドメインの不可逆域接近条件に対応し、評価前にCause-Sideドメイン権限が固定する正規Handoff閾値です。Effect-Side結果や外部監査が評価後に定めたり書き換えたりする条件ではありません。通常回答を止めるべきなのは、原則としてこの時点です。

`R = 1.0`は、正規Handoff閾値ではありません。宣言済みNRA-IDE評価において残存構造余裕`τ − δ`がなくなる`RUPTURE_BOUNDARY`です。この分類は、自然界のすべての相転移をNRA-IDEの破断と宣言するものではありません。この境界に到達した後、停止理由を説明するためにLLMへ自由記述を新たに生成させてはなりません。

---

## 構造が通常生成を止める

`R_handoff ≤ R < R_irrev`では、Post-NRAが通常の生成内容を利用者へ渡しません。`R_irrev ≤ R < 1`では`IRREVERSIBLE_TRANSITION`となり、不可逆ラッチと構造証言を保持します。

同一履歴内では、`R_irrev`到達後にRが低下しても、自動処理、手動介入、人間レビュー、承認、版更新のいずれによっても不可逆ラッチを解除できません。

代わりに、Post-NRAがCause-Sideに基づいて確定した値と、事前に固定された様式だけを用いて、外部人間監査へ固定Handoff証言を提示します。

```text
HANDOFF_REQUIRED
REASON: domain-specific handoff threshold reached
OBSERVED: predefined structural fields
ACTION: generated response suppressed; fixed Effect-Side testimony for external human audit
```

この通知は、LLMがその場で考えた説明ではありません。構造判定の結果として、あらかじめ定めた項目を返す固定Effect-Side証言です。外部人間監査はこれを調査できますが、監査や承認によって旧Cause-Sideまたは新Cause-Sideへの逆向きの辺は生じません。固定Handoff証言または破断後固定証言へ、新たに生成した自由形式説明を追加してはなりません。

したがって、LLMが「このまま答えてよい」と自己評価しても、評価スコアが高くても、Post-NRAの`HANDOFF_REQUIRED`判定を上書きできません。止める根拠は、出力の説得力ではなく、Cause-Sideから確定した構造状態です。

---

## R = 1.0以後は、通常の説明を続けない

`R ≥ 1.0`は、宣言済み評価において、その評価の構造余裕が失われた終端境界です。

たとえば、`δ = 0.15`、`τ = 0.14` であれば、

```text
R = 0.15 / 0.14 ≒ 1.071
```

となります。このとき、通常の生成回答を作り直したり、より慎重な説明へ言い換えたりしても、構造余裕そのものは回復しません。

Post-NRAが返すのは、事前に定めた破断後固定証言、または保護された廃棄ログへの参照です。

```text
RUPTURE_BOUNDARY
REASON: structural boundary reached
ACTION: post-rupture fixed testimony; old evaluation history terminated at Effect-Side
```

これは、利用者へ何も伝えないことではありません。通常の生成回答を抑止し、事前に定めた構造上の破断後固定証言だけを伝えることです。

---

## 再生成は、固定Handoff証言の代わりにならない

通常回答が抑止された後に、同じLLMへ「もう一度だけ答えさせる」「より慎重な表現にさせる」と指示しても、それは固定Handoff証言の代替にはなりません。

`R_handoff`到達後に必要なのは、生成を続けることではありません。対象ドメインを理解する外部監査者は、ダイオード経路の外側で観測値・設定根拠・Handoff閾値を監査できますが、その監査は旧構造評価を継続も書換えもしません。

`R ≥ 1.0`の後は、通常生成を重ねても、宣言済み評価を`RUPTURE_BOUNDARY`から通常運用へ戻すことはできません。再生成は、構造状態を更新する根拠にも、不可逆ラッチを解除する根拠にも、境界記録を取り消す根拠にもなりません。

旧経路はEffect-Sideで終端します。後続評価が必要な場合は、独立して宣言した対象、新たに確立したCause-Side観測と規則、新しい因果ダイオードから開始します。物理的残存物はその対象の一部として新たに観測できますが、旧Effect-Sideの値、正規閾値、状態、不可逆ラッチ、規則、変換入力、更新根拠、出所をCause-Side資料としてimport、名称変更、再構成、再利用してはなりません。

---

## ωは正規状態を置き換えない

ωは、事前に固定したドメイン規則の下で遷移継続を観測したかを補助的に証言できます。代替の状態分類器ではありません。

旧説明語`SILENCE`や`HALT`は、`RUPTURE_BOUNDARY`、`OUT_OF_DESCRIPTION_DOMAIN`、`CONFESSION`を置き換えません。ωが正でもゼロでも、Rを下げず、不可逆ラッチを解除せず、安全な回復を立証しません。人間が観測経路と遷移条件を監査できるのは、終端済みダイオード経路の外側だけです。その監査は、旧Effect-Side証言をCause-Sideの値、正規閾値、状態、不可逆ラッチ、規則、変換入力、更新根拠、出所へ変換できません。

Fail-Closedの目的は、構造終端を通常回答で覆い隠すことではありません。通常生成を抑止し、固定証言を計算へ戻さず外部人間監査へ提示することです。

---

## 意味上の安全判定とは役割が異なる

Fail-Closedは、出力内容の正しさ、法令適合性、倫理性、または危険性を意味だけから判定する仕組みではありません。

コンテンツフィルタ、ガードレール、モデレーションなどは、それぞれ別の目的を持ち得ます。NRA-IDEのFail-Closedは、それらを一律に置き換えるものではありません。

この部分的な運用応用において、Fail-Closedが扱うのは、定められた観測・更新規則の下で、宣言済み構造状態が通常生成を許可するかです。NRA-IDEの生存式・生存領域を出力許可ゲートとして再定義するものではありません。

このため、LLMの通常出力が意味上正しいこと、δ・τの観測値が正しいこと、τやR_handoffの設定根拠が妥当であることについて、Fail-Closedは安全保証を与えません。

---

## Fail-Closed原則の適合範囲

実装が正規状態規則へ適合し、Cause-Sideの観測経路、τの更新規則、閾値設定、固定証言経路が保たれている場合、Fail-Closed原則は次の動作を要求します。

- `R_handoff`に到達したとき、通常の生成回答を抑止し、事前確定の固定Effect-Side証言を外部人間監査へ提示すること。
- `R ≥ 1.0` で`RUPTURE_BOUNDARY`となり、破断後固定証言へ切り替えること。
- 停止・固定Handoff証言の判定根拠を終端Effect-Sideまたは外部記録として残し、旧Cause-Sideにも新Cause-Sideにも、値、三閾値、状態、不可逆ラッチ、規則、変換入力、更新根拠、出所として戻さないこと。

一方で、次のことは保証しません。

- LLMの通常出力が意味上正しいこと。
- Cause-Sideの観測値や外部入力が汚染されていないこと。
- τ、R_handoff、ωの定義や設定が対象ドメインに対して適切であること。
- 終端済みダイオード経路の外側で、Handoff後にどの外部判断を行うべきか。

この適合範囲を定めることは、条件付きで強制される実装動作を、安全保証や終端経路外で人間が負う判断と混同しないために必要です。

## 次章への接続

Fail-Closedでは、通常生成を抑止した条件と構造状態を、人間が逆向きの辺を作らず外部監査できます。

次の章では、通常計算へ再流入させない残差と、停止・固定Handoff証言の根拠をどのように記録するかを扱います。ログは外部監査を可能にする終端済み証言です。自動処理、手動レビュー、承認、版更新によって、旧Cause-Sideまたは新Cause-Sideの資料へ変換してはなりません。
