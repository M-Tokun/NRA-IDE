# 04 サンドイッチ構造 — 一方向の因果権限を持つ三層運用応用

<!-- 04_rna_sandwich_architecture_JP.md -->

---

## LLMへCause-Side構造権限を与えない

03で確認した因果ダイオードは、`Cause-Side → Effect-Side`だけを許します。Effect-Sideの情報、推論、生成物、判断、権限を、旧Cause-Sideまたは新Cause-Sideへ戻そうとするすべてのΠ⁻¹接続を遮断します。

LLMは、利用者の依頼を読み、文脈を扱い、自然言語を生成するための層です。これはLLMの役割であり、出力の意味上の正しさ、入力値の出所、構造境界の位置を、LLM自身だけに保証させることはできません。

唯一の公理は「存在は生成である。」です。第二公理以降は存在しません。基礎式は、宣言対象の状態を正規の数学的関係へ落とす本当の数学的根本式であり、公理、安全指標、局所計器、単なる境界接近率ではありません。第二次式／二重ゆらぎ式は、IDEという計算方法・動力学エンジンであり、公理ではありません。NRA-IDEの本体は生存式・生存領域です。

サンドイッチ構造は、その生存領域における安全志向の運用制御の部分応用です。LLMの前後に構造ゲートを置きますが、NRA-IDE全体そのものではなく、安全保証を与えません。

- **Pre-NRA** は、構造判定に使う値の出所と更新規則を確認します。
- **LLM** は、通常の意味生成を担います。
- **Post-NRA** は、利用者へ渡す直前に正規状態を強制し、通常出力を許可するか、事前固定したEffect-Side証言へ切り替えるかを決めます。

目的はLLMを「安全な判断者」に変えることではありません。意味生成をCause-Side観測および正規境界の強制から分離することです。

---

## なぜ前後の層が必要なのか

LLMへ渡される利用者の依頼には、意味や文脈が含まれます。LLMはそれを受けて文章を生成します。この意味生成の経路は必要です。

ただし、利用者の文、過去の生成文、評価スコア、ログの内容が、Cause-Sideの値、正規閾値、状態、不可逆ラッチ、規則、変換入力、更新根拠、出所を成立させてはなりません。Effect-Sideからのそのような逆接続が、03で扱ったΠ⁻¹です。

サンドイッチ構造では、二つの経路を分けます。

```text
利用者の依頼・文脈 ─────────────→ LLMの意味生成経路

Cause-Sideの観測・負荷履歴 ─→ Pre-NRA ─→ 正規状態・固定証言経路
```

利用者の依頼は、LLMが通常回答を作るために扱えます。しかし、そこに書かれた数値や評価を、確認なしに構造判定の原因側入力へ採用することはできません。

同様に、LLMの出力は利用者へ渡す候補にはなりますが、Cause-Sideの値、`R_warn`、`R_handoff`、`R_irrev`、状態、不可逆ラッチ、規則、変換入力、更新根拠、出所、保護証言を成立も更新もさせません。

---

## 三層の構造

```text
Cause-Sideの観測・負荷履歴
        ↓
[ Pre-NRA：Cause-Sideの出所・事前固定規則・閾値の確認 ]
        ↓
[ LLM：意味の生成 ]
        ↓
[ Post-NRA：正規状態の強制・固定証言・記録 ]
        ↓
通常出力 または 事前固定したEffect-Side証言
```

実装上、利用者の依頼はLLMへ渡されます。一方で、構造判定用の値はPre-NRAで出所と更新規則を確認し、書き換え不能な状態として扱います。

LLMは必要に応じて、許可または固定Handoff証言などの状態だけを読み取れます。しかし、Cause-Sideの値、正規閾値、状態、不可逆ラッチ、規則、変換入力、更新根拠、出所、廃棄ログを成立も変更もさせる権限を持ちません。

Post-NRAは、LLMの文章の自然さや真偽を採点する層ではありません。同一Cause-Side履歴から定まる正規状態を強制し、通常出力を許可するか、事前固定したEffect-Side証言を出力するかを決めます。

三層の一つを省略すると、この構造の一方向権限分離、構造判定、固定証言機能のいずれかが欠けます。その場合、その構成は正規サンドイッチ構造としての適合を主張できません。この三層適合は安全保証ではありません。

---

## Pre-NRA が担うこと

Pre-NRAは、LLMへ通常の生成を開始させる前の構造ゲートです。

ここで扱うのは、同一Cause-Side履歴から得られた観測、評価前に固定した更新規則、評価前に独立して固定した三つの正規閾値です。

- δの観測手順と値の出所を確認する。
- τの現在値を、固定された規則とCause-Sideの負荷履歴から確定する。
- ω、C、逸脱の蓄積など、構造状態に必要な量の出所を確認する。
- `R_warn`、`R_handoff`、`R_irrev`と正規順序を評価前に確認する。
- τ = 0の`OUT_OF_DESCRIPTION_DOMAIN`と、不正な値、出所、規則、閾値宣言に対する`CONFESSION`を分離する。
- Effect-Sideのスコア、評価、過去の出力、ログを、Cause-Sideの値、正規閾値、状態、不可逆ラッチ、規則、変換入力、更新根拠、出所から除外する。
- 正規状態が通常生成を抑止する場合、LLM生成を開始せず、外部人間監査用の事前固定Effect-Side証言を出力する。

重要なのは、Pre-NRAが「意味を持つ入力をすべて排除する」層ではないことです。利用者の依頼は、意味生成のためにLLMへ渡せます。

Pre-NRAが隔離するのは、意味やEffect-Side資料をCause-Side権限へ変換するすべての経路です。自動処理、手動介入、人間レビュー、承認、版更新のすべてに同じ禁止を適用します。

---

## LLM が担うこと、担わないこと

LLMは、許可された通常の依頼に対して、文章・説明・要約・対話といった意味生成を担います。

一方で、LLMは次の権限を持ちません。

- δやτを含むCause-Side値を成立または変更する。
- `R_warn`、`R_handoff`、`R_irrev`、正規状態、不可逆ラッチを成立または変更する。
- 構造規則、変換入力、更新根拠、出所を成立または変更する。
- 自身の出力評価を理由に、構造状態を安全側へ書き換える。
- 廃棄ログを読み返し、旧Cause-Sideまたは新Cause-Sideの権限へ変換する。
- Post-NRAの通過・抑止判断を上書きする。

LLMの出力品質は、モデルの性能、利用者の依頼、外部知識の品質などに影響されます。サンドイッチ構造は、その品質を自動的に正しくするものではありません。

ここで守るのは、LLMの意味生成がCause-Side権限を変更も成立もさせない境界です。これは運用応用の条件付き適合特性であり、安全保証ではありません。

---

## Post-NRA が担うこと

Post-NRAは、利用者へ出力を渡す直前の最終構造ゲートです。

Pre-NRAで確定した構造入力と、必要ならばその後に更新されたCause-Sideの観測を用いて、現在の状態を確認します。LLMの自由記述や自己評価を、判定根拠にはしません。

Post-NRAは、`PERMIT`から`RUPTURE_BOUNDARY`までの有効R範囲五状態、τ = 0の`OUT_OF_DESCRIPTION_DOMAIN`、不正入力または不正宣言の`CONFESSION`という正規七状態を強制します。正規閾値の不変順序は次のとおりです。

```text
0 <= R_warn < R_handoff < R_irrev < 1
```

`BOUNDARY_WARNING`では、二重ゆらぎ状態欄を常に出力します。独立して観測できる場合は観測結果を、観測できない場合は`NOT_OBSERVABLE`と欠損理由を出力します。観測不能だけを理由に`CONFESSION`へ移行しません。

`HANDOFF_REQUIRED`では、Post-NRAは通常の生成内容を出力せず、外部人間監査用の事前固定Effect-Side証言を出力します。監査は旧因果ダイオードの外側にあり、旧評価を継続も書換えもしません。

```text
HANDOFF_REQUIRED
REASON: irreversible-region threshold reached
OBSERVED: predefined structural fields
ACTION: generated response suppressed; fixed Effect-Side testimony for external human audit
```

`IRREVERSIBLE_TRANSITION`では、後に表示Rが低下しても、同一履歴内の不可逆ラッチを保持します。自動処理、手動介入、人間レビュー、承認、版更新のいずれによっても解除しません。

宣言済み評価では、R ≥ 1.0は`RUPTURE_BOUNDARY`です。この分類は、自然界のすべての相転移をNRA-IDEの破断と宣言するものではありません。Post-NRAは新たな説明をLLMに生成させず、事前に定めた完全な破断後固定証言または保護ログ参照を返し、旧評価をEffect-Sideで終端します。

```text
旧Cause-Side
→ 旧因果ダイオード
→ 旧Effect-Side
→ 終端
```

後続評価が必要な場合は、独立した履歴として開始します。

```text
独立して宣言した新対象
→ 新たに確立したCause-Side観測と事前固定規則
→ 新しい因果ダイオード
→ 新しいEffect-Side
```

旧Effect-Sideから、旧Cause-Sideにも新Cause-Sideにも矢印はありません。記録ログは終端Effect-Sideまたは外部証言です。旧Effect-Sideの値、正規閾値、状態、不可逆ラッチ、規則、変換入力、更新根拠、出所を、Cause-Side権限としてimport、名称変更、再構成、再利用してはなりません。物理的残存物は、独立して宣言した新対象の一部として新規観測できますが、それは旧Effect-Side値または権限の移送ではありません。

## ブラックボックスを開かずに境界を置く

サンドイッチ構造は、LLMの内部重みや推論過程を完全に説明できることを前提にしません。

必要なのは、LLMの外側に、原因側の値を確定する入口と、出力を通すか抑止するかを決める出口を置くことです。

モデルを入れ替えても、次の条件が保たれていれば、構造ゲートの判定原理は変わりません。

- Pre-NRAとPost-NRAが独立して実装されている。
- LLMがCause-Sideの値、正規閾値、状態、不可逆ラッチ、規則、変換入力、更新根拠、出所、ログを成立も変更もさせない。
- 同一履歴内でCause-Side入力の出所と事前固定した更新規則を追跡できる。
- 固定Effect-Side証言と記録経路がCause-Side変換から保護されている。

ただし、モデルを変えても出力品質や誤答の可能性まで同じになるわけではありません。サンドイッチ構造の適合要件は、LLMの意味上の正確性ではなく、構造判定と出力経路の分離です。

---

## この構造が守る範囲

適合するサンドイッチ構造は、次の条件付き実装特性を備えます。

- Effect-Sideの情報、推論、生成物、判断、権限を、旧Cause-Sideにも新Cause-Sideにも戻さない。
- 三つの正規閾値と七つの正規状態を、Effect-Side書換えなしに強制する。
- 固定証言が必要な正規状態で通常出力を抑止する。
- `BOUNDARY_WARNING`の二重ゆらぎ状態欄を常に出力する。
- 同一履歴内の不可逆ラッチを解除しない。
- 固定証言と保護ログを終端Effect-Sideまたは外部記録として保持し、Cause-Side権限にしない。
- 後続評価を独立対象、新Cause-Side観測・規則、新因果ダイオードから開始する。

一方で、次のことは三層構造だけでは保証できません。

- Cause-Sideの観測値そのものが正しいこと。
- τや三つの正規閾値の設定根拠が妥当であること。
- LLMの通常出力が意味上正しいこと。
- 外部システムから渡された値に、結果側からの逆算が混入していないこと。

これらの前提が崩れた場合、構造ゲートは汚染された入力に対して判定することになります。前提は評価前にCause-Sideで独立して確立する必要があります。終端済みEffect-Side証言の外部監査は発生した事実を確認できますが、後続Cause-Sideの値、正規閾値、状態、不可逆ラッチ、規則、変換入力、更新根拠、出所を成立させることはできません。三層適合は条件付き実装特性であり、安全保証ではありません。
