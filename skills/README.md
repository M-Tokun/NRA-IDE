# AI思考におけるふらつき防止と経路の考え方

> 本書は `skills/` 配下の全 Skill（`thought-boundary-5w1h`・`axis-boundary-reasoning`・`document-paper-writing`・`nra-depth-guard`・`agents-md-guard`・`operation-approval`・`file-operation-report`）に共通する基礎原則を定める。

## 1. 推論させる領域と推論させてはならない領域
AIの本領は文脈から未指定の要素を補う「推論」にある。文章作成や設計展開では推論が不可欠となる。しかし、権限確認、Gitの送信制御、エラー停止、履歴保護といった「経路選択と境界制御」では、1000回に1回のふらつきも許されない。999回は正しく動いても、1000回目に別の分岐を選べば、無断送信や無限ループ、規則逸脱という事故に直結する。
正確さが絶対条件となる領域でふらつきをゼロにするには、「注意深く推論させる」のではなく、「経路選択の構造から推論を発生させない」設計が必要となる。

## 2. 並列・配列・同列選択が「迷いと揺れ」を生む理由
なぜAIは分岐で迷い、ふらつくのか。最大の原因は、選択肢を「並列・配列・同列選択」で記述することにある。
言語モデルは文脈内の全要素へ同時に注意（アテンション）を向ける特性を持つ。そのため、`select / case`文、`A | B | C`の並列記号、あるいは一覧表や配列として複数の選択肢を「横並び（同列）」に置くと、AIは上から順に切り捨てるのではなく、全選択肢を同時に天秤にかけて「どれが最も近いか」を比較推論してしまう。この同列比較には3つの欠陥がある。
第一に、複数条件へ同時該当する事象が起きた瞬間、同列ゆえに優先順位が定まらず、直前の対話次第で選ばれる先が揺れる。
第二に、初期読込文書（`AGENTS.md`等）に例外やエラー原因の配列を並べると、作業開始の第1段階から全配列の比較推論が走り、平常時の判断まで揺らぐ。
第三に、同列の候補が視界に残ることで「Aが駄目なら同列のBを試す」という循環推論が働き、停止条件を迂回してループに入り込む。
つまり、並列・配列・同列選択という構造自体が、AIに「比較と解釈」を強制する迷いの発生源なのである。

## 3. なぜインタプリタ型の直下式命令が有効なのか
この同列比較によるふらつきを遮断するのが、88 BASICのように行番号に沿って上から下へ1行ずつ逐次実行する「インタプリタ型の直下式命令」である。全体を俯瞰して解釈させるのではなく、実行位置を1行ずつ直下に落とし、「1番号＝1条件＝1遷移」で処理させる方式には3つの利点がある。
1. **視野の単一化（比較推論の消滅）**: 1行には単一の観測条件（YESかNOか）しか書かない。AIは他候補と比べる必要がなく、目の前の1行の真偽だけを機械的に判定する。
2. **位置による絶対優先順位の固定**: 上から直下に流れるため、若い行番号（上流）ほど先に評価される。上流でYESとなり`GOTO`した時点で下流は評価すらされず、同時該当の迷いが消える。
3. **直下落下と片道終了によるループ排除**: 条件がNOなら無条件で次番号へ落ち、エラー時は代替実行をせず`STOP`だけを返して終端（`99`）へ直下終了する。後方ジャンプを禁じることで循環推論の余地がなくなる。

## 4. 事例：NRA-IDEにおける経路改修
- **事例1：同列選択（`|`）の衝突から直下式への改修**
  `docs/ERROR_MANUAL.md`初版では、`reason="PLAN_REQUIRED" GOTO 200 | push_gate.py の reason あり GOTO 210`と`|`で同列に並べていた。すると`PLAN_REQUIRED`発生時に両条件へ該当し、200と210の同列比較で迷いが生じた。これを1行1条件の直下式命令（`26 IF 出力に "\"reason\": \"PLAN_REQUIRED\"" を含む: GOTO 200` → `28 IF push_gate.py の出力に "\"reason\":" を含む: GOTO 210`）へ改めた結果、`26`で即座に`200`へ飛び、`28`との比較推論は消滅した。
- **事例2：初期文書の肥大化防止と片道停止**
  `AGENTS.md`で「必要な下位規則を読む」と委譲していた際、AIが手順を読まず素の`git push`を実行して停止し、リモート障害やReload Windowを疑う揺れが生じた。そこで`AGENTS.md`には原因配列を書かず、`55`（`git push`なら`scripts/push.py`）、`65`（エラーなら`docs/ERROR_MANUAL.md`へ飛び戻り`STOP`で`95`→`99`へ直下終了）だけを置いた。これで第1段階の推論負荷をゼロに保ち、迷走とループを封じた。

## 5. 結論
生成領域の内側と制御領域の外枠を峻別し、外枠から並列・配列・同列選択を排して「インタプリタ型の直下式命令」で1行ずつ落下させること。比較させず、戻らせず、1条件ずつ直下に流すこの構造こそが、1000回に1回のふらつきを根絶する設計原則である。
