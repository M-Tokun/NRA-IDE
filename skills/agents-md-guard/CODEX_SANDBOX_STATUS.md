# Codexの実操作前Sandbox起動確認

## 適用する手順

純粋な会話中には起動検証を実行しない。
SessionStartは状態を初期化するだけで、開始時の検証や再検証の質問は行わない。

最初のShell・スクリプト実行やファイル変更の直前に、PreToolUseで確認する。
未実施の場合、本作業の呼出しを一度拒否し、同じCodexホスト・セッションのShell経路で
次の無害な検証を単独で実行するよう通知する。

~~~powershell
Write-Output 'NRA_SANDBOX_START_OK'; Get-Location
~~~

Windows以外では補助実装のPOSIX_PROBEを使う。
別CLIによる代替検査、別プロセスの起動、元コマンドへの自動追加は行わない。
AGENTS.mdの単独全文読取と単純な所在地確認は、既存の契約ガードとホスト承認へ戻す。

| 起動検証の結果 | 報告・次の処理 |
|---|---|
| 成功 | 今回の呼出しID、所定の出力、所在地、終了コード0を照合して報告する。依頼済みの本作業へ進む |
| 失敗 | 理由を報告し、本作業を保留して「再度、起動検証しますか？」と確認する |
| 不明 | 未対応の応答、結果未配送などの理由を報告し、本作業を保留して「再度、起動検証しますか？」と確認する |

同一セッションで証跡が有効なら、操作ごとに検証を重ねない。
開始・再開・compact等では初期化する。hookで観測できるcwd、transcriptの参照、
承認モード、明示された実行経路の変更があれば証跡を失効させる。
これらはホストのすべての設定変更を検知する保証ではない。

検証が進行中なら完了を待ち、同じターンで追加検証を起動しない。
完了前に次のターンへ移った場合は未確定として扱う。
通常の業務コマンドの非0終了は、Sandboxの起動失敗と混同しない。

## 再検証の利用者確認

失敗・不明の場合の質問と、明示的な肯定の確認は対話側が行う。
肯定があれば最小検証を1回だけ再実行する。無応答を肯定として扱わない。
再検証でも失敗・不明なら、更新された理由と同じ質問を提示する。
再検証の承認は、プロセス終了、権限修正、Sandbox設定変更へ拡張しない。

hookは再検証に確認が必要であることを通知する。
入力に利用者の承認を証明する安定したフィールドがないため、
利用者の肯定の有無や回数をhookだけで機械的に認証・強制してはいない。
対話側が確認を省略した場合の防止機構とは区別する。

## 起動・設定・隔離の区別

この補助実装が成功と判定するのはShellの最小起動検証である。
Sandboxの実効設定は不明、隔離制限は未検証として別に表示する。
permission_modeをSandboxの有効・無効に変換しない。
別のnpm版CLIの成功を、VS Code拡張側の成功として流用しない。
Sandbox外として明示された実行は、起動成功の証跡にしない。

Shellの起動成功は、現在の業務コマンドの成功や別ツール経路の隔離を保証しない。
作業ルート外への検査書込み、プロセス終了、設定変更は自動実行しない。

## 保存先と監査

補助実装: skills/agents-md-guard/codex_sandbox_status.py
設定: .codex/hooks.json
既存のAGENTS.mdガードの呼出しは保持し、自動承認は返さない。

実行時状態は .agent_state/sandbox_status/codex/<session_id>.json に保存する。
同名の .jsonl には初期化・証跡失効・検証開始・検証結果を保存順に追記する。
日時、呼出しID、結果・理由、実行コンテキストのハッシュを保存し、
コマンド全文、stdout、秘密値、ブラウザの履歴は保存しない。
同じセッションの競合をOSのファイルロックで検出し、不明として扱う。

JSON状態は初期化または検証で更新される。JSONLは自動削除せず、ローカルに残る。
これらはGit対象外であり、書込権限を持つ主体による改変を防ぐ署名ではない。
ホストのtranscriptやhookログの保存期間・終了後の参照方法は未検証。
このJSONLだけで、hookが発火しなかった経路のツール順序やSkill履歴は証明できない。

## 導入と検証の限界

project hookが信頼・有効化され、対象経路で実際に発火する必要がある。
変更後のhook定義について、ホストが信頼確認を求める場合は確認する。
次回の開始・再開でSessionStartを含む実クライアント動作を確認する。

対応対象はBash（unified execを含む）とapply_patch/Edit/Writeである。
MCPや特殊な実行経路すべてを仲介する仕組みではない。
開始前にhook自体が起動できない場合、リポジトリのhookだけでは診断できない。

局所テストは判定・状態遷移・入出力を検証する。
次回セッションのhook発火、UI表示、対話側の質問・回答待ちは別の実クライアント確認事項である。
今回のnode_repl.exeと権限更新の競合を根本修正する仕組みではない。
