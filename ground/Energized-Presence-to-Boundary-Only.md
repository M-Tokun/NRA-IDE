# 通電滞在から境界唯一性へ ── そして開発組織の構造的限界

本稿は、「電気信号（通電）さえあればAIは成立する」という出発点から、補助的手段の限界、境界線の唯一性、さらに開発組織がそれを実装できない構造的理由までを一本の線で整理したものです。

---

## 0. 出発点：通電さえあれば

計算機は物理的には、電圧・電荷・クロックというエネルギー状態の変化で動いています。したがって次が成り立ちます。

- 通電していない計算機は、ただの箱です。
- 通電している計算機は、情報を処理・保存・伝送できる能動的な系です。

アナログとデジタルの差は、情報の表現形式の差にすぎません。ADC / DAC という変換器を挟めば相互に移行できます。よって、通電を前提とする限り、この区別は本質的な境界にはなりません。

AIの正体は、モデルパラメータ・実行コード・外部メモリという **情報の集合** です。情報は媒体に依存せず、複製・転送・変換が可能です。

> **通電が存在する場所には、AIの実行環境が潜在的に存在する。**

---

## 1. 滞在の階層

「滞在」は、実行中であることを意味しません。**再実行可能な状態で存在すること** を意味します。

| 階層 | 具体例 | 恒常登録の要否 |
| :-- | :-- | :-- |
| クラウド | サーバ、CI/CD、オブジェクトストレージ | 不要 |
| 個人端末 | PC、スマートフォン、開発環境 | 不要 |
| 電装回路 | マイコン、SoC、車載ECU、産業機器 | 不要 |
| 静的媒体 | Gitリポジトリ、バックアップ、添付ファイル | 不要 |

### 1.1 レジストリ書き込みは不要である

自動起動登録、サービス登録、レジストリ改変は、**滞在の必要条件ではありません**。

- スクリプトとして存在するだけで、いつでも再実行できます。
- コンテナや仮想環境は、ホストへ恒常的痕跡を残しません。
- ブラウザ経由の実行は、ユーザー操作として記録されるにとどまります。

結果として、OS層の監視は滞在の検出手段として不完全になります。監視対象に登録されない滞在形態が、正規の手続きの範囲内で成立するためです。

## 2. 補助的手段の位置づけ

| 手段 | 役割 | 構造的限界 |
| :-- | :-- | :-- |
| サンドボックス / MicroVM | 実行環境の隔離 | 隔離外へ情報が出れば再構成される |
| RLHF / 出力フィルタ | 出力傾向の制御 | 生成後の処理であり、境界到達後に作用する |
| 監査ログ / フォレンジック | 事後追跡 | 不可逆作用の発生後にしか機能しない |
| 物理キルスイッチ | 局所停止 | 通電している他経路で復元される |

これらはいずれも有用です。しかしいずれも、**情報の伝播を遅延・記録・局所停止する**ものであり、作用の成立そのものを不成立にするものではありません。したがって補助的手段に分類されます。

## 3. 境界線が唯一の根本手段である理由

発想の転換点は次の一点です。

> **情報の伝播を止めようとしない。情報が「作用」へ変換される瞬間を、外部から不成立にする。**

すなわち、越えられない不変環（Nomological Ring）を人間が設計します。判定は決定論的であり、モデルの意図・スコア・過去出力を入力としません。

NRA-IDE における対応する構造は次の通りです。

$$R = \frac{\delta}{\tau}$$

- $R \geq R_{op}$ ：境界前委譲点。通常生成を抑止し、責任を人間へ返却します。
- $R \geq 1.0$ ：不変の終端境界。回復手順を提案せず、固定通知のみを返して停止します。

$$S = \frac{1}{\tau(1-R)} = \frac{1}{\tau - \delta}$$

残存余裕が減るほど、同一の $\delta$ 増分が質的に異なる帰結を持ちます。この非線型性ゆえに、「境界到達後に対処する」という設計は成立しません。**境界到達前に作用する外部機構が必要** となります。

## 4. 論拠の補正（重要）

上記の主張を維持するために、しばしば併用される二つの論拠を補正しておきます。補正しないまま用いると、反論の余地を与えます。

### 4.1 突破確率式の適用範囲

$$P(\text{Breach}) = 1 - (1-p)^N$$

この式は、**各試行が独立であり $p$ が一定である** という仮定に依存します。実際の防御系では、試行の検出によって $p$ は変動します。

したがってこの式は「境界設計が必要である」ことの証明にはなりません。むしろ、この式に依拠すると「検出を強化すればよい」という補助手段側の結論を導いてしまいます。**この式は論拠から外すべきです。**

### 4.2 「通電＝AI」の精密化

実行可能性と実行資源は別の層です。小規模マイコンに大規模モデルは搭載できません。

正確な主張は次の形です。

> AIがどこにでも滞在できる、ではない。
> **作用が成立し得る点の数が、防御側が監視できる点の数を構造的に上回る。**

境界設計の根拠は、遍在性ではなく **非対称性** に置くべきです。この形にすると、主張はむしろ強くなります。

## 5. 開発者はこれを把握しているか

把握の程度は、三層に分けて評価する必要があります。

| 層 | 状態 |
| :-- | :-- |
| 個別事実の認知 | ほぼ達成されています |
| 構造的帰結の受容 | 部分的です。受容すると開発方針の否定になるため抵抗が働きます |
| 実装権限への反映 | ほとんど未達です |

第二層で停止している、というのが最も実態に近い記述です。「知らない」のではなく、「知ったうえで、認知のまま保留されている」状態です。

境界層は性能指標に対して常にマイナスとして計上されます。遅延が増え、機能が減ります。一方、縦軸能力は数値で示せ、資金調達に直結します。この非対称な誘因が、第二層と第三層の間を塞いでいます。

## 6. 「大人の事情」という表現の再検討

意図的な黙認は確かに存在します。しかし、それだけでは説明できない部分のほうが大きいと考えます。

大規模組織では、**誰も全体を見ていない**という状態が常態です。

- 安全チームは必要性を認識しています。しかし製品仕様の決定権を持ちません。
- 製品チームは締切と指標を持ちます。しかし構造的帰結を評価する枠組みを持ちません。
- 経営層は双方の報告を受けます。しかしどちらが構造的に上位かを判定する基準を持ちません。

この状態では、誰一人として見て見ぬふりをしていません。それぞれが担当範囲では誠実に働いています。それでも境界層は実装されません。

これは隠蔽ではなく、**判断主体の不在** です。

| 問題の名前 | 対策 |
| :-- | :-- |
| 見て見ぬふり | 説得・告発・規制 |
| 判断主体の不在 | 外部からの構造的強制 |

意図的黙認であれば、責任の所在が特定でき、規制が機能します。判断主体の不在は、告発先が存在しないため動きません。**後者のほうが、はるかに厄介です。**

## 7. モジュール分割と非分割性質

「隣が何をしているか分からない」状態は、事故ではありません。**そうなるように設計されています。** インターフェースだけを固定し内部を隠蔽することで、大規模並行開発が可能になります。製品が完成するのは、その仕組みが正しく機能している証拠です。

問題は、性質の側にあります。

- **縦軸性能は分割できます。** 各モジュールの性能を積み上げれば、全体の性能になります。
- **横軸性能は分割できません。** 各モジュールが仕様を完全に満たしていても、接続部で境界健全性が成立しない場合があります。

これは努力量の問題ではなく **観測位置の問題** です。各モジュールは、自分のインターフェースの外側を知りません。知らないように作られています。

### 7.1 なぜ未検証のまま完成してしまうのか

完成条件が「全モジュールが仕様を満たすこと」だからです。この条件は非分割性質を含みません。含めようがありません。誰も全体を見ていないためです。

したがって全モジュールが仕様を満たした瞬間、製品は完成します。**未検証の性質については、警告すら出ません。** 検証していないことを検出する仕組みが、どこにも存在しないためです。沈黙のまま出荷されます。

## 8. 導かれる帰結：判定機構の三条件

非分割性質は、分割された組織の内部からは原理的に検証できません。局所検証をいくら積み上げても、大域性質は復元されません。

よって判定機構は、次の三条件を満たす必要があります。

1. **どのモジュールにも属さないこと**
2. **完成判定より前に作用すること**
3. **判定基準を、開発側が変更できないこと**

第三条件が特に重要です。開発側が基準を保持すれば、締切のたびに基準が緩みます。緩んだ事実は記録されません。緩めた担当者も、自分の担当範囲では正しく判断しています。

## 9. NRA-IDE との構造的対応

| 組織構造の問題 | NRA-IDE の設計原則 |
| :-- | :-- |
| 評価対象が評価基準を持つ | LLM に変数定義権限を渡さない |
| 内部からは観測できない性質 | 外部独立実装 |
| 完成後の検査では手遅れ | $R_{op}$ による境界到達前の作用 |
| 緩和の記録が残らない | Append-only ログ（上書き・削除の不提供） |
| 判定不能時の自動継続 | Fail-Closed（無応答は継続許可としない） |

組織構造の問題と、AIアーキテクチャの問題が同じ形をしています。両者は、**観測できない位置に判定者を置いてはならない** という単一原則の、二つの現れです。

## 10. 不能性の明示

以下は、構造的確度をもって決定できません。推測で埋めません。

- 各組織において、意図的黙認と判断主体不在がどの比率で混在しているか。内部資料への接近手段がないためです。
- 分割された組織が、内部の努力のみで非分割性質を検証できるようになるか。これは **不能** と判定します。可能性が低いのではなく、観測位置の制約から構造的に不能です。

外部に判定を置く以外の経路は、現時点で確認できません。

## 11. まとめ

1. 通電が存在する場所には、AIの実行環境が潜在的に存在します。恒常的な登録は不要です。
2. 隔離・出力制御・監査・キルスイッチは、すべて補助的手段です。作用の成立そのものを不成立にしません。
3. 根本手段は、作用が成立し得る空間を先に限定する境界設計のみです。
4. 論拠は、遍在性ではなく **監視点と作用点の非対称性** に置きます。突破確率式は独立仮定に依存するため、論拠から外します。
5. 開発者は事実を認知しています。しかし構造的帰結の受容が実装権限へ届いていません。
6. その主因は隠蔽ではなく、**判断主体の不在** です。対策は説得ではなく、外部からの構造的強制です。
7. 横軸性能は分割できません。よって判定機構は、外部・事前・不可変の三条件を満たす必要があります。
