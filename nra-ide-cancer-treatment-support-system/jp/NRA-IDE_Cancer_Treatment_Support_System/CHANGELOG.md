## Rev 2.0 (2026-07-29)

### 1. 判定式の次元不整合を是正（最重要）

Rev 1.0 の支配方程式は次の形だった。

```
F_resist = (k + Boost) * Δx + η * dv/dt
F_resist > ΔP  =>  判定
```

これには2つの誤りがあった。

* `k` を「弾性係数 [kPa]」＝ヤング率（応力）と定義しながら、ばね定数 [N/m]
  のように変位 `Δx` [μm] を直接乗じていた。**応力に乗じるべきは変位ではなく
  歪み（無次元）である。** 左辺は kPa·μm となり、右辺 kPa と次元が一致しない。
* ダンパー抵抗は速度に比例する `η·v` であり、加速度 `dv/dt` ではない。

この誤りにより、左辺が右辺より桁違いに大きくなり、**幾何エラー以外は
常に BLOCKED（旧 SAFE）に張り付いていた。** 薬剤量も血流圧も判定に
反映されておらず、判定エンジンとして機能していなかった。

Rev 2.0 では応力比較形に改めた。

```
σ_resist = (E + B) · (D − d)/D  +  12·η·v·D / (1000·d²)
σ_resist > ΔP  =>  BLOCKED
```

全項が kPa に揃い、両辺が同次元である。パラメータは増えていない。

**この修正により、Phase 30 の検証ケース7件が期待値どおりに再現された。**
オラクル（`expected_results.json`）の書き換えは不要だった。設計当初の意図は
応力比較であり、実装段階で正規化が落ちたものと思われる。

### 2. 適用範囲の限定と出力語彙の変更

Rev 1.0 は、同一の不等式を正反対の意味で二重に使っていた。

| 出典 | 式 | ラベル |
|:---|:---|:---|
| README（薬剤到達の文脈） | 抵抗 > 投与圧 | **DANGER**（薬が届かない） |
| SafetyMap（細胞封鎖の文脈） | F_resist > F_flow | **SAFE**（細胞が封鎖された） |

「薬剤が組織へ浸透できるか」と「癌細胞が血管から脱出できるか」は支配則の
異なる別問題である（前者は多孔質媒体中の流体輸送）。両者を同じ式・同じ
語彙で扱うことはできない。

Rev 2.0 では **判定対象を「細胞が隙間を通り抜けられるか」に限定** し、
出力語彙を次に変更した。

| 出力 | 意味 |
|:---|:---|
| `BLOCKED` | 抵抗応力が駆動圧を上回り、細胞は通過できない |
| `PASSABLE` | 細胞は変形して通過しうる |

**`SAFE` / `DANGER` は廃止した。** 「細胞が物理的に封鎖されている」ことと
「投薬してよい」ことは別命題であり、一語に畳むと計算結果が治療の許可として
読まれ、Gate Axiom（決定権は医師にある）に反する。

薬剤到達の記述は、README の「背景・動機」の節に降格した。当該モデルは未着手である。

### 3. 判定モデルの一元化

Rev 1.0 では、FPGA の RTL と可視化スクリプトが**別々の式**を実装していた。
医師が見る安全マップと装置の判定が食い違う状態だった。

Rev 2.0 で参照実装 `20_Software_Host/nra_core_model.py` を新設し、RTL の演算を
Q8.8 のビット単位で再現した。判定に関わる4者がこれを唯一の根拠とする。

* FPGA RTL（`10_BioCalibrator_TypeA.v`）
* シミュレーション判定（FPGA 非接続時）
* ジャミングマップの境界描画
* レポートの判定根拠

**ホスト側に独自の近似式を持たせてはならない。**

### 4. FPGA RTL の完成と検証

Rev 1.0 の `10_Top_Module.v` は `// ... (前略)` で始まる断片で、module/endmodule
すら無く、**合成もシミュレーションもできなかった。**

Rev 2.0 で実装し、Icarus Verilog 11.0 で検証した。

| テストベンチ | 結果 |
|:---|:---|
| `10_Testbench_TypeA_Cases.v`（演算コア単体） | 7 / 7 PASS |
| `10_Testbench_Integration.v`（全系, 1 Mbps） | 8 / 8 PASS |
| `10_Testbench_Integration.v`（全系, 115200 bps） | 8 / 8 PASS |

主な変更:

* `10_Top_Module.v` を新規実装。チェックサム不一致時はパケットを破棄し
  **応答しない**（ホストが再送し、3回失敗で `0x05 ERR_COMM`）。誤った判定を
  返すより返さない方が安全側である。
* `10_BioCalibrator_TypeB.v` を未実装スタブに置換（`0x06 ERR_UNSUPPORTED`）。
  理由は §「Type B について」を参照。
* **UART のビット周期に off-by-one があった。** `rx_cnt == BIT_PERIOD` は0から
  数えて `BIT_PERIOD+1` クロック待つため、実効ボーレートが
  `CLK_FREQ/(BIT_PERIOD+1)` になっていた。115200 では誤差 0.115% で顕在化
  しないが、**実機でもボーレートがずれる実在の不具合**である。`BIT_PERIOD - 1`
  に修正した。
* パイプラインを3段から5段へ。全段をリセット同期に変更。Stage 1 で全入力を
  同時にラッチするよう修正（Rev 1.0 は後段で入力ポートを直接読んでおり、
  1クロック遅延した変形量と食い違っていた）。
* エラーコード `0x02`（範囲外）、`0x03`（粘性ゼロ）、`0x04`（オーバーフロー）を実装。

## Rev 1.0 からの訂正

Rev 1.0 の記述のうち、**誤っていたもの**を明示する。Rev 1.0 を入手済みの
場合、これらに依拠していないか確認されたい。

| 箇所 | 誤 | 正 |
|:---|:---|:---|
| 支配方程式 | `(k+B)·Δx` を `ΔP` と比較 | 歪み `(D−d)/D` へ正規化し応力で比較 |
| 支配方程式 | ダンパー項が `η·dv/dt` | `η·v`（速度に比例） |
| SAFE/DANGER | 同一式に反対の意味のラベル | `BLOCKED`/`PASSABLE` に統一 |
| Q8.8 対応表 | 変形速度 200.0 = `0x3200` | `0x3200` は 50.0。200.0 は `0xC800` |
| 応答プロトコル | 3バイト = Status / Error / Checksum | Header / `(Error<<1)\|Jammed` / Checksum |
| エラーコード | `0x02` = 負の物理量 | Q8.8 は符号なしで発生不能。`0x02` は範囲外に再定義 |
| エラーコード | `0x04` を通信エラーに流用 | `0x04` はオーバーフロー。通信エラーは `0x05` |
| 統合テストベンチ | チェックサム `0x00` を直書き | 当該ペイロードの XOR は `0x10` |
| Type A / Type B | 細胞の硬さによる分類（検証プロトコル） | 細胞数の軸（単一細胞 / 集団） |
| 処方算出例 | 硬化分 +1.5 kPa（検証プロトコル §4） | 同条件で +0.60 kPa |
| レポート雛形 | 推奨 Boost +3.00 kPa | 同条件で +0.25 kPa |
| テストデータ | 「25種類の網羅的テストケース」 | 7件 |
| パイプライン | 3段（RTL）/ 5段（文書） | 5段に統一 |

## Type B について

Type B（細胞集団のスクラム効果）は **Rev 2.0 で未実装スタブとした。**
`0x06 ERR_UNSUPPORTED` を返し、判定を行わない。理由は3つある。

1. **モデルが未検証である。** `PHASE_2 §3` の √N 則は現象論であり、増幅係数 α も
   `60_Research` の文献では裏付けられていない。検証プロトコルも Type A のみを
   対象としている。
2. **入力が届かない。** 現行の14バイトプロトコルは `cell_count` を搬送しない。
3. **未検証の物理式を回路にすると、判定が出てしまう。** 出た判定は読まれる。
   根拠のない数値を出すより、出さない方が安全側である。

実装する場合は `PHASE_2 §3` の検証を先に済ませ、`nra_core_model.py` の
`MODEL_VERSION` と `VALIDATION_STATUS` を必ず更新すること。
