## アブストラクト



自動運転システムは、複雑な環境を解釈するためにディープニューラルネットワークにますます依存しています。  

しかし、ニューラルネットワークは本質的に不確実性とハルシネーションのリスクを抱えており、特にグレア、雨、センサ不一致などの劣化条件下で顕著です。  



本論文では、**NRA-IDEフレームワーク**に基づく**境界中心安全アーキテクチャ**を提案します。このアーキテクチャでは、AI決定システムを内部的に修正するのではなく、**決定論的な安全ゲート**によって外部から制約します。  



提案する安全監視は3層構造です：  

1. 必須センサ境界  

2. 物理リスクメトリクス  

3. IDE再構成ゲート  



この構造は**AIの知能と物理的安全検証を分離**し、AIが自由に動作できる一方で、不安全な動作が車両制御システムに到達するのを防ぎます。

## 1. はじめに



現代の自動運転システムは、ディープラーニング駆動の知覚・計画アルゴリズムに大きく依存しています。  

これらの手法は高い性能を発揮しますが、以下の3つの根本的問題を抱えています：  

1. センサ不整合  

2. モデルハルシネーション  

3. 計算的不確実性  



従来のアプローチは、これらの問題をAIモデルの改善によって解決しようとします。  

しかし、知能の向上は安全を保証するものではありません。  



本論文では異なるアプローチを提案します：  

**AIを完璧にするのではなく、外部の安全境界によってAIの振る舞いを制約する**  



この概念を**NRA-IDE境界アーキテクチャ**として実装します。



---



## 2. 最小センサ境界（Minimum Sensor Boundary）



自動運転には最小限のセンシングシステムが必要です。  

本論文では以下の**必須境界セット**を定義します：  



- カメラ  

- レーダー  

- IMU / ホイールオドメトリ  



これらのセンサは**相互に置き換え不可能**です。  

観測原理が根本的に異なるためです。  



```

カメラ ≠ レーダー ≠ IMU

```



したがって、これらを単一の融合された真実値に強制的に統合すると、重大な不整合が隠されてしまいます。  

提案アーキテクチャでは、**不一致そのものを安全情報**として扱います。



---



## 3. 物理リスクメトリクス



センサ境界に加えて、以下の5つの物理量を独立に監視します：  



- 前方障害物距離  

- 相対速度  

- ヨーレート誤差  

- レーン信頼度  

- 停止余裕時間  



これらの値は**直接的な物理的安全条件**を表します。  



リスク推定の例：  

```python

metric_risk = max(

    r_distance,

    r_relative_velocity,

    r_yaw_error,

    r_lane_confidence,

    r_stop_margin

)

```



これらのメトリクスは、AI推論とは独立した物理ベースの安全層を提供します。



---



## 4. IDE再構成層



NRA-IDEフレームワークは、システムの安全性を以下の3つの内部変数で評価します：  



- `R_now`：瞬間的な境界偏差  

- `R_short`：短期再構成状態  

- `D_long`：長期劣化指標  



複合リスクは以下のように計算されます：  

```python

CompositeRisk = max(

    R_now,

    R_short * 0.92 + D_long * 0.45,

    metric_risk

)

```



これにより、**瞬間的な失敗検知**と**徐々に進行する劣化の監視**の両方が可能になります。



---



## 5. 決定ロジック



システムは以下の3つの制御状態を出力します：  



- **PASS**：通常動作  

- **DAMP**：出力減衰  

- **FALLBACK**：安全停止手順  



この決定はAIプランナーから独立しています。



---



## 6. 危険状態可視化



別途、安全インジケータが視覚的な状態フィードバックを提供します：  



- **SAFE**  

- **WARNING**  

- **DANGER**  



これらの状態は車両を直接制御しませんが、状況認識と診断に役立ちます。



---



## 7. 外部安全境界の原則



主要な設計ルールは**非侵入型統合**です。  

IDEシステムはAIアルゴリズムの内部に埋め込まれません。  

代わりに**外部検証層**として配置されます。  



```

AIプランナー

      ↓

IDE検証

      ↓

最終安全ゲート

```



したがってIDEは、確率論的AIシステムに対する**決定論的な安全ケージ**として機能します。

## 9. 議論



提案アーキテクチャは、従来のセンサ融合システムとは異なります。  



従来のアプローチ：  

```

センサ融合 → AI → 制御

```



提案アーキテクチャ：  

```

センサ

   ↓

AIプランナー

   ↓

IDE境界検証

   ↓

車両制御

```



これにより**AIの知能と安全検証が分離**され、維持されます。

本論文では、NRA-IDEフレームワークを用いた自動運転車両のための境界中心安全アーキテクチャを導入しました。
