## 1. B.1-8（j・Aとωの対応づけ）への応答

### 1.1 「都度」は曖昧か

「都度」には二つの意味があり、どちらを指すかで答えが変わる。

| 意味 | 内容 | 曖昧か |
|---|---|---|
| 事後の都度 | 評価が終わった後で、その場ごとに「これはωのこの部分に当たる」と判断する | **曖昧である**。判断の根拠が評価の外にあり、結果を見てから決めることになるので、方法論的逆導出（結論から理論を組み立てること）に近づく |
| 評価前の都度宣言 | 評価ごとに、評価宣言𝒟の中で「対応づけの有無と方法」を**計算を始める前に**固定する | **曖昧ではない**。一つひとつの評価の中では境界が閉じており、評価と評価の間で方法が異なることを「広範」として許すだけである |

利用者の言う「拡大解釈というより広範の定義」は、後者の形にすれば構造として書ける。適用される範囲が広いこと自体は曖昧さではない。**範囲の境界を評価ごとに宣言しているかどうか**が、曖昧かどうかを分ける（総合案§1「不明は構造化して宣言し、境界を消さない」）。

### 1.2 提起 C-1

| 案 | 内容 |
|---|---|
| (a) 保留のまま | 一般規則も、宣言の枠も置かない。承認済みの推奨どおり |
| (b) **二層に分ける**（推奨） | **一般規則は保留**とする（事例研究で手法が見えるまで置かない）。ただし当面の扱いとして、評価宣言𝒟に**任意要素**「ωとの対応づけの有無と方法」を置く。宣言しない場合は「対応づけなし」とする |

**推奨理由**：(a)のままにすると、実際に対応づけが必要になった評価で「事後の都度」が入り込む余地が残る。(b)は、研究が進むまで一般規則を作らないという利用者の判断を保ったまま、個々の評価では境界を閉じられる。任意要素なので、B.1-5で承認した「必須要素は正典が既に要求しているものに限る」とも矛盾しない。

$\sigma$ は、観測値 $x_n$ を、基準状態から宣言した破断方向へ測ったズレへ移す規則である。領域の支配方程式または実証された変換規則がここに入る。

$\sigma$ maps an observation $x_n$ to the deviation measured from the reference state in the declared rupture direction. The governing equations or validated transformation rules of the domain enter here.

## 0.5.3 分解 / Decomposition

$$
\delta_n=q_n+p_n,\qquad q_n\ge0,\quad p_n\ge0
$$

- $q_n$ ：可逆成分。作用を除けば0へ戻る / reversible component; returns to 0 when the action is removed
- $p_n$ ：不可逆成分（残留ズレ）。補修事象がない限り減らない / irreversible component (residual deviation); does not decrease without a repair event

分解規則 $\Lambda$ は、観測された一つの変化を、作用（ $q$ を生む）、残留ズレの増分 $\Delta p_n\ge0$ 、劣化度の増分 $\Delta\lambda_n\ge0$ （0.5.4）の**ちょうど一つ**に計上する。同じ変化を二つ以上に計上しない。

The decomposition rule $\Lambda$ counts each observed change in **exactly one** of: the action (which produces $q$), the increment of residual deviation $\Delta p_n\ge0$, or the increment of degradation $\Delta\lambda_n\ge0$ (0.5.4). The same change is not counted twice.

## 0.5.4 厚み / Thickness

$$
\tau_n=(1-\lambda_n)\,\tau_0,\qquad 0\le\lambda_n<1
$$

| 層 / Layer | 記号 / Symbol | 性質 / Property | 使う場所 / Used in |
|---|---|---|---|
| 宣言厚み / declared thickness | $\tau_0$ | 評価宣言で固定 / fixed by the declaration | 各評価の出発点 / start of each evaluation |
| 実効厚み / effective thickness | $\tau_n$ | 補修事象がない限り非増加 / non-increasing without repair | 一次式 / Primary Formula |
| 側別有効ゲート幅 / side-specific effective gate widths | $\tau_{\mathrm{upper}}(n)$、 $\tau_{\mathrm{lower}}(n)$ | 増減してよい / may increase or decrease | 二次式（§4.4）だけ / Secondary Formula (§4.4) only |

$\lambda_n$ は劣化度であり、外生的な補修事象がない限り減らない。 $\lambda_n=1$ のとき $\tau_n=0$ であり、§1のとおり記述領域外とする。動的な $\tau$ を用いる実装は、その増減がどの層に属するかを明示する。

$\lambda_n$ is the degree of degradation and does not decrease without an exogenous repair event. When $\lambda_n=1$, $\tau_n=0$, which is outside the description domain as stated in §1. An implementation using a dynamic $\tau$ states which layer each increase or decrease belongs to.

## 0.5.5 一次式への到達 / Arrival at the Primary Formula

$$
R_n=\frac{\delta_n}{\tau_n}=\frac{q_n+p_n}{(1-\lambda_n)\,\tau_0}
$$

分子は構造へどれだけ入り込んだか、分母は構造の器が今どれだけ残っているかを表す。

The numerator expresses how far the structure has been penetrated; the denominator expresses how much of the structure's capacity currently remains.

### 16.3 cascade-failure-prevention の実態（2026-09-28時点）

- `gate/han_gate_service.py`：R = r_raw × τ_dynamic（掛け算。コメント自身が「正典のR=δ/τをそのまま実装したものではない」と書く）。r_raw＝retry/10 × queue/500 × dep_timeout/5。τ_dynamic＝τ_base×(1+EMA(r_raw))。
- τ_base は**リクエストごとに呼び出し側が渡す**（`data.get("tau")`）。
- サーバー台数・容量の概念はない。正規化の定数（10・500・5）は「通常運用の上限目安」として固定されており、暗に台数に依存している。
- SILENCEはHOLD_MS（2秒）後に自動で解除される。テレメトリが欠けるとR＝999を返す。

これらは正典との不一致として派生作業で扱う（本件の範囲外）。以下は、正典に沿って作り直す場合の当てはめである。

### 16.4 サーバーの増設・減少への当てはめ

評価対象をサービス群（スコープ＝service・route・cluster）、各サーバーを構造要素とする。

| 事例 | 本書の枠組みでの扱い | 当てはまるか |
|---|---|---|
| サーバーを1台増設 | 構造要素の付加。新サーバーの厚み（処理能力）は、加えた時点のCause-Side測定（負荷試験・実測スループット等）で定める。全体の厚みは宣言済みの合成規則 $\Gamma$ で求める（同一構成のレプリカでも、調整の負担があるため単純な和とは限らない）。既存サーバーの劣化（メモリリーク、ディスク摩耗等）は増設で戻らない | **当てはまる** |
| Rが高いのでオートスケーラーが増設する | 評価出力を事前固定された物理制御の指令に使うことはAXIOMS §14で許される。書き換え先は対象（サーバー群）であり、計器ではない。ただし、実機を足さずにゲートのτの値だけを上げるのは、計器の自己調整（逆導出B）である。現行実装のようにτを呼び出し側が毎回渡せる構造は、この区別ができない | 当てはまる（区別の規則が要る） |
| サーバーが1台故障で落ちる | 要素の破断（ $\lambda^{[e]}=1$ 、厚み0）。全体の評価は続く（小さな破断点）。残りのサーバーへ移る負荷は、作用 $a$ の増加としてズレ側に現れる（第3部段7 C2） | **当てはまる** |
| 計画的に1台外す（縮退・撤去） | 壊れていない要素を外す分類がない（S2） | **穴あり** → G1 |
| 保守で一時的に外し、後で戻す | 「除去と再付加」とみるか「一時的な厚みの減少」とみるかが決まっていない（S2・S3） | **穴あり** → G1・G2 |
| 新サーバーの暖機（キャッシュが温まるまで性能が低い） | 一時的な厚みの減少（S3） | **穴あり** → G2 |
| 全台が同時に停止 | τ=0でOUT_OF_DESCRIPTION_DOMAIN（S4） | 要判断 → G3 |
| 台数が変わると正規化定数（retry/10等）の意味が変わる | 射影規則 $\sigma$ が台数に依存するなら、その依存を評価宣言で事前に固定する。黙って定数を変えるのは宣言の変更に当たる | 当てはまる（宣言の要件として明記が要る） |

### 16.5 確認事項

| # | 内容 | 推奨 |
|---|---|---|
| G1 | **健全な要素を外す操作の正規語**。付加と対になる語が要る | 「構造要素の除去」を正規語とする。除去は劣化ではないので $\lambda$ に計上せず、その要素を合成規則 $\Gamma$ の引数から外す（厚みは減る。§7に反しない）。除去は事象として記録する。外した要素を戻す場合は再び「付加」とし、その時点のCause-Side測定で厚みを定める（外していた間の劣化も測定に含まれる）。9分類の「取り替え」は「旧要素の除去（壊れていれば破断）と新要素の付加」に改める |
| G2 | **一時的な厚みの減少を一次式でどう数えるか**（§13の問い1の続き。未回答） | ズレの側に数える（ $R=(\delta+m)/\tau_n$ ）。破断点は厚みの側で差し引いた場合と同じで、破断の手前ではRが同じか大きく出る（安全側、命題1と同じ形）。暖機中の新サーバー・保守中のサーバーはこれに当たる。保守で外す場合は、G1の除去・再付加とするか、 $m$ とするかを評価宣言で決めておく |
| G3 | **全要素が同時に失われた場合**の分類 | 正典どおりOUT_OF_DESCRIPTION_DOMAINとし、Rを無限大へ置き換えない。そのうえで、評価宣言の破断様式に「全台停止（サービス停止）」のような**直接観測できる破断の条件**を入れておき、それが観測されたことを構造証言に記録する（AXIOMS §11.1の対象別状態の分離）。正典の変更は要しない |
