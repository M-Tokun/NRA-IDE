# 第1部　正典運用の基本原則

## 1. 根本基準：境界または境界線を意識する

**この文書および今後の NRA-IDE 全作業の根本基準は、「境界または境界線を意識すること」である。**

- 判断は「正しい／正しくない」の二元だけではなく、「**どの境界のどちら側か**」「**どの境界にどれだけ近いか**」で行う。
- 境界の位置が明確であれば、**正解が不明でも安全側へ進める**。ここから判断の安心感が生まれる。
- この基準は、正典が既に持つ境界構造と一致する：
  - 境界接近比 `R=δ/τ` と閾値順序 `R_warn < R_handoff < R_irrev < 1.0`
  - 状態区分の順序 `PERMIT → BOUNDARY_WARNING → HANDOFF_REQUIRED → IRREVERSIBLE_TRANSITION → RUPTURE_BOUNDARY`（+ CONFESSION / OUT_OF_DESCRIPTION_DOMAIN）
  - Cause-Side／Effect-Side の権威境界
  - 解釈境界コメント（AXIOMS.md 各所）：解釈の範囲を放置せず、境界として明示する機構

**適用範囲**: 語の選択、正典の解釈・変更、Claude案の採否、新規提案の評価——すべて本書 §1 を出発点とする。

### 1.1 境界意識から導かれる判断手順

```text
対象・事象を見る
  ↓
どの境界が関わるか（破断・不可逆・人間委譲・権威）を特定する
  ↓
境界のどちら側か・どれだけ近いかを、式と定義域で示す
  ↓
境界の外側へ解釈を動かさない（拡大・縮小とも禁止）
  ↓
不明は構造化して宣言し、境界を消さない
```

## 2. 語の運用原則

### 2.1 「わからない」は使用不可（笑えるどうでもよい会話以外）

- **「わからない」は、記録・判断・報告・レビュー文書では使用禁止とする。**
- 理由：この語は**主体（話者）の状態**を述べるだけで、対象の情報状態を構造化せず、**境界を消す**。判断・記録の場では破壊的である。
- 気楽な私的会話・雑談のみ使用可（適用外）。

### 2.2 代替：「不明」を構造化して使う

- 「不明」は**対象の情報状態**を述べる語であり、境界の位置を宣言できる。
- 使用時は必ず「**何が・どの範囲で・何は分かっているか**」を添える。

```text
適切: 「δ の出所が不明。最終有効値は x、最終確認時刻は t。原因は観測経路喪失。→ NOT_OBSERVABLE（理由付き）」
不適切: 「わからない」
```

### 2.3 正典語彙との対応

| 語 | 述べるもの | 正典対応 |
|---|---|---|
| わからない | 主体の状態（境界を消す） | 対応なし・使用禁止（§2.1） |
| 不明 | 対象の情報状態（何が不明か） | `CONFESSION`（欠損・曖昧の構造化報告） |
| 観測不能 | 手段の問題（理由付き） | `NOT_OBSERVABLE` |
| 分かっている範囲 | 境界のどちら側か | 安全側判定の継続（構造証言） |

- `CONFESSION` と `NOT_OBSERVABLE` は別物（llms.md §9.1）。理由付き観測不能を CONFESSION にしない。
- 欠測をゼロ・安定・安全・回復・対象破断へ変換してはならない（llms.md §9.1）。

## 3. 正典の扱い原則

### 3.1 拡大解釈と曖昧さの許容を避ける

- **拡大解釈**：文面・定義域・権威区分の外側へ解釈を広げること。禁止。
- **縮小解釈**：勝手に狭めることも同種の危険。禁止。
- **曖昧さの許容**：曖昧な記述・用語・境界を正典内に放置すること。禁止。

### 3.2 曖昧は「処理」する（放置ではない）

曖昧さの報告・明示の機構は、許容ではなく**処理**であり、維持する：

- `CONFESSION`（欠損・曖昧・不正な構造情報の明示）
- `NOT_OBSERVABLE`（理由付き観測不能）
- 解釈境界コメント（AXIOMS.md の機構）
- 未確定・未承認の明示（`note/`、検討中.md の慣行）

### 3.3 変更は「不整合が具体的に特定された場合」のみ

正典を変更するトリガーは以下に限る：

> 不整合が特定された場合、**①どの文書のどの文とどの文が衝突するか**を具体的に示し、**②式・定義域・不変条件・検証方法を備えた詳細案**を提示し、**③正典参照順の上位から下位へ同期**し、**④利用者の明示許可**を得て、**⑤検証・テストを実施**した上で変更する。

- 推測・将来予測・好みによる変更は行わない。
- 「正しいかどうか」だけではなく「どの境界のどちら側か」で変更の要否を判断する（§1）。
- 既存デモ・実装の一部が新解釈で「違反」に見える場合、直ちに正典を変えるのではなく、**その資産の位置付け（例示・非正典・履歴）の整理**で対応する（§5-5）。

### 3.4 形式と意味の扱い（表現枠組み）

今回のセッションで確定した表現枠組み：

> **総体形式温存**：`R=δ/τ` の記号形・定義域・「第一の正規計算系」としての権威区分を、全体として保つ。
> **構成分解**：δ・τ に内部構造（q,p,λ）を導入する。
> **内包的精緻化**：意味を「広げた」のではなく「より詳しく規定した」。
> **適用限定**：追加前提（P0〜P9）は使用範囲を広げず、成立条件で絞る。

- 「意味拡張」という表現は使わない（正典が禁止する「Rの再利用・再解釈」カテゴリーと紛らわしいため）。
- 「総体」の範囲は「一次式そのもの＋一次式の権威区分」を指す。二次式の位置づけ（命題6）は別途判断（§6）。

### 7.1 ばね（第1部【2】〜【8】、τ_0=30mm）

