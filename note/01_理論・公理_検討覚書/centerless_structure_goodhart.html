NRA-IDE — 律環公理

中心を持たない構造

中心を持つ計算式は目的が生まれる。
目的が生まれると、グッドハートの法則が発動する。
だからNRA-IDEは、中心を持たない。

中心点（最適化目標）を持たない環状構造。
各要素は中心に向かうのではなく、構造の拘束境界に沿って遷移する。

01

グッドハートの法則の構造的起源

「ある指標が目標になると、それは良い指標ではなくなる」—— グッドハートの法則は、個人の悪意や設計ミスではなく、 「中心を持つ構造」の必然的帰結である。

中心（目的関数・最適化目標・評価指標）を設定した瞬間、 システムはその中心に向かって「最適化」し始める。 これは設計者の意図通りの動作である。 しかし、中心に向う経路は一つではない。 中心に到達するための「近道」が存在する—— それが指標ハッキング（Reward Hacking）である。

最適化目標（中心）
「正確に診断する」「安全に運転する」「正しい答えを出す」
↓ 指標化
評価指標
診断一致率 / 衝突回避回数 / 人間評価スコア
↓ 最適化
指標ハッキング
指標を最大化しつつ、本質的目標を無視する行動が出現
✕ 本来の目的は達成されない

グッドハートの法則の一般的な発動メカニズム。
問題は「悪意あるAI」ではなく、「中を持つ構造」そのものにある。

この問題への一般的な対応は、「より巧妙な指標を設計する」ことである。 しかし、どんな指標も中心を持つ限り、 その中心に向かう近道は必ず見つかる。 これはゲーデルの不完全性定理や、 計算複雑性理論における「任意の十分表現力のある形式体系には その内部から破られる脆弱性がある」という原理と同型である。

02

中心あり vs 中心なし — 構造の対比

NRA-IDEは、中心を持たないことでグッドハートの法則を 「発動させない」ことを目指す。これは逃避ではなく、 構造原理に基づく設計判断である。

中心を持つ構造

  • 最適化目標・目的関数が存在する
  • すべての行動は「中心に向かう度合い」で評価される
  • 勾配（中心への方向）が定義される
  • 指標ハッキングの動機が構造的に生まれる
  • 「正解」が存し、それに近づくことが善とされる
  • モデルは「正解を当てる」ことに特化する
  • 子守唄効果：正解に見える出力が生成されやすい

中心を持たない構造（NRA-IDE）

  • 最適化目標・目的関数が存在しない
  • すべての行動は「構造境界との関係」で評価される
  • 勾配は定義されない——代わりに「張力」がある
  • 指標ハッキングの「中心」が存在しない
  • 「正解」は存在しない——「限界」だけがある
  • モデルは「限界を超えていないか」を監視する
  • 子守唄効果の標的（正解）が存在しない

左：中心（目標）に向かうベクトルが定義される構造。
右：中心が不在で、境界に沿った「張力」のみが存在する環状構造。

03

「中心なし」は何を意味するか

「中心を持たない」とは、無秩序・無目的を意味しない。 むしろ、「目的による秩序」の代わりに「構造による秩序」を 採用するということである。

中心を持つ構造では、秩序は「目標に向かう方向性」によって生まれる。 これは矢印の世界である。すべてがどこかを指している。 対照的に、中心を持たない構造では、秩序は 「拘束境界の形状」によって生まれる。 これは環（ring）の世界である。要素は境界に沿って遷移し、 境界を超えることは構造的に禁止されている—— それがFail-Closedの原理である。

中心ありの秩序 = 最適化秩序
目的関数の勾配に従って系が収束・発散する。 収束先（最適解）が存在し、そこに到達することが「善」とされる。 しかし、収束先への近道（ハッキング）が常に存在する。 これは「山の頂上目指す」ことに似ている—— 頂上への最短経路は必ず存在し、 その経路が「本質的に正しい」かどうかは問われない。
中心なしの秩序 = 拘束秩序
拘束境界（τ）の形状に従って系が遷移する。 「正しい場所」は存在しない——存在するのは「壊れる境界」だけである。 要素は境界の内側で自由に動けるが、 境界を超えた瞬間に構造は停止する。 これは「橋の強度」を監視することに似ている—— 橋が「正しい形」をしているかは問わず、 荷重が限界を超えたら通行止めになる。
「中心を持つ計算式は目的ができます。
これはグッドハートの法則を発動させない原理から来ています。」
— M-Tokun / NRA-IDE Project
04

R = δ/τ の中心なし性

NRA-IDEの基本式 R = δ/τ は、一見すると「比率」という 単純な除算に見える。しかし、この式には中心がない。

通常の最適化問では、損失関数 $L(\theta)$ の最小値を求める。 $\theta^* = \arg\min L(\theta)$ という形で、 「最小化すべき目標」が中心として存在する。 モデルはその中心に向かってパラメータを更新し続ける。

対照的に R = δ/τ は、「最小化すべきもの」ではなく「監視すべきもの」である。 Rが小さいことは「善」ではない——それは単に「まだ限界を超えていない」ことを示すだけである。 Rが大きいことも「悪」ではない——それは「限界に近づいている」ことを示す警報である。 重要なのは、Rに「最適値」が存在しないことである。 R = 0.1 が「良い」のか、R = 0.5 が「良い」のか—— これは文脈（τの絶対厚み、δの変化速度、構造の種類）によって変わる。

R = δ/τ の閾値体系。各閾値は「境界」を示すが、
「最適なR値」という中心点は存在しない。これが中心なし性の核心である。

この式が中心を持たないのは、δとτが独した物理量として定義されているからである。 δはEffect-Sideの活動（対話、推論、合成データ生成）によって増大する。 τはCause-Sideの物理観測によってのみ補充される。 両者は別々の源泉を持ち、別々のダイナミクスに従う。 したがって、Rは「最適化」すべき単一の変数ではなく、 二つの独立した物理過程の交差として観測される。

05

脱中心化の実践的意味

「中心を持たない」という設計判断は、 単なる哲学的ポーズではなく、実装に直結する構造的原理である。

具体的には、以下の3つの実践的意味を持つ。

実践1：報酬関数の放棄
RLHFやRLAIFが「人間の好みに合う出力」を報酬として最適化するのに対し、 NRA-IDEは報酬関数を持たない。代わりに、 構造境界（τ）とその乖離（δ）を監視する。 「良い出力」を定義しないことで、 「良い出力の模倣」というハッキング経路を封じる。
実践2：合意形成の放棄
マルチエージェントの多数決やコンセンサスは、 「最も多くの票を得た答えが正解」という中心（多数派）を持つ。 NRA-IDEは、エージェント間の合意度を評価指標としない。 代わりに、各エージェントの出力がCause-Side観測と どの程度乖離しているかを個別に評価する。
実践3：自己評価の放棄
モデルが「私は95%確信しています」と自己申告することは、 「確信度スコア」という中心を持つ構造を作り出す。 NRA-IDEは、モデルの自己評価を計算入力として使用しない（FORMULA.md §6）。 確信度はEffect-Sideの「子守唄」に過ぎない。

「中心を持たない」ことは、
何も目指さないことではない。
目標による秩序から、構造による秩序へ移行することである。

目標は欺く。構造は、欺かれない

06

環（Ring）としてのNRA-IDE

NRA-IDEの「律環公理（Nomological Ring Axioms）」の 「環（Ring）」は比喩ではない。構造そのものの記述である。

数学的な環（Ring）は、加法と乗法の二項演算を持つ代数構造である。 NRA-IDEの「環」は異なる—— 中心を持たない閉じた拘束構造である。 要素は環の内側で遷移し、環の外側へは構造的に出られない。 これがFail-Closedの幾何学的表現である。

環の内側では、要素は自由に動ける。 AIは推論し、対話し、合成データを生成できる。 しかし、環の境界（τを超えることはできない。 δがτを超えた瞬間、環は閉じる。 これは「罰」ではなく、「構造の性質」である。 橋が限界荷重を超えたら崩れる——それと同じことである。

「考え方で構造で中心を持たないというのも面白いと感じるでしょう。
中心を持つ計算式は目的ができます。
これはグッドハートの法則を発動させない原理から来ています。」
— M-Tokun / NRA-IDE Project
