# 可能性探索における記録・再検索・更新の方法

- 作成日時：2026-10-10 19:04（JST）
- 位置付け：可能性の追求探索を継続するための運用設計案
- 対象：対話、着想、仮説、試行錯誤、未解決の可能性
- 成熟度：暫定。運用とともに変更できる。

## 1. 基本思想

- 先に目的・達成指標を固定する「最適化」ではなく、何が成立し得るかを探る「可能性の追求探索」を対象にする。
- 探索では試行錯誤を省かない。会話が100行になり、記録が1行になることもある。
- **記録は会話の要点・要約ではない。** 会話中の文章を抜粋・短縮するのではなく、試行錯誤によって形成・更新された**現在の思考状態**を新しく記述する。
- 探索に必要だった文字列と、後の探索に必要な記録は一致しなくてよい。保存する必要のない経過は残さない。
- ただし、短期的なコスト削減を理由に、将来の検討につながる可能性まで無条件に消さない。
- 何でも残す方式は採らない。記憶量の増加そのものが探索の混乱を招くためである。

## 2. 探索を有限に保つ境界

- 目的への到達度・単一スコアを境界指標にはしない。探索に固定の終着点を要求しないためである。
- それでも、探索を無期限に拡散させないため、**今この論点をさらに掘るか**を判定する。
- 検討対象：現在の主軸との接続、未解決条件、得られた新しい着想、必要な検証、探索の負荷、情報の不足。
- 同じ疑問の反復、新しい成立条件の発見がない状態、証拠・手法待ちの状態では「保留」を選べる。
- 「今は扱わない」と「成立しない」は別の判断として記録する。
- 探索の保留は可能性の否定ではなく、**計算や考察を一時的に止める管理上の判断**とする。

## 3. 記録の取捨選択

| 判断 | 意味 | 記録の扱い |
|---|---|---|
| 継続 | 現在の主軸に関係し、さらに考察すべき | 現在の問い・成立条件・次の試行を残す |
| 保留 | 有用性が未確定、または今掘る必要がない | 最小限の着想・保留理由・再検討のキッカケを残す |
| 棄却 | 必須前提との矛盾など、不成立の根拠がある | 不成立の根拠と対象範囲だけ残す |
| 対象外 | 現在の探索との接続が確認できない | 原則保存しない。必要なら参照先のみ残す |
| 統合 | 別の記録に思考内容を引き継いだ | 旧IDから統合先IDへの参照を残す |

- 保留の優先順位は、真偽や優劣の点数ではなく**再検討する順序**（例：P1／P2／P3）として用いる。
- すべての可能性を完全に評価する必要はない。判断不能は「判断不能」のまま扱う。

## 4. 保存する最小単位

**原則：1つの独立した探索論点につき1つのMD記録。** 自然文を基本に、短い箇条書きで記す。

保存する項目は次の範囲に絞る。

1. 固有IDと短い表題：名称の変化に耐える参照先。
2. 現在の着想：今どのように考えているか。
3. 成立・未成立・不明の境界：未検証を事実扱いしない。
4. 継続／保留／棄却等の判断と、その理由。
5. 再検討のキッカケ：検索語だけでなく「何が起きれば再び考えるか」。
6. 関連ID：後から別の探索経路で発見するための接続。

- 会話の全ログ、思考途中の反復、装飾的な図、大量の類似文章は標準の保存対象としない。
- 図を使うなら、後で関係を思い出すための簡単な関係図に留める。
- 元の文章を完全復元できることは保証しない。残した記録から何を再開できるかを重視する。

## 5. 記録と検索のキッカケを分離する

- **MD本文**：当時の考察から到達した判断・根拠・未解決条件を保存する。
- **検索のキッカケ**：別名、関連語、タグ、関連ID、再検討条件など。現在の考え方の変化に応じて更新可能にする。
- 過去の判断を、新しい解釈で黙って上書きしない。必要な変更は履歴として短く残す。
- キッカケは増やすだけではない。関連性のない語は整理し、必要なら旧名称からの到達経路だけ維持する。
- 索引更新のために全記録を毎回再読解しない。関係が見つかった記録から局所的に更新する。

**区別すべきもの**

- 事実・観測／仮説・推定／未検証／不成立
- 当時の判断／現在の判断
- 保存する本文／到達に使う検索語
- 保留の優先順位／成立可能性の評価

## 6. MDを正典としたDB的管理

- 一次記録はプレーンテキストの `Markdown + YAML front matter` とする。
- YAMLのキー名、状態値、ID規則だけを固定する。本文の自由な自然文は固定しない。
- XMLは必要ならMDから**自動生成する索引・交換形式**とし、MDとXMLを別々に手修正する二重管理は避ける。
- 本格的なDBが必要になれば、MDを一次資料として索引をSQLite等に生成できる。導入を前提条件にはしない。
- grep/rgで検索できるよう、文字列表記のゆらぎは `aliases` や `triggers` で吸収する。

### 記録例（概念実証）

```markdown
---
id: EXP-00042
status: hold
priority: P2
title: 双曲空間による情報配置
triggers: [双曲空間, 情報の隣接化, 局所探索]
aliases: [ポアンカレ空間, 幾何学的探索]
related: [EXP-00018, EXP-00031]
updated: 2026-10-10
---

# EXP-00042 双曲空間による情報配置

- 現在の着想：関連情報を近傍に置く表現が、一部の探索に役立つ可能性。
- 成立が確認されたこと：未検証。
- 未解決：近さの定義が用途や評価軸によって変わる。
- 判断：保留。表現上の利点と更新負荷を比較する材料が不足。
- 再検討のキッカケ：異なる評価軸での実験結果が得られたとき。
- 関連：EXP-00018、EXP-00031。

## 更新履歴
- 2026-10-10：初期記録。新しい意味付け・索引変更はここに短く追記する。
```

この例は**記録形式の例**であり、双曲空間の優位性を実証したものではない。

### 検索例

```bash
# file: search_examples_20261010-1904.sh | 2026-10-10 19:04 JST
rg -n '情報の隣接化|ポアンカレ空間' records/
rg -l 'status: hold' records/
rg -n 'EXP-00042' records/
```

※ 文字列検索には限界がある。想定外の同義語まで自動で拾える保証はないため、キッカケの更新を運用に含める。

## 7. 実際の運用サイクル

1. **探索する**：会話や試行錯誤では文章量を制限しない。
2. **考え方を確かめる**：現在成立している判断、矛盾、未解決を切り分ける。
3. **記録を形成する**：会話の短縮版ではなく、新たに到達した思考状態として記す。
4. **境界判断を行う**：継続・保留・棄却・対象外・統合を選ぶ。
5. **キッカケを付ける**：将来検索し、再考できる最低限の言葉・条件・関連IDを残す。
6. **考え方の更新時に接続を直す**：本文の過去の意味を守りつつ、索引・関連性・現在の判断を更新する。

## 8. 保存容量・コストの扱い

- 保存対象は静的な文字・簡素な図・索引であり、保存した記録自体が計算し続ける設計ではない。
- テキスト中心なら比較的小さな容量で多数の記録を扱える可能性がある。ただし「必ず数GB以内」という上限は件数・履歴・図の量が未確定のため保証しない。
- 保存の費用と、後から探索・再評価する計算費用は別に扱う。
- コスト削減は探索可能性を不必要に破壊しない範囲で検討する。

## 9. 現時点の設計原則

> **目的を先に固定せず、可能性を探索する。探索そのものには境界を置き、到達した思考状態を簡潔に保存する。将来の再探索のキッカケは、考え方の変化に合わせて更新する。**

未確定：保留順位の判断方法、索引の自動更新条件、記録分割の粒度、再検討の負荷と見落とし率。これらは実際の利用によって検討する。
