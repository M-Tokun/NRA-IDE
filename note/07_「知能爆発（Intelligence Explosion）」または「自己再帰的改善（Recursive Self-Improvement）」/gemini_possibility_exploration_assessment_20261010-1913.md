# 計算構造を変える可能性の探索 — 現時点の判断記録

- **本記録は、Gemini対話の要点・要約ではない。** 試行錯誤の結果として残った考え方と、結（ゆい）による評価・不整合指摘を、新しい記録として形成する。
- 出発点の着想：M-Tokuni。Geminiによる数式・構成・実装提案は**生成された提案**であり、実証済みの研究結果とは区別する。
- この記録は完成理論・実装仕様・性能評価ではない。検討順位は再訪順の仮置きであり、真偽や性能を数値化したものではない。

## 1. 形成された考え方

- **目的を決めて達成方法を探すのではなく、何が可能かを試行錯誤で探索する。** 「最適化」は結果として起こり得ても、探索全体の定義にはしない。
- 考察対象は計算量の増減だけではない。**情報表現、記憶の保持、データ更新、関係性の配置、探索のやり方**を変える可能性がある。
- 分散PC、構文差分、複数の正解、幾何空間、メタ構造、センサーとの接続は、**一体化を前提としない別々の探索候補**として扱う。
- 可能性を広げるだけでは不明になる。現在の考察を煮詰める主軸を保持し、実際の探索資源には境界を置く。
- **短期のコスト削減を理由に、将来の接続可能性を消さない。** ただし何でも保存しない。保留した理由と、再検討を始めるキッカケだけ残せばよい場合がある。

## 2. 結による評価：残す可能性と成立条件

| ID | 検討候補 | 現時点の評価 | 再検索・再検討のキッカケ |
|---|---|---|---|
| GE-01 | AST差分・実行ログからの構造抽出 | 既存技術を組み合わせた小規模検討は可能。**構文差分は原因の確定ではない** | 失敗軌跡、メタデータ、環境条件、因果 |
| GE-02 | 条件が異なる複数の正解を保持 | 有効な方向性。**一つの評価軸で切らない**。正解・失敗・未検証を区別 | Quality-Diversity、MAP-Elites、多目的、負例 |
| GE-03 | 情報を幾何的に隣接させて検索 | 階層関係などでは検討価値がある。**近さの定義と遠方の見落とし**が未解決 | 双曲空間、ポアンカレ、局所探索、距離 |
| GE-04 | 外部メモリ・局所パッチ更新 | 部分技術は存在する。**重みが不変でも出力への副作用は起こり得る** | ROME、MEMIT、GRACE、パッチ衝突 |
| GE-05 | 規則・制約・不変量による探索枝刈り | 条件付きで有効。**抽象化そのものにも計算と誤判定がある** | メタ構造、同型、型、探索空間 |

| GE-07 | 端末側でのセンサー差分・補正 | 通信負荷低減などの余地はある。**観測から真値や原因は自動確定しない** | IMU、物理接地、観測残差、時刻同期 |

- **優先する再検討順**：GE-01〜03 → GE-04〜06 → GE-07〜08。これは試行の容易さ・主軸との接続を踏まえた暫定順位であり、変更してよい。
- どの案にも「成立済み」「局所的には成立」「保留」「不成立の主張」を混在させない。

## 3. Geminiの強い断定で、引き継がないもの

| 主張 | 指摘・判断 |
|---|---|
| 双曲空間なら遠方探索が不要・検索コストが消滅 | **一般には成立しない。** 類似性の尺度、埋め込み誤差、更新負荷、見落としが残る |
| 連続緩和・双曲幾何でNP困難問題の厳密解を高速に得られる | **根拠がない。** 緩和問題の解が元の離散問題の厳密解とは限らない |
| メタ化すれば組み合わせ爆発を完全に迂回できる | **未成立。** 規則発見、構造変換、同型判定、検証の負荷が残る |
| ROME・MEMIT・外部キャッシュなら破滅的忘却／他領域への影響がゼロ | **不正確。** 重みの保持とシステム挙動の安定は異なる。反復モデル編集による忘却の報告も存在する |
| 極小の記憶から失われた細部を一意に復元できる | **一般には不可。** 失われた区別は追加情報・限定条件なしには復元できない |
| 端末内の差分処理で「100%純粋な真値」を確定できる | **誤り。** 観測誤差・モデル誤差・未知の状態は残る |
| ポアンカレ球内で座標が閉じていれば物理的に安全 | **境界の混同。** 数学上の座標制約と、外部実行・危険行為を禁止する境界は別 |
| 99%削減、1/50圧縮、数µsで実行などの具体値 | **未検証。** 実測条件・比較対象・ログがないため採用しない |

### 判断の根にある区別

- **表現上の近さ ≠ 論理的正しさ**。
- **実行成功 ≠ 正しい仕様・原因の確定**。
- **記録の圧縮 ≠ 元情報の復元**。
- **部品の実装可能性 ≠ 統合構造の成立**。
- **数学的な制約 ≠ 安全境界**。
- **プログラム例・可視化 ≠ 動作実証・物理妥当性・性能検証**。

## 4. 探索の境界と、保留の運用

- **継続**：新しい成立条件、反証、接続先、試行方法が得られている。
- **保留**：同じ議論を繰り返している／観測・実装・外部資料を待つ必要がある。現時点で扱わないだけで、可能性を否定しない。
- **棄却**：対象と前提を限定した上で矛盾が確認できた。棄却理由だけを記録する。
- **対象外**：現行の探索と接続できない。無理に保存しない。
- **再接続**：新しい考え方から過去の記録が必要になった際、関連語とIDを更新して拾い上げる。

境界は、あらかじめ設定した「目的への達成度」の指標ではない。**無限探索を防ぎ、今この論点を掘るべきかを判断するための境界**である。

## 5. 次に進める場合の最小試行（未実施）

1. **構造抽出**：同じ小規模なコード修正・エラーログを、全文とAST差分の両方で保持し、後から問題を再発見できるか確認する。
2. **検索経路**：少量の共通データで、文字列・タグ・必要なら幾何索引を比較する。速度だけでなく、関連情報の見落としを記録する。
3. **更新と再接続**：過去の判断を改変せず、検索キッカケだけを新しい考え方に合わせて追加・修正できるか確かめる。

- 初期条件：元データ読み取り専用、外部送信なし、実験出力は分離。自律更新・権限拡張は許可しない。
- 結果が不明なら、推論で埋めず**不明として保留**する。
- 実験の狙いは最高性能の達成ではなく、**何が残り、何が失われ、どんな条件で成立するか**を知ること。
