## 1.1 従来の計算方式と「なぜ計算が破綻するか」



### 1.1.1 変分量子固有値ソルバ（VQE: Variational Quantum Eigensolver）



量子回路のパラメータを古典最適化で調整し、基底状態エネルギーを求める手法。



**破綻の構造**

- 古典最適化ループが「推定 → 補正 → 再推定」の二重推定連鎖を形成する

- ノイズのある量子回路（NISQ）では測定のたびに誤差が変質する

- 勾配消失問題（Barren Plateau）により、パラメータ数が増えるほど最適化不能に近づく



```text

推定値 → 損失関数 → 勾配計算 → パラメータ更新 → 再推定

            ↑_________________________________↓

                 誤差が二重推定で変質していく

```



### 1.1.2 量子位相推定（QPE: Quantum Phase Estimation）



ユニタリ演算子の固有値（位相）を精密に求める量子アルゴリズム。



**破綻の構造**

- 高精度化には回路深さの増大が必要になる

- 深い回路ほどデコヒーレンスが進み、測定前に情報が失われる

- 精度と安定性がトレードオフとなり、どちらかが犠牲になる



### 1.1.3 ハートリー–フォック法（HF: Hartree–Fock）



電子間相互作用を平均場近似で扱う量子化学計算の基礎手法。



**破綻の構造**

- 全電子の平均的影響という統計近似により、電子相関を構造的に切り捨てる

- 相転移、分子解離、強相関系では本質を見失う

- 平均値設計は、ピークと最小値が設計空間を決める系に適用しにくい



### 1.1.4 密度行列繰り込み群（DMRG: Density Matrix Renormalization Group）



量子多体系の基底状態を行列積状態（MPS）で近似する手法。



**破綻の構造**

- 1次元系には強力だが、2次元以上では必要なボンド次元が急増する

- 長距離エンタングルメントを持つ系では計算コストが現実的でなくなる

- 次元を上げるたびにメモリと計算量が爆発する



### 1.1.5 量子モンテカルロ法（QMC: Quantum Monte Carlo）



確率的サンプリングで量子系の期待値を計算する手法。



**破綻の構造**

- フェルミオン系では符号問題により統計誤差が急増する

- 符号問題はアルゴリズム工夫だけでは原理的解決が困難

- 長時間発展では分散が増大し、信頼できる平均値が得られなくなる



### 1.1.6 結合クラスター法 CCSD(T)



電子相関を系統的に取り込む量子化学の精密計算手法。



**破綻の構造**

- 計算スケールは \(O(N^7)\)

- 分子サイズの増大で計算量が急増する

- 精度は高くても、古典計算で全体を扱う設計のため、規模拡大に弱い



### 1.1.7 分子動力学シミュレーション（MD: Molecular Dynamics）



原子・分子の運動方程式を時間発展で数値積分する手法。



**破綻の構造**

- 離散化誤差が時間とともに累積する

- 短時間は安定でも、長時間では発散する

- 生物学的に意味のある時間スケールは原理的に重い



### 1.1.8 有限差分法（FDM: Finite Difference Method）



偏微分方程式を格子点上の差分で近似する手法。



**破綻の構造**

- CFL 条件により時間刻みと空間刻みの比に厳しい制約がある

- 条件を破ると不安定化する

- 局所急変や相転移で精度が崩れやすい



### 1.1.9 スペクトル法（Spectral Methods）



関数をフーリエ基底や多項式基底で展開して微分方程式を解く高精度手法。



**破綻の構造**

- ギブス現象により不連続点付近で精度が崩れる

- 周期的・滑らかな問題には強いが、相転移や衝撃波では対応が難しい

- 局所だけ精度を上げる操作が難しい



### 1.1.10 Runge–Kutta 法（RK4 等）



常微分方程式の標準的数値積分法。



**破綻の構造**

- 剛性方程式では極小時間刻みが必要になる

- 適応刻み幅制御は設計者の判断に依存する

- 長時間積分では位相誤差が避けにくい

## 1.2 従来手法の破綻パターンの共通構造



```text

【パターンA：二重推定連鎖】

推定 → 推定への補正 → 補正への補正 → ...

誤差が変質し続ける



【パターンB：誤差の線形・指数的累積】

ステップ数 × 離散化誤差 → 長時間で発散



【パターンC：次元の呪い】

次元・粒子数が増えるたびに計算量が指数爆発



【パターンD：局所精度と大域安定性のトレードオフ】

精度を上げると不安定化し、安定化すると精度が落ちる

```



全パターンに共通するのは、**古典計算が全体を抱えようとする設計**である。

## 1.4 なぜこの式が従来の問題を解消するか



### 1.4.1 根本保持：\(F_{\mathrm{IDE}}\) が全体を手放さない



```text

従来：古典計算が全体を抱える → 次元爆発・誤差累積

本式：F_IDE が大局的状態空間を保持し、

      古典補正 C(r_t) は局所・一時的役割のみ

```



### 1.4.2 基準点が過去実績値（逆算なし）



```text

r_t = \tilde{x}_{t+1} - x_{t-\ell}^{ref}



x_{t-\ell}^{ref}：過去の実測記録

\tilde{x}_{t+1}：IDE の前進計算による予測

```



比較対象が「推定 vs 推定」ではなく「予測 vs 記録」であるため、誤差の性質が変質しにくい。



### 1.4.3 残渣写像 \(C(r_t)\) が自動判断ゲートとなる



```text

|r_t| \ll k → C(r_t) \approx 0   古典層が沈黙

|r_t| \gg k → C(r_t) \approx r_t  精密補正が全開

```



### 1.4.4 二重推定連鎖を構造的に禁止する



```text

VQE：推定 → 損失 → 勾配 → 再推定 → ...

本式：記録 → r_t → C(r_t) → 補正

```



補正の計算に推定値を再投入する経路を持たない。



### 1.4.5 計算爆発の回避



```text

DMRG・CCSD(T)：全体を抱えるため指数爆発

本式：IDE が包括計算を担い、

      古典層は局所介入に限定される

```

## 1.6 結論



従来手法の共通の失敗は、**古典計算に全体を持たせようとすること**に起因する。



NRA-IDE 残渣ベース遅延精度確保型は、



- IDE が根本を保持し続ける

- 古典は \(C(r_t)\) が許可したときだけ局所介入する

- 補正基準が実績記録値である



という構造により、従来手法が個別に抱えてきた問題を、**単一の式の設計思想として扱う**。

## 2. 外部批評文



### 2.1 主張の整理



既存の量子回路ベース計算（VQE, QPE など）は破綻しやすく、  

NRA-IDE 残渣ベース遅延精度確保型は、そうした破綻を避ける構造候補として読める、という理解が提示された。



### 2.2 評価の要点



#### 2.2.1 既存量子計算が破綻しやすい理由

- VQE は二重推定連鎖と Barren Plateau を抱える

- QPE は回路深さとデコヒーレンスのトレードオフを抱える

- NISQ 実装では、現実的制約が強い



#### 2.2.2 NRA-IDE 式の量子計算への読み替え

- \(F_{\mathrm{IDE}}\) を量子時間発展に対応させる

- 残渣 \(r_t\) を「予測」と「過去の固定記録」の差として構成する

- \(C(r_t)\) により局所補正のみを発動させる



#### 2.2.3 慎重評価

- 「計算爆発をしない」とまでは言い切れない

- 量子ノイズそのものを消去するわけではない

- より正確には、**誤差が連鎖的に変質して制御不能になる経路を設計上排除する** と表現すべきである

## 3. 批評応答（◯1）



### 3.1 受け入れるべき指摘



#### 3.1.1 「爆発しない」という表現の強度

- ハードウェア層のノイズや誤り訂正問題は別層である

- したがって、「爆発しない」ではなく、

  - **誤差が連鎖的に変質して制御不能になる経路を設計上排除する**

  - **古典層に全体を持たせない設計により、爆発経路を構造的に閉じる**

  という表現が適切である



#### 3.1.2 量子ノイズと数値積分誤差の性質差

- NRA-IDE の式は、数値積分誤差の変質経路を断つ設計である

- 量子ノイズそのものを消す設計ではない

- 両者の混同は避ける必要がある



### 3.2 前提の食い違いとして整理すべき点



#### 3.2.1 「IDE が全体を保持する」の解釈

批評側はこれを「古典で全状態を全列挙すること」と読んでいる。  

しかし NRA-IDE の包括保持は、**性質保存圧縮**を前提としており、必要次元だけを展開し、それ以外は圧縮変数のまま運搬する設計である。



#### 3.2.2 本来の接合点

- 本来の接合点は量子シミュレーターである

- 線形量子計算は中継ぎ的運用と位置づけるべきである



### 3.3 この段階の結論

批評は全体として誠実であり、  

**受け入れるべき指摘** と **前提のずれ** を分けて扱うのが筋である。

## 11. 設計思想の転換1：遷移そのものを読む（◯9）



### 11.1 「急いで計算する」は線形の発想である



従来の量子計算は、しばしば次の構造に陥る。



```text

T_2 が短い → 情報が消える → だから急いで計算する

                                    ↓

                             回路深さを増やす

                             ゲート数を増やす

                                    ↓

                             δ_gate が累積する

                             τ_coh を食い潰す

                                    ↓

                     消失を防ぐための計算が消失を加速する

```



### 11.2 根本的な誤り



#### 誤り1：遷移を「制限時間」として扱う

\(T_2\) は締切ではなく、吸収幅 \(\tau_{\mathrm{coh}}\) の一部として読むべきである。



#### 誤り2：状態そのものを保存しようとする

量子状態 \(\rho\) そのものは no-cloning と衝突する。  

保存すべきは \(\rho\) そのものではなく、**構造の性質** と **遷移履歴** である。



#### 誤り3：速度で消失に勝とうとする

物理の時間スケールは、計算速度だけでは変えられない。  

NRA-IDE は、越えたら Fail-Closed で不能を返す。



### 11.3 遷移そのものを情報源として読む



従来：



```text

A状態 →【遷移＝ノイズ】→ B状態

```



NRA-IDE：



```text

A状態 →【遷移＝読み取り対象】→ B状態

        δ と τ の推移が情報

        dR/dt が予測情報

        C_ij(t) の変化が構造情報

```



### 11.4 時間スケール設計の転換



従来：

- 速く計算しなければ消える



NRA-IDE：

- **遷移の時間スケールに同期する**



```text

系の時間スケール τ_coh

        ↓

観測リズム Δt_obs = τ_coh / N_slice

        ↓

遷移を N_slice 枚のスナップショットとして読む

```



### 11.5 この節の結論

正しい問いは、



> 消失する前にどう計算するか



ではなく、



> 遷移そのものをどう読むか



である。

## 12. 設計思想の転換2：遊びを中心に置く（◯10）



### 12.1 \(\tau\) の本質は「遊び」である



吸収厚み、許容幅、余裕という説明は結果側の表現にすぎない。  

\(\tau\) の本質は、**系が存続するための遊び** である。



- ベアリングの隙間

- 歯車の噛み合いの遊び

- 熱膨張やゆらぎを吸収するための余地



遊びは欠陥ではなく、**存続条件** である。



### 12.2 線形の発想との違い



線形的発想：

- \(\tau\) を小さくすれば判定精度が上がる

- \(\delta\) と \(\tau\) の差を詰めれば正確になる



NRA-IDE の発想：

- \(\tau\) は系が生き延びるための遊び幅

- \(\delta\) がブレても \(R\) が跳ねないための構造

- 遊びを削ってはならない



### 12.3 生存条件としての遊び



ゼロ誤差を目指す系は、わずかな外乱で停止する。  

遊びを持つ系は、外乱を \(\tau\) の中に吸収しながら続く。  

**揺れながら続くこと** が生存である。



### 12.4 「何を遊びと考えるか」が設計の本質



従来：

- まず理想精度を作る

- 現実との差を誤差として後から許容する



NRA-IDE：

- まず遊びを定義する

- 遊びの中でどう動くかを追跡する

- 遊びそのものを設計の中心に置く



### 12.5 観測量選択への影響

観測量を選ぶとは、**何を厳密に追跡するか** を決めることである。  

選ばれなかった次元は、**遊ばせる次元** になる。  

全てを追跡しようとする発想こそが線形の呪いである。



### 12.6 重み行列 \(W\) への影響

\(W\) は、各観測量をどれだけ厳密に追跡するかの配分である。



- \(W\) が大きい軸：厳密追跡軸

- \(W\) が小さい軸：遊びを与える軸



### 12.7 相関変質検出式の再定式化

旧い発想：

- 相関のズレを検出して止める



新しい発想：

- 相関は遊びの中で揺れるのが正常

- \(\tau_C\) は相関が遊べる幅

- その範囲を越えたときだけ構造変質とみなす



### 12.8 \(R = \delta / \tau\) の読み替え



旧い読み方：

- 逸脱 / 許容



新しい読み方：

- **動いている幅 / 遊ばせている幅**



\(R\) は破綻判定値ではなく、**遊びの使用率** である。  

動きが遊びの範囲内なら生存し、遊びを越えれば生存空間から離脱する。



### 12.9 この節の結論

「どれもが精緻な正確さを求めない」という一文は、  

NRA-IDE を従来の計算論から切り離す決定的な言語化である。
