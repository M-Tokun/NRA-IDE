# Microsoftが確認した事実と、まだ証明されていないこと（AIサイバー攻撃の実態）

**2026年10月23日｜一次資料検証**

2026年10月21日、MicrosoftはAIエージェントを利用した大規模なサイバー攻撃について技術報告を公開しました。

報告によると、Microsoftが「Storm-0940」と呼ぶ攻撃集団は、AIを利用する侵入テストフレームワーク「ARTEX」を使い、2026年9月以降、世界の数百の組織を標的としていました。

さらに、IT管理サービス企業ConnectWiseのクラウドバックアップ関連アプリケーションの認証情報が悪用され、顧客のMicrosoft 365環境への不正アクセスが発生しています。

しかし、ここで重要な区別があります。

**攻撃の観測事実、攻撃主体の帰属分析、AIが実行した処理の範囲、実際に発生した被害は、それぞれ異なる検証対象です。**

本記事では、Microsoft、ConnectWise、Huntress、Todylの直接報告を照合し、攻撃の各段階と、まだ証明されていない部分を明確にします。

## 1. Microsoftが観測した攻撃活動――認証試行の段階

Microsoftの報告では、2026年10月10日から14日にかけて、327アカウント、8組織を対象とする大規模なパスワードスプレー攻撃が観測されています。

認証失敗は15万1,000件以上に達し、10月11日のピーク時には毎分2,900件の失敗が記録されました。

ただし、この攻撃についてMicrosoftは、認証成功、トークン発行、Microsoft Graph操作、ディレクトリ変更を観測していないと明記しています。

これは、**大量の攻撃が実行されたことと、攻撃が成功したことは別である**という具体的な事例です。

また、この攻撃活動と、その後に確認されたConnectWise経由の不正アクセスについては、関連するネットワーク上の痕跡が確認されています。

しかし、ネットワーク上の関連性だけで、パスワードスプレー攻撃がConnectWiseの認証情報窃取を直接引き起こしたと証明できるわけではありません。

この二つは、関連する攻撃活動として扱いながらも、侵入経路としては分離して検証する必要があります。

## 2. ConnectWise経由の不正アクセス――既存権限の悪用

もう一つの重要な攻撃経路は、ConnectWiseのアプリケーション認証情報の悪用です。

ConnectWise自身が、Cloud Backup（旧SkyKick）に関連するアプリケーション認証情報への不正アクセスを確認しています。

Microsoftの報告では、攻撃者がこれらの認証情報を利用し、2,250を超えるMicrosoft 365テナントへのサインインを試みたとされています。

攻撃者は、個々の利用者のパスワードを新たに入力するのではなく、第三者アプリケーションに既に与えられていた認証情報とアクセス権限を利用していました。

この仕組みでは、利用者本人による対話的なログインを経ずに認証が成立します。

セキュリティ企業Todylは、自社が監視する顧客環境で、ConnectWise Cloud BackupのアプリケーションIDによる不正な認証成功を確認しています。

またMicrosoftは、複数の顧客環境において、Microsoft Graphを通じた探索、アプリケーション認証情報の変更、権限に関する操作を確認したと報告しています。

ただし、認証成功後の操作内容は、すべての顧客環境で同じではありません。

ここで分離する必要があるのは、次の三つの状態です。

- **認証試行：** 攻撃者がアプリケーションとしてサインインを試みた状態。
- **認証成功：** Microsoft Entra IDが認証を受け入れ、アクセストークンを発行した状態。
- **後続操作：** 認証によって得た権限を使い、探索や権限変更などを実行した状態。

この三つをまとめて「侵害成功」と表現すると、どの操作が実際に成立したのか分からなくなります。

さらに、ConnectWiseの認証情報が最初に取得された経路については、公開された調査資料だけでは全工程を確定できません。

これは今回の重要な未確定境界です。

## 3. AIは何を実行したのか――自動化と自律性

ARTEXは、複数の大規模言語モデルを利用する、オープンソースの侵入テストフレームワークです。

Microsoftによると、ARTEXは偵察、スキャン、認証試行、OAuthアプリケーションの悪用など、複数の攻撃工程を自動化するために利用されました。

この自動化によって、攻撃者は大量の対象に対し、高速に処理を進めることができます。

Microsoftは、Storm-0940によるARTEX利用攻撃の複数事例において、標的の選定から3時間未満でクラウドの特権アクセス取得に至ったと報告しています。

ただし、この3時間未満という結果を、ConnectWise経由のすべての攻撃に適用することはできません。

また、ARTEXというフレームワークが自律的な侵入テストを実行できることと、今回の攻撃における個々の判断をAIが独立して行ったことは、別の問題です。

公開資料からは、AIエージェントが攻撃の自動化に利用されたことを確認できます。

一方で、標的の選定、認証情報の取得、実行命令、操作内容の変更について、人間がどこまで介入したのかは、すべて明らかになっているわけではありません。

**AIによる処理の自動化と、AI自身による判断の自律性は、分けて評価する必要があります。**

なお、MicrosoftはStorm-0940が過去の攻撃活動でMicrosoft Graphを通じたメールなどの情報取得・外部流出を行ったことも報告しています。

しかし、その記述を今回のConnectWise経由の全顧客環境における情報流出の証拠として扱うことはできません。

## 4. 中国政府との関係――帰属分析の限界

Microsoftは、Storm-0940を中国国家と連携する攻撃主体として分類しています。

同社は、この攻撃集団が2021年から活動していると説明し、ConnectWiseに対する今回の攻撃も同集団によるものと評価しています。

ConnectWiseも、Microsoftから共有された脅威情報などを根拠として、中国国家と連携する集団が関与したとみられると説明しています。

ただし、両社の説明が一致していることだけで、独立した二つの証拠系統が成立したとは判断できません。

また、公開資料からは、中国政府による具体的な命令内容、指揮命令系統、実行者個人の特定までを独立に確認することはできません。

この区別は、中国国家との関連を否定するものではありません。

**Microsoftの脅威主体に関する分析評価と、中国政府による直接指揮の証明では、必要とされる証拠が異なります。**

したがって、Storm-0940の帰属については、Microsoftによる分析判断として明記することが適切です。

## 5. 実際に確認された侵害――観測主体による違い

今回、複数のセキュリティ企業が顧客環境の調査結果を公開しています。

しかし、それぞれの企業が監視している環境は同じではありません。

### Huntressの確認結果

Huntressは、10月16日19:00 UTC時点で、162テナントにおける不正サインインを確認したと報告しています。

さらに10月17日の更新では、不正活動に関連するIPアドレスから約1,000テナントへのサインイン活動を確認し、そのうち300を超えるテナントでサインインが成功したと報告しています。

また、特定の顧客環境では、ConnectWise Cloud Management関連のアプリケーションがGlobal Administrator権限を付与され、ほかのアプリケーションに新しい認証情報が追加されたことを確認しています。

Huntressは10月19日の更新で、二つの顧客環境における類似した後続操作についても報告しました。

ただし、Huntressは一部の先行操作について、後続の不正サインインと同じ実行者によるものと確定できない点も明記しています。

### Todylの確認結果

Todylは、自社が監視する顧客環境において、ConnectWise Cloud Backupアプリケーションによる不正な認証成功を確認しています。

一方、その調査範囲では、不正な新規認証情報の追加、権限付与、アカウント作成などの後続操作を確認していません。

これはMicrosoftやHuntressの報告と矛盾するものではありません。

観測された対象環境と攻撃の進行状態が異なるためです。

### ConnectWiseの確認結果

ConnectWiseは10月23日01:00 UTC時点の更新で、既存のバックアップアーカイブが暗号化・隔離・保全されており、侵害を示す兆候は確認されていないと説明しています。

しかし、これは顧客のMicrosoft 365環境でデータがアクセスされたかどうかについての結論ではありません。

ConnectWiseも、個々の顧客環境について別途確認が必要であると説明しています。

以上のように、各社の報告は観測対象と検証範囲を明示して取り扱う必要があります。

## 6. 本質的な問題はAIだけではない――権限と信頼関係

今回の攻撃では、AIによる処理の自動化が注目されています。

しかし、実際の侵入経路で重要だったのは、第三者アプリケーションに既に付与されていたアクセス権限です。

利用者本人のログインに多要素認証を設定していても、バックアップや管理用アプリケーションには、別の認証方式と権限が用意されています。

攻撃者がそのアプリケーションの有効な認証情報を入手すると、既に許可されていた範囲でアクセスできる場合があります。

これは多要素認証そのものの欠陥という意味ではありません。

利用者認証と、アプリケーションの認証・権限管理が別の境界を持っているということです。

さらに、攻撃者が新しい認証情報を別のアプリケーションに追加した場合、最初の侵害経路だけを遮断しても、不正アクセスが継続する可能性があります。

そのため、防御側には以下の確認が必要です。

- アプリケーション認証情報の管理と失効
- 第三者アプリケーションに付与された権限の確認
- 不審なサービスプリンシパルのサインイン調査
- 新規認証情報や権限変更の監査
- 復旧後に不正なアクセス経路が残っていないことの確認

認証を突破されたかどうかだけでなく、どの権限が利用され、どの状態まで変化したかを確認する必要があります。

## 7. 攻撃件数と被害件数を混同しない

今回の事件では、複数の異なる数値が報告されています。

| 指標                 | 確認された数値      | 意味                        |
| ------------------ | ------------ | ------------------------- |
| パスワードスプレーの認証失敗     | 15万1,000件以上  | Microsoftが観測した失敗イベント      |
| パスワードスプレーの対象       | 327アカウント・8組織 | 上記攻撃の対象範囲                 |
| ConnectWise経由の認証試行 | 2,250超テナント   | Microsoftが報告したサインイン試行対象   |
| 不正サインイン確認          | 162テナント      | Huntress、10月16日時点         |
| 不正活動関連IPからのサインイン成功 | 300超テナント     | Huntress、10月17日の追加報告      |
| 特権操作・認証情報追加        | 一部環境で確認      | MicrosoftおよびHuntressの個別観測 |
| 情報流出の総件数           | 未確定          | 全体を確定する資料なし               |

これらは、異なる時点、観測環境、攻撃段階を表しています。

また、二次報道には173テナントでの不正サインインという数値もありますが、今回採用したHuntressの直接報告とは確認時点・範囲の照合が必要なため、確定した被害総数としては使用していません。

認証試行、認証成功、特権操作、情報へのアクセス、外部流出は、順番に発生し得る状態であっても、すべてが必ず成立するわけではありません。

特に、Microsoftが確認した15万1,000件以上の認証失敗を、侵入成功数や被害件数に含めることはできません。

同様に、2,250超テナントへの認証試行を、2,250組織の実侵害として表現することも不適切です。

## 8. 結論――何が成立し、何がまだ分かっていないのか

今回のMicrosoftの報告では、AIエージェントを利用した攻撃の自動化と、侵害された第三者アプリケーションの認証情報を悪用する攻撃が確認されています。

また、一部の顧客環境では、認証成功後の権限変更や、新しい認証情報の追加も報告されています。

したがって、今回の事件を単なる攻撃試行として扱うことはできません。

実際に認証が成立した環境があり、一部ではさらに後続操作へ進んでいます。

しかし、すべての認証成功が特権取得に至ったわけではなく、特権取得の観測から直ちに情報流出まで確定できるわけでもありません。

AIの自律的判断の範囲、ConnectWiseの初期侵害経路、個々の顧客環境での情報流出についても、未確定事項が残っています。

さらに、攻撃主体についてのMicrosoftの分析評価と、中国政府による直接指揮の証明を混同してはなりません。

**重要なのは、AIによる攻撃を過小評価することでも、危険性を過大に表現することでもありません。**

何が観測され、どの境界を通過し、どの状態まで成立したのか。

どこから先は証拠が不足しているのか。

それらを切り分けることで、実際に成立した攻撃経路と防御上の問題を明確にできます。

## 大事な部分のまとめ

今回の事件では、既存の認証情報を悪用した不正なクラウド認証が成立し、一部の環境では権限変更や認証情報の追加も確認されました。

その一方、認証失敗数、認証成功数、特権操作が確認された環境数、情報流出件数は別々の指標です。

**観測された状態と、そこから推定される状態を混同しないことが、攻撃の実態を正確に把握するための基本条件です。**

また、観測されていない経路を推論で補わず、未確定事項として保持する必要があります。

## 要点（要約）

- **観測事実：** Microsoftが15万1,000件以上の認証失敗を報告しました。この試行段階では認証成功を観測していません。
- **認証の成立：** ConnectWiseのアプリケーション認証情報が悪用され、一部の顧客環境で不正な認証が成功しました。
- **後続操作：** 一部の環境では権限変更、認証情報の追加などが確認されています。ただし、その実行主体との関連付けには個別の留保があります。
- **AIの利用：** MicrosoftはARTEXを利用した攻撃の自動化を報告していますが、人間とAIの判断分担の全容は未確定です。
- **帰属分析：** Storm-0940と中国国家との関連はMicrosoftの分析評価であり、政府の直接指揮の独立した証明とは異なります。
- **未確定事項：** 初期侵害経路、AIの具体的な自律判断範囲、組織別の情報流出、侵害全体の最終的な規模。
