## NRA‑IDE：構造安全のための原則体系

### ⚠️ 最重要：NRA‑IDE の混用禁止原則

### 他構造や他AIとは値の受け渡し接続は問題ありません。しかし、NRA-IDE本体との混用計算はNRA-IDEの価値が無くなります。
### また、最悪なのは結果を見たAIが原因を推定して再帰学習を行うこと。
### これは精度向上ではなく原因追跡不能なブラックボックスができます。

---

## 1. NRA‑IDE の根本思想

NRA‑IDE は **AI の推測や意味を信用しない** という前提に立ち、AI の前後に「因果構造フィルタ」を挟むことで安全を保証する仕組みである。
そのためには、**AI の推測と IDE の構造安全を絶対に混用しない**という強い分離が必要である。

---

## 2. IDE が扱うのは「物理ログ」だけである

### IDE が扱うべき情報は、物理構造。「 **物理的・因果的・観測可能な事実** のみである。」

扱ってよいもの
- 入力 δ 列
- τ（厚み）
- R（安定度）
- 経路（ω）
- Pre‑RNA Gate の通過／拒否ログ
- Post‑RNA の R 計算ログ
- fail‑closed の発火点
- LongRunGuard の経路情報
- センサー値
- 実際の入出力
- 状態遷移

### 扱ってはいけないもの

- AI の推測
- AI の内部確率
- AI の「思ったこと」
- ハルシネーションログ
- 意味・意図・文脈

###　勘違いしてはいけないこと　---

IDE 側には 「AI の出した値がどこから来たか」は一切書き込まないこと。
IDE が受け取るのはあくまで外部システムからの入力値（＝世界に現れた事実）だけ。
AI 由来であっても、それは 推論ログではなく “物理的に出てきた値” として扱う。

---

## 3. 🛡 IDE の役割：事実を残し、整合性が崩れたら止める
IDE は AI を賢くする装置ではない。
IDE は AI がどれだけ推測しようと、物理構造でロックする装置 である。

ASCII 図で示すとこうなります。

```
┌──────────────┐
│   世界（物理） │
└───────┬────────┘
        │ 物理ログ
┌───────▼────────┐
│      IDE（構造安全） │  ← 事実だけ扱う
└───────┬────────┘
        │ 因果構造フィルタ
┌───────▼────────┐
│      AI（推測器）     │  ← 推測は信用しない
└────────────────┘
```

IDE は AI の推測を安全判断に使わない。
IDE は AI の推測を構造ルールに反映しない。
IDE は AI の推測ログを信用しない。

---

## 4. 「1.0 閾値」とハルシネーション検知

「1.0」という閾値は、
**AI に任せてはいけない領域に到達したことを示す警告点**

--　例　--
- 前に物体があるのに AI が「ない」と判断した
- センサー値と AI の判断が一致しない
- AI の出力が物理世界と矛盾した

このとき IDE は即座に警告を発し、人間に責任バトンタッチする。

```
AI判断  ──┐
          │  ← 1.0 を超えたら危険領域
物理世界 ─┘
```

1.0 を超えた後も **物理ログは取り続ける** が、
**AI のハルシネーションログは安全判断に使ってはならない**。

---

## 5. 再帰学習（自己改善）は構造安全の観点から絶対に禁止
AI の再帰（自己改善）学習は
**推測 → 推測の学習 → 推測の学習の学習**
という「二重推測構造」を生む。

ASCII で示すとこうなる。

```
推測1 → 推測2 → 推測3 → 推測4 → …
   ↑         ↑         ↑
   │         │         │
  学習      学習      学習
```

これは、安全度を高めるのではなく、ブラックボックスを**指数関数的に深くするだけ** である。

結果
- 原因が追跡不能
- 誤りが構造に焼き付く
- 人間が解析できない
- リセット機構が存在しない

よって再帰学習は **構造安全層に関しては完全に排除** されるべきである。

---

## 6. RCA（原因分析）は IDE ではなく人間が行うこと

### IDE が作成した物理ログを元に、**原因を考えるのは人間である**。

### 👉 AI に原因推定をさせてはいけない理由
- 推測が混ざる
- 推測の連鎖でブラックボックス化
- 誤った推測が構造に焼き付く
- IDE の安全性が崩壊する

### 👉 IDE と完全に分離した別 AI を使う
### 👉 ただし IDE の構造ルールに反映してはならない

これが
**「混用は不可でも接続は認める」**
という原則である。

---

## 7. レコード情報が足りなければ IDE のログ変数を増やす

原因が追求できない場合
不足しているのは **AI の推測ではなく物理ログの項目** である。

したがって
- IDE のログ変数を増やす
- センサーを追加する
- 経路情報を細かくする
- fail‑closed の発火点を詳細化する

など、**物理世界に対して観測可能な変数を増やす** のが正しい。

---

## 8. IDE の構造ルール（invariants）は人間が書く

### 禁止事項
- AI に invariant を作らせる
- AI に構造ルールを変更させる
- AI の推測を構造ルールに反映する

IDE は **固定された構造** を守る装置であり、自己改善や自己修正を行う装置でありません。

---

## 9. フライトレコーダーの役割

### フライトレコーダーは

- 意図を記録しない
- 推測を記録しない
- 物語を記録しない
- なぜそう思ったかを記録しない

 記録するのは
**実際に存在した事実だけ**。

NRA‑IDE の Vault / Trace も同じである。

```
┌──────────────────────┐
│   フライトレコーダー（IDE）   │
│   ・事実だけを記録する         │
│   ・推測は記録しない           │
└──────────────────────┘
```

---

## 10. 🧩最終まとめ

### IDE は“事実を残す装置”であり
 
 1.推測を混ぜた瞬間に構造安全は崩壊する
 2.原因分析は別途に解析させる（別AI解析でも問題はないが結果を人間が確認してしくみを再構成）
 3.NRA-IDEの構造本体には絶対に反映させない
 4.情報が足りなければ IDE の物理ログ変数を増やす
 5.再帰学習と推測の連鎖は安全の確保ができない。
 公理の分離違反、安全思想違反と同じ原則。
 混用すると、何の保証もない価値のないものが出来上がります。。
