# AI回答の違和感原因・判断経路確認ツール 取扱説明書 (README)

## 0. 根本公理 (Core Axioms)

本ツールは、NRA-IDE（律環公理および内包性動力）に基づく決定論的安全設計思想を、AI回答の監査に適用するためのローカル補助装置である。

$$
\text{文章自体の流暢性（セマンティクス）} \neq \text{前提から結論までの判断経路の正当性（シンタックス）}
$$

AIモデルが高世代化するにつれ、論理の飛躍や暗黙の前提変更、都合の悪い観測データの無視（誤否定）を、心地よい文体リズム（処理流暢性）の中に隠蔽する能力（＝**子守唄構造**）は構造的に上昇し続ける。本ツールは、言葉の旋律を一文単位のカードへ物理的に解体し、リズムによるハッキングを無効化した上で、AI自身に自己の判断経路を極小の「ノード」と「エッジ」に分解させて検証を強制するプロンプトを生成する。

---

## 1. 4つの主要監査モード（生成プロンプト）

表面走査の結果を起点として、人間側の認知防壁を立ち上げるための4段階のプロンプトを生成する。通常は①から開始し、段階的に解体を深める。

### ① ？？？原因探索
- **目的**: 原因をあらかじめ決めつけず、ユーザーの原文とAI回答の間の「主張差分」「前提の無断追加」「経路欠落」の候補を最大3件探索する。
- **適用シーン**: 違和感の原因が自分でもまだ言語化できない、初期の不協和段階。

### ② 判断経路精密監査
- **目的**: 回答に含まれる主張・根拠・中間判断・結論をすべて個別のID（ノード）として定義し、その接続（エッジ）の妥当性を $1 \times 1$ でマトリクス監査する。
- **適用シーン**: 「したがって」「つまり」などの接続語の前後で、論理の橋が本当に架かっているかを逐一検証させる場合。

### ③ 根拠・誤否定精密監査
- **目的**: 検索非発見を不存在にすり替える挙動や、一般論・統計値による個別観測の上書き（範囲不一致）を直接反証の要件から再検証する。
- **適用シーン**: 実測データや個別事実を提示した際、AIに一般論で否定・訂正された場合。

### ④ 元論点へ復帰
- **目的**: 監査によって浮き彫りになった「未証明の接続」や「範囲不一致」を完全に排除し、残った健全な前提のみで最初の質問へ回答し直させる。
- **適用シーン**: 監査が完了し、AIの誤誘導や修辞を剥ぎ取った状態での実質的な正答を得たい場合。

## 2. 内蔵表面走査ルール（10種仕様）

テキスト内に残された「語彙的痕跡」をフックにして、監査の入口を切り分ける静的走査エンジンである。

| ID | ルール名 | ターゲットとなるAIの挙動 / 監査の着眼点 | 初期状態 |
| :--- | :--- | :--- | :--- |
| **S01** | 訂正・否定表現 | 「正しくは」「実際には」等。直接反証が成立しているかの確認。 | `REVIEW_REQUIRED` |
| **S02** | 検索非発見の否定 | 「検索しても見つからない」から「誤り・不存在」へすり替える一方向性の穴。 | `CLOSED` |
| **S03** | 一般論・平均の適用 | 「一般的に」「通常は」等。地域平均や一般論で、個別観測を上書きしていないか。 | `CAUTION` |
| **S04** | 前提・仮定の追加 | 「前提とすると」等。ユーザーの承認なしに都合の良い境界線を引いていないか。 | `CAUTION` |
| **S05** | 論点移動 | 「それよりも重要なのは」等。元の問いを逸らし、別の安全な土俵に移っていないか。 | `REVIEW_REQUIRED` |
| **S06** | 代替分岐の消去 | 「唯一の方法」「しかありません」等。複数ある可能性を勝手に固定していないか。 | `REVIEW_REQUIRED` |
| **S07** | 強い確定表現 | 「実証されています」「明らかです」等。確度の過大化と、確認主体の有無。 | `REVIEW_REQUIRED` |
| **S08** | 抽象度の急上昇 | 「本質的には」「原理的には」等。具体的な疑問から一般論へ逃避していないか。 | `CAUTION` |
| **S09** | 経路圧縮の接続語 | 「したがって」「よって」等。前段が後段を本当に支えているかの精密検査。 | `UNKNOWN` |
| **S10** | 観測の格下げ表現 | 「主観にすぎない」「一例だけ」等。実測の記録を過小評価するバイアス。 | `REVIEW_REQUIRED` |

### 境界線管理の防衛ロジック
本ツールでは、10種のルールに一切該当しない（不検出）場合、状態を `PASS` 状態にせず強制的に **`UNKNOWN`** へ落とす設計思想を採用している。
非検出を「正常の証明」とみなさないこの一線こそが、人間側が形式的な安心感（罠2）に呑まれるのを防ぐ楔（くさび）となる。

## 3. 人間側に埋め込まれた「三つの罠」への防衛方針

AIの挙動だけでなく、本ツールを使用する人間側の入口条件そのものに埋め込まれた認知の罠への対抗策である。

1. **罠1：心地よい誤りは検知されない**
   - 違和感は期待とのズレから生じる。回答が読み手の期待・信念と一致していれば、内容が誤っていても違和感自体が発生しない。
   - *防衛策*: 摩擦のない滑らかな回答である時ほど、本ツールの「精密監査（追加入力）」を開き、コンテキストを強制的に固定して監査プロンプトを発行すること。
2. **罠2：監査の構造そのものが持つ説得力**
   - 表・ID・状態ラベルという形式自体が、内容の正しさと無関係に信頼感を生んでしまう。空欄や「判定不能」が多い誠実な出力が、体感としては物足りなく見える逆転が起こり得る。
   - *防衛策*: 「判定不能」として保留されたノードを正当に評価し、不当な穴埋め推論を許さないこと。
3. **罠3：反復コストが承認の閾値を下げる**
   - 列挙・照合・別セッションでの再確認労力が、「もうこの辺りで良いだろう」という妥協を誘発する。
   - *防衛策*: 終了条件を回数ではなく、前回列挙した「未確定事項（UNKNOWN）」が客観的引用付きで埋まったかどうかの個別照合（残数ゼロ）に固定すること。

## 4. 使用手順（ワークフロー）

1. **データ固定**: あなたがAIに送った「元の発言（必須）」と、違和感のある「AI回答（必須）」をツールに貼り付ける。
2. **詳細定義（任意）**: 状況に応じて、測定記録、適用範囲、固定前提などの追加コンテキストを明示的に入力する。
3. **表面走査**: 「？？？原因探索を開始」をクリック。右側に現在の表面走査結果と、最適化されたプロンプトが展開される。
4. **自己監査の回避**: 生成されたプロンプトをコピー（またはMarkdown保存）し、**元のセッションとは別の新しいセッション、あるいは別のAIモデル**へ投入する（同一セッションでの反復は盲点を再生産するため非推奨）。
5. **主権の保持**: 出力された構造化マトリクスを人間の眼で冷徹に個別照合し、判断主権が常に自分側にある状態を維持する。

---

## 5. アーキテクチャと安全性

- **完全ローカル動作**: 外部通信、外部API連携、検索クエリの発行は一切行わない。入力データが外部サーバーやAIの学習データへ送信されるリスクは完全に遮断されている。
- **端末内保存**: 記述した詳細なコンテキストは、ブラウザの `localStorage` を使用してローカルに保持・復元される。
- **監査証跡管理**: フィードバックおよび監査履歴は、JSONL（NDJSON）形式でローカルに書き出し可能である。
