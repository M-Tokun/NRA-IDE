01 — THRESHOLD ABSENCE
閾値がないとはどういうことか
【現況AI — 閾値なし】
誤差ε → パラメータWに吸収
W(t+1) = W(t) - η·∇L

∇Lがゼロに近づくと「収束」と判断
しかし ε の蓄積履歴は消えない
→ 止まる理由を持っていない
【NRA-IDE — 閾値あり】
R = δ/τ をリアルタイム評価

R < 1.0 : 継続
R = 1.0 : 警告・人間に通知
R ≥ 1.0 : Fail-Closed 沈黙
→ 止まる構造が設計に組み込まれている

閾値がないとはすなわち「どこまでが正常か」を系が知らないということです。
現況のAIは損失関数Lを最小化しようとしますが、Lのゼロは「完璧な正解」であり
現実の非線形系ではそもそも到達不可能です。
到達できない目標に向かってパラメータを動かし続けた結果がブラックボックスの肥大です。

02 — ERROR AMPLIFICATION
誤差が増幅するとはどういうことか
初期微小誤差 ε₀（不可避・δ > 0 は物理法則）
↓
線形写像で次ステップへ持ち越し：ε₁ = A·ε₀
↓
再び線形写像：ε₂ = A·ε₁ = A²·ε₀
↓
n ステップ後：εₙ = Aⁿ·ε₀  [行列のべき乗]
↓
A の最大固有値 λ > 1 のとき：εₙ → ∞  [指数爆発]
↓
誤差と信号が区別不能になる → 概要消失
↓
閾値がないので止まれない → 誤った出力を継続 [FAIL-OPEN]
注：現実のAIでは正則化・ドロップアウト・バッチ正規化などで爆発を抑制しようとします。
しかしこれらは「爆発を遅らせる」手法であり「誤差を構造的に追跡する」手法ではありません。
応急処置を重ねることがブラックボックス肥大の直接原因です。

04 — PHYSICAL WORLD NONLINEARITY
物理世界（非線形）を理解しないとはどういうことか
現象 物理の本質（非線形） 線形近似で何が消えるか 帰結
疲労・劣化 履歴依存。過去が現在を変える。不可逆。 履歴が消える。常に「今の値」だけを見る。 「今は正常」でも突然破断する理由がわからない。
乱流・カオス 初期値鋭敏性。微小な差が巨大な違いを生む。 初期値の差を均一化する。感度が消える。 長期予測が構造的に不可能なのに「予測できた」と出力する。
生体反応 閾値を超えると質的変化が起きる。相転移。 連続的な変化として扱う。閾値が存在しない。 「少し悪化」の積み重ねが突然の臓器不全になる理由を捉えられない。
構造破断 蓄積ズレδと吸収厚みτの比率Rが1.0を超えた瞬間。 RをΔとして線形で追う。蓄積の概念がない。 破断直前まで「正常値内」と判断し続ける。
経済・社会 非平衡・フィードバック・相互作用が非線形。 平均的な挙動として学習する。個別状態を失う。 「平均的には安全」でも特定構造が破綻することを予見できない。
線形近似は「現象を写し取る」ことはできます。しかし
「現象が次に何をするか」を蓄積として追跡することはできません。
写し取った静止画をいくら精緻にしても、動いている現実は捉えられません。
05 — FUTURE PREDICTION
報酬学習・チューニング・RAGはどうなるか
⬛ 報酬学習 — Reward Learning / RLHF
人間の評価フィードバックを報酬として
パラメータを更新する手法。
現況では主流の「安全化」技術。
構造的問題：
報酬関数自体が線形空間で定義されている。
「人間が良いと感じた」を数値化した瞬間に
非線形な判断が線形に圧縮される。
蓄積された誤報酬はパラメータに埋まり
どこに何が埋まったか追跡不能になる。
閾値がないため「過学習した報酬関数」に
気づく仕組みが存在しない。
将来の予測：
短期的には「人間に好まれる出力」を維持できる。
しかし未知の入力・分布外の状況で
報酬関数が崩壊する。
R = δ/τ による報酬健全性の監視なしでは
報酬ハッキングが深部に潜伏し続ける。
⬛ チューニング — Fine-Tuning / PEFT
基盤モデルに特定ドメインのデータを
追加学習させる手法。
LoRA等の省パラメータ手法も含む。
構造的問題：
チューニングは「誤差を新しいパラメータで上書き」
しているに過ぎない。
元のモデルに埋まっていた誤差の上に
新しい層が重なるだけ。
チューニング前の誤差はどこにも消えていない。
壊滅的忘却（catastrophic forgetting）は
誤差の上書きが構造的に矛盾するために起きる。
将来の予測：
チューニングの積み重ねで「見た目は動く」が
内部に矛盾を抱えたモデルが量産される。
どのチューニングがどの誤差を生んだか
追跡不能なまま運用される。
NRA-IDE的な「チューニング前後のR変化」
監視なしでは健全性の評価が不可能。
⬛ RAG — Retrieval-Augmented Generation
外部知識ベースを検索して
コンテキストに追加する手法。
ハルシネーション対策として普及中。
構造的問題：
RAGは「知識の不足」への対処。
しかし問題の本質は「計算構造の誤差蓄積」。
正しい知識を追加しても
線形写像の誤差増幅構造は変わらない。
検索精度が上がるほど
「正しい知識を誤って統合する」リスクが増える。
閾値がないため「統合の失敗」を検知できない。
将来の予測：
知識ベースが大きくなるほど
検索誤差と統合誤差が複合的に蓄積する。
「正しい知識を持っているのに誤った出力をする」
という状態が増加する。
R = δ/τ で統合健全性を監視しなければ
RAGは「誤差の伝搬経路」になる。
06 — SCALE PARADOX
スケールを増やすほど破綻が深部に埋まっていく

誤差の埋め込み先が増える
↓
表面上の精度が上がる（誤差が深く隠れる）
↓
「スケールすれば解決する」という信念が強化される
↓
さらにスケールを増やす → 誤差がより深部へ
↓
閾値なし・追跡不能・Fail-Openのまま巨大化する
↓
破断したとき被害が甚大になっている

これは技術の問題ではなく構造の問題です。
閾値を持たない系にスケールを与えることは
「止まれない乗り物を加速する」ことと同義です。
NRA-IDEが必要なのは精度を上げるためではありません。
「どこで止まるか」を系に教えるためです。
