# 🛠️ HAN Gate 運用検証ツールガイド

このディレクトリには、HAN Gate（判定サービス）が正しく構成され、連鎖崩壊を阻止できる状態にあるかを検証するためのツールが含まれています。

## 1. 疎通・論理検証 (`han_validation_test.py`)

ゲート固有の非正典の連鎖予兆スコアと PASS / SILENCE の運用判定が、現行実装・API仕様通りに動作するかを確認します。正典の R = δ/τ や正規状態分類の検証ではありません。

### ■ 実行方法

```bash

# 判定サービスが localhost:8080 で動いている場合

python han_validation_test.py

```

### ■ 検証内容

1. **正常系 (PASS)**: 低負荷時のテレメトリで `PASS` が返るか。

2. **異常系 (SILENCE)**: 再試行率、キュー滞留、タイムアウトが閾値を超えた際に即座に `SILENCE` になるか。

3. **Fail-Closed**: テレメトリデータが不完全な場合に、安全のために遮断（SILENCE）されるか。

4. **HOLD判定**: 一度遮断された後、冷却期間（`HOLD_MS`）の間、判定が維持されるか。

入力不備では `SILENCE` と `chain_score: null` が返ります。倍率はサーバー設定の `GAIN_BASE` だけを使用し、リクエストの旧 `tau` または `base_gain` 指定は Fail-Closed になります。

---

## 2. 運用者による導入前チェックリスト

統合（Envoy/Nginxへの反映）前に、以下の項目を確認してください。

* [ ] `gate/han_gate_service.py` が正常に起動しているか。

* [ ] `CHAIN_SCORE_LIMIT`（既定値 1.0）と `GAIN_BASE`・`GAIN_EMA_ALPHA`・`GAIN_AMPLIFY_LIMIT` が対象の実測に基づいて設定されているか。既定値は普遍的な推奨値ではありません。

* [ ] 判定のレイテンシを検証スクリプトで実測し、対象環境で定めた目標と比較したか。旧版の 10ms は実測保証値ではありません。

* [ ] プロキシ側で `failure_mode_allow: false` (Fail-Closed) が設定されているか。
