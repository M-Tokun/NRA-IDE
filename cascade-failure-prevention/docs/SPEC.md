## 0. このシステムの目的

連鎖崩壊（Cascade Failure）を防ぐために、入口（イングレス境界）で

新しいリクエストを強制的に **Fail-Closed（SILENCE）** することです。

**大切な考え方：**  

このシステムは「最適化」ツールではありません。  

応答速度を上げたり、最良の経路を探したりするものではなく、  

**「連鎖が始まったら入口を静かに止める」防波堤**です。

---

## 1. 必須要件

**R1. 決定論的な判定**  

同じ入力・同じ設定を与えれば、必ず同じ判定が返ります。  

（二重ゆらぎの EMA は状態を持ちますが、その状態も決定論的に更新されます）

**R2. Fail-Closed**  

テレメトリが欠損・不完全な場合は、迷わず SILENCE を返します。  

「情報がないときは動かす」ではなく「情報がないときは止める」が原則です。

**R3. 連鎖反応への集中**  

1つの指標だけが高くても反応しません。  

リトライ・キュー・タイムアウトの「3つが同時に上昇する」パターンに反応します。  

これが連鎖崩壊特有のシグナルだからです。

**R4. シンプルな統合**  

Envoy ext_authz（推奨）と Nginx auth_request に対応しています。  

アプリ側のミドルウェアは最終手段として用意しています。

## 2. 入力テレメトリ

スコープ（service / route / cluster）ごとのスナップショットを受け取ります。

| フィールド | 説明 | 単位 |

|---|---|---|

| retry_rate | リトライ発生数 | req/s |

| dep_timeout_rate | 依存先タイムアウト数 | req/s |

| error_rate | エラー率（参考値、判定には使用しない） | - |

## 3. 設定パラメータ

| パラメータ | 既定値 | 説明 |

|---|---|---|

| R_OP | 1.0 | SILENCE 閾値。低いほど早く止まる（安全方向） |

| TAU_DEFAULT | 1.5 | 吸収厚みの基底値。高いほど安全方向 |

| TAU_EMA_ALPHA | 0.3 | 二重ゆらぎの感度。0〜1、大きいほど最近の変化を重視 |

| TAU_AMPLIFY | 2.0 | τの最大増幅倍率の上限 |

| HOLD_MS | 2000 | SILENCE 最短維持時間（ミリ秒） |

| MAX_CACHE_SIZE | 5000 | スコープ記憶の上限数（メモリ保護） |

| RECOVER_STEP | - | 段階的な再開（省略可能） |

## 4. R の計算式（二重ゆらぎ版）

```

r_raw     = (retry / 10.0) × (queue / 500.0) × (dep_to / 5.0)

EMA(t)    = α × r_raw(t) + (1-α) × EMA(t-1)   ← スコープ別に保持

τ_dynamic = τ_base × clamp(1 + EMA, 1.0, TAU_AMPLIFY)

R         = r_raw × τ_dynamic

```

**「なぜ乗算なのか？」**  

3指標を加算すると「1つが極端に高い」だけでも反応してしまいます。  

乗算にすると「全部が同時に高くないと大きくならない」ので、  

連鎖崩壊特有のパターンだけを狙い撃ちできます。

**「なぜ τ を動的にするのか？（二重ゆらぎ）」**  

静的な τ では、r_raw が急増した瞬間に R が「尖って」急上昇します。  

これにより閾値超過が唐突に起きることがありました。

動的τ（EMA ベース）では、圧力が上がり始めると τ も連動して膨らみます。  

すると R は「じわじわと閾値に近づく」緩やかな山になります。  

これが「山の尖りを丸める」効果であり、予兆段階での早期検知にもつながります。

## 6. 受入基準

| ID | 内容 |

|---|---|

| A1 | 連鎖反応を誘発した状態で、システム全体への伝播が止まること |

| A2 | SILENCE 判定がスナップショット更新から 100ms 以内に行われること |

| A3 | テレメトリを意図的に欠損させると、保守的モード（SILENCE）になること |

| A4 | R_OP / TAU は再デプロイなしに ConfigMap で変更できること |

| A5 | TAU_EMA_ALPHA / TAU_AMPLIFY も再デプロイなしに変更できること |

---

## 7. このシステムがやらないこと

- 「最適な」ルーティングや性能向上

- リアルタイムの因果説明

- SILENCE 件数の最小化（SILENCE は正しい動作です）

- ML・強化学習による自動調整（決定論的設計を壊すため禁止）
