## 0. このシステムの目的

連鎖崩壊（Cascade Failure）を防ぐために、入口（イングレス境界）で

新しいリクエストを強制的に **Fail-Closed（SILENCE）** することです。

**大切な考え方：**  

このシステムは「最適化」ツールではありません。  

応答速度を上げたり、最良の経路を探したりするものではなく、  

**「連鎖が始まったら入口を静かに止める」防波堤**です。

---

## 1. 必須要件

**R1. 決定論的な判定**  

同じ入力・設定・スコープ別 EMA・HOLD 状態・判定時刻を与えれば、同じ判定が返ります。

（入力だけが同じでも、EMA 履歴や HOLD 期限が異なれば結果は変わり得ます）

**R2. Fail-Closed**  

テレメトリが欠損・不完全な場合は、迷わず SILENCE を返します。  

「情報がないときは動かす」ではなく「情報がないときは止める」が原則です。

**R3. 連鎖反応への集中**  

3つの指標の積で判定します。ほかの指標がゼロなら積はゼロですが、非ゼロの場合は1つの極端な値でも閾値に達し得ます。

リトライ・キュー・タイムアウトの現在値を掛け合わせます。上昇傾向そのものは検出していません。

このスコア単独では連鎖崩壊の有無を断定できません。

**R4. シンプルな統合**  

Envoy ext_authz（推奨）と Nginx auth_request に対応しています。  

アプリ側のミドルウェアは最終手段として用意しています。

## 2. 入力テレメトリ

スコープ（service / route / cluster）ごとのスナップショットを受け取ります。

| フィールド | 説明 | 単位 |
|---|---|---|
| retry_rate | リトライ発生数 | req/s |
| queue_depth | キュー滞留数 | 件数 |
| dep_timeout_rate | 依存先タイムアウト数 | req/s |
| error_rate | エラー率（参考値、判定には使用しない） | - |

---

## 3. 設定パラメータ

| パラメータ | 既定値 | 説明 |
|---|---|---|
| CHAIN_SCORE_LIMIT | 1.0 | 非正典スコアの SILENCE 閾値。正の有限値 |
| GAIN_BASE | 1.5 | スコア補助倍率の基底値。正の有限値。正典の吸収厚みτではない |
| GAIN_EMA_ALPHA | 0.3 | 共起値 EMA の係数。有限かつ 0 < α ≤ 1 |
| GAIN_AMPLIFY_LIMIT | 2.0 | 補助倍率の上限比。有限かつ 1 以上 |
| HOLD_MS | 2000 | SILENCE 最短維持時間（ミリ秒） |
| MAX_CACHE_SIZE | 5000 | 現行版では HOLD 用キャッシュの管理値。スコープ別 EMA の件数・期限管理は未実装であり、未解決の実装課題 |

旧版に記載された `RECOVER_STEP`（段階的な再開）は現行ゲートコードでは未実装です。

## 4. 非正典の連鎖予兆スコア

```
cooccurrence(t) = (retry_rate / 10.0) × (queue_depth / 500.0) × (dep_timeout_rate / 5.0)
EMA(t) = α × cooccurrence(t) + (1 - α) × EMA(t-1)  （スコープ別。初回は現在値）
dynamic_gain(t) = GAIN_BASE × min(1 + EMA(t), GAIN_AMPLIFY_LIMIT)
chain_score(t) = cooccurrence(t) × dynamic_gain(t)
chain_score(t) ≥ CHAIN_SCORE_LIMIT なら SILENCE（HOLD 中も SILENCE）
```

正規化定数と閾値はこのゲートの例示設定です。領域根拠のある正規 R = δ/τ、吸収厚みτ、正規状態分類を実装したものではありません。`PASS` / `SILENCE` はローカルな運用判定です。欠損・負値・非有限の必須計測値、無効な設定値、リクエスト側の `tau` / `base_gain` 指定では Fail-Closed により `SILENCE`、応答の `chain_score` は `null` になります。

**「なぜ乗算なのか？」**  

3指標を加算すると「1つが極端に高い」だけでも反応してしまいます。  

乗算では各指標がスコアに寄与します。ただし、1指標が極端に大きければ、ほかが非ゼロでも閾値に達し得ます。

この式だけで連鎖崩壊の有無を証明するものではありません。

**「なぜ補助倍率を動的にするのか？」**

EMA で共起値の履歴を保持し、補助倍率を変化させる例示設計です。

現在値が直前の EMA より高ければ EMA は上昇し、低ければ低下します。

したがって、係数 α を上げれば常に早く SILENCE する、とは言えません。

スコア閾値や倍率の変更は、対象サービス・経路・クラスタの実測値と影響を確認して決めます。

## 6. 受入基準

| ID | 内容 |
|---|---|
| A1 | 連鎖反応を誘発した状態で、システム全体への伝播が止まること |
| A2 | SILENCE 判定がスナップショット更新から 100ms 以内に行われること |
| A3 | テレメトリを意図的に欠損させると、保守的モード（SILENCE）になること |
| A4 | CHAIN_SCORE_LIMIT / GAIN_BASE を ConfigMap で設定し、Pod の更新後に反映されること |
| A5 | GAIN_EMA_ALPHA / GAIN_AMPLIFY_LIMIT も ConfigMap で設定し、Pod の更新後に反映されること |

---

## 7. このシステムがやらないこと

- 「最適な」ルーティングや性能向上

- リアルタイムの因果説明

- SILENCE 件数の最小化（SILENCE は正しい動作です）

- ML・強化学習による自動調整（決定論的設計を壊すため禁止）
