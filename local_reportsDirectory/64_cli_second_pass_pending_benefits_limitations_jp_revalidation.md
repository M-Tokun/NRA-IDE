## 新たに検出した問題

### 1. Handoffを人間への判断委譲として扱う表現が広く残る

問題箇所:

- 「人間への委譲」「委譲を受け取る人間」「定型で人間へ委譲」が残る。
- 見出しと本文に「人間への委譲後」「委譲後の判断」「人間へ渡す」が残る。
- 適用条件にも「委譲手順」「委譲を受ける人間」が残る。
- 固定Handoff証言でLLMによる自由記述の停止説明を禁止する境界がない。

正典境界との衝突:

- Handoffは旧因果経路内から人間へ判断権限を移し、旧Effect-Sideから次の処理へ進む経路ではない。
- Fail-Closed後に提示できるのは固定Effect-Side証言であり、人間が行うのは旧経路外の外部監査である。

影響:

- 人間判断を介して旧Effect-Sideの値、規則、状態、出所を次のCause-Sideへ戻せるように読める。
- Handoff後の自由記述生成や旧履歴内の判断継続を許す余地が残る。

推奨修正案:

- 人間委譲表現を、固定Handoff証言の提示と外部人間監査へ統一する。
- 人間の責任は、終端済み経路外の監査、現場対応、将来の独立対象に対する事前設計へ限定する。
- 固定Handoff証言と最終固定証言では、LLMに自由記述の停止説明を生成させないと明記する。

### 2. LLM三層構成を普遍的な適合前提としている

問題箇所:

- 冒頭で「三層の実装」を一般的な適合前提としている。
- 前提一覧で Pre-NRA / LLM / Post-NRA の責務分離を全実装に要求している。
- 構造ゲートとLLMの分離を一般的なNRA-IDE特性として記述している。

正典境界との衝突:

- Pre-NRA / LLM / Post-NRA は、LLMを含み当該構成を宣言するシステムに対する実装形態であり、NRA-IDE本体または全実装の普遍的要件ではない。
- 普遍的に必要なのはCause-SideとEffect-Sideの権限分離、正典状態挙動、証拠、テストである。

影響:

- NRA-IDEを特定のLLM三層実装へ縮小し、LLMを含まない適合実装を誤って排除する。
- 層数または特定コンポーネント名だけで適合性を判断できるとの誤読を生む。

推奨修正案:

- 三層に関する前提と利益を、LLMを含み三層構成を宣言するシステムへ限定する。
- 一般的前提には権限分離、正典挙動、証拠、テストを置き、層数だけでは適合を判定しないと明記する。

### 3. Effect-Sideから戻せない要素の列挙が不完全

問題箇所:

- LLM出力やログが更新できない対象に「不可逆状態」が残り、状態と不可逆ラッチが分離されていない。
- 変換入力と更新根拠が欠落する一覧がある。
- ログ非再利用を入力、更新根拠、規則根拠、出所に限定している。

正典境界との衝突:

- 旧Effect-Sideの値、正典三閾値、状態、不可逆ラッチ、規則、変換入力、更新根拠、出所は、新旧いずれのCause-Sideにも戻せない。

影響:

- 列挙されていない要素だけを旧Effect-Sideから更新、seed、成立させられるとの誤読余地が残る。

推奨修正案:

- 遮断一覧を、値、正典三閾値、状態、不可逆ラッチ、規則、変換入力、更新根拠、出所へ統一する。
- 自動、手動、人間レビュー、承認、版更新のいずれにも同じ禁止を適用する。

### 4. 後続履歴への非再利用禁止が一部の用途に限定されている

問題箇所:

- 将来規則の段落では禁止対象が旧Effect-Side値と「規則根拠、Cause-Side入力、出所」に限定される。
- 新対象の段落では禁止対象が旧Effect-Side値と構造権威だけに限定される。

正典境界との衝突:

- 古いEffect-Sideを、値、閾値、状態、不可逆ラッチ、規則、変換入力、更新根拠、出所としてimport、名称変更、再構成、再利用してはならない。
- 新しい履歴は独立した新対象、新しいCause-Side観測、新しい規則、新しい因果ダイオードから開始する。

影響:

- 禁止一覧にない名称や用途へ変換すれば、旧Effect-Sideを新履歴へ持ち越せるとの解釈が残る。

推奨修正案:

- import、名称変更、再構成、再利用の禁止対象を完全列挙し、旧Cause-Sideと新Cause-Sideの双方へ適用する。
- 物理的残存物の新規観測は維持し、旧Effect-Side記録や権威の持越しと明確に分離する。
