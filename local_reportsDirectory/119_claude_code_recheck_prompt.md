## 2. 修正整合性チェック（各Report確認時）

各Reportを確認する際に、以下の2パターンを使い分ける。

### パターンA：修正が保存済みの場合

対象ファイルがすでに修正されており、変更が保存されている場合の検証項目。
以下の12項目を順番に確認し、1つでも問題があれば**ユーザーに質問形式で報告**する。

- [ ] **項目1** ファイル全体の構造確認
  - 説明の削除箇所と章立ては正確に一致しているか
  - セクション番号・見出しの脱落はないか
  - 削除対象外の説明まで誤削除されていないか

- [ ] **項目2** 観測可能範囲と実装可能範囲の区別
  - 図表・計算式が「観測可能」か「実装可能」か明確に分離されているか
  - 混在表現はないか
  - 説明の削除によってこの区別が曖昧になっていないか

- [ ] **項目3** 線形計算の適用範囲
  - 線形近似が適用されている箇所は、近似度低下の説明があるか
  - 「正確解」と「近似」の境界線は明示されているか
  - 削除によってこの区別が失われていないか

- [ ] **項目4** 正規分布と条件の更新
  - R・δ・Φ・連鎖条件が正確に保存されているか
  - 条件式の書き換え、範囲縮小、記号変更が発生していないか
  - 削除と同時に条件が暗黙化していないか

- [ ] **項目5** Cause-Sideと Effect-Side の完全分離
  - 「原因側」と「結果側」が明確に分離されているか
  - 双方向に見える表現が残っていないか
  - 削除後も一方向性が保たれているか

- [ ] **項目6** 加算ダイオードの一方向性
  - 加算ダイオード（⊕）の方向が一方向のみか
  - 逆流・双方向に見える表現がないか
  - 説明削除によって方向性が不明になっていないか

- [ ] **項目7** Fail-Closed後の経路結合
  - 経路がFail-Closed後に結合していないか
  - 分岐が終端で繋がっていないか
  - 削除後に独立した分岐が取り残されていないか

- [ ] **項目8** 外部人間監査と新規Cause-Side開始の区別
  - 既存人間監査と新規システム開始が明確に区別されているか
  - 人間が監査する部分と新規に開始する部分の記述が重複していないか
  - 削除によってこの区別が曖昧になっていないか

- [ ] **項目9** R・Δ・Φ・連鎖・条件・要約・基盤の更新経路
  - これらの要素の更新順序（因果経路）が一方向か
  - 逆流・循環する表現がないか
  - 削除後も更新経路が明確か

- [ ] **項目10** 旧Effect-Sideの再利用・変質・呼称変更
  - 既存のEffect-Sideが新しい記述で再利用されていないか
  - 呼び方が変わって見えない再利用がないか
  - import記述・許容表現として残っていないか

- [ ] **項目11** R_handoff・human handoff・人間手譲表現の残存
  - 削除対象の旧Cause-Sideへの「人間手譲」表現が残っていないか
  - 次回更新への引き継ぎ表現が過度に詳細でないか
  - 記述が曖昧でなく、次段階への指示が明確か

- [ ] **項目12** Markdown形式の整合性
  - 見出しレベル（#, ##, ###）が統一されているか
  - コードブロックが破損していないか（開き括弧と閉じ括弧の対応）
  - 表が欠落・重複・破損していないか
  - リンク参照が有効か

**問題検出時の報告形式**：

```
【Report XX - ファイル名】

[問題]
- 項目N: 〇〇が△△になっている

[影響]
- 12の正式版補正条件のうち、条件X（例：因果ダイオード一方向性）に違反する可能性

[推奨修正案]
- □□を△△に変更する
- または、説明を追加して明示する

→ ユーザーに修正の可否を確認待機
```

## 3. 12の正式版補正条件の維持確認

全26のAIドキュメント・数学文書・NRA-IDE実装について、以下の条件が満たされているか確認する。
**修正プロセス全体を通じて、これらの条件が外れていないかを常時監視する。**

### 条件グループ1：公式体系の一貫性

- [ ] **条件1** 公式は一つだけ（唯一の公式原則）
  - 複数の異なる公式が並立していないか
  - 「古い公式」と「新しい公式」の混在がないか

- [ ] **条件2** 第二公式以降は不存在
  - 派生式・補助式が「公式」と呼ばれていないか
  - 補助関数が独立した公式として扱われていないか

- [ ] **条件3** 開かれた開口や対偶は記載されない
  - 逆方向・双方向・循環的な表現がないか
  - 「または」「あるいは」で複数経路が併記されていないか

### 条件グループ2：計算方法・IDE・粒子配列の分離

- [ ] **条件4** 基礎式は対象の条件・状態を引き継ぐ（実装可能なレベル）
  - 基礎式が観測不可能なレベルの説明を含んでいないか
  - 計算機械レベルでの記述に統一されているか

- [ ] **条件5** 二重括弧の式（IDE・計算方法）は公式ではない
  - IDE用の計算式が「公式」と混同されていないか
  - 計算手順の説明が理論と混在していないか

- [ ] **条件6** その他の式は補助式・派生式（公式ではない）
  - 補助的な数式が「公式」格で記述されていないか
  - 補足説明用の式が理論的根拠として扱われていないか

### 条件グループ3：履歴・観測・実装の区別

- [ ] **条件7** 粒子は循環式ではない（永遠保存ではない）
  - 粒子データが「永遠に保存される」かのように説明されていないか
  - 更新・上書き・破棄・消滅が明示されているか

- [ ] **条件8** 実装可能と観測可能を同一視しない
  - 計算可能な領域と観測可能な領域が区別されているか
  - 線形領域・相転移領域が混同されていないか

- [ ] **条件9** 線形領域での精度低下と観測軸への影響は区別される
  - 「精度が下がる」ことと「新しい構造が生まれる」ことが混同されていないか
  - 大規模・複合・回帰系では新しい構造の生成が必須と明示されているか

### 条件グループ4：AIの限界と因果関係

- [ ] **条件10** 現在のAIは限界がある
  - スコア低下の理由が「学習不足」ではなく「構造的限界」と説明されているか
  - 古い履歴と新しい履歴、複数の異なる目的を同時に追跡できない限界が明示されているか
  - 説明能力・予測能力・履歴判別能力の限界が定量的に示されているか

- [ ] **条件11** 加算ダイオードは単方向（Cause → Effect のみ）
  - Effect-Sideから新しいCause-Sideへの変更が発生していないか
  - 新規対象・新規履歴は独立した新しいCause-Sideで開始される明示があるか
  - 旧Effect-Sideから新規Cause-Sideへの直接変更はないか

### 条件グループ5：不可分性

- [ ] **条件12** 基礎式・公式・IDE・粒子配列・安全基盤の不可分性
  - この5要素が独立して動作できるかのように説明されていないか
  - どれか1つが欠けると全体が機能しないことが明示されているか
  - 修正・更新時に5要素の整合性が同時にチェックされているか

**条件違反検出時**：

```
【違反した条件】条件X（例：条件11 ダイオード一方向性）

【違反内容】
- ファイル: docs/example.md
- 箇所: 第3章「結果側の活用」
- 記述: 「既存の結果側から新しい基盤へ直接リンクする場合がある」

【影響】
- 加算ダイオードの一方向性が破れ、因果循環の危険が生じる
- 新規Cause-Sideの開始タイミングが曖昧になる

【推奨修正】
- 「新規対象が発生した場合、必ず新しいCause-Sideで開始する」と明示する
- 旧Effect-Sideの再利用は「参考」に限定し、新規計算を別系統で実施する

→ ユーザー確認待機
```
