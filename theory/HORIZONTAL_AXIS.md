## 1. 目的と位置付け

従来の「縦軸的確認」

$$
V(x_t) = \text{現在の出力単体の妥当性}
$$

は、単一時点の断面しか観察できず、途中の前提混入・要約による不確実性の洗浄・snapshot不一致を検知できない。

これに対し、外部横軸は次を要求する。

$$
H(x_t, a, x_{t+1}, E_t) = \text{証拠を保持した安全な状態遷移}
$$

$$
H_t = (C_t, F_t, D_t, B_t, V_t)
$$

| 記号 | 内容 |
|------|------|
| \(C_t\) | Frozen Snapshot SHA-256（対象内容の一意性） |
| \(F_t\) | 決定論的検出集合（コードポイント、行・列、規則） |
| \(D_t\) | 人間の明示的承認・意図 |
| \(B_t\) | exact baseline（特定出現のみを保持） |
| \(V_t\) | テスト・コマンド実行などの検証証拠 |

状態遷移は、次の論理積が成立する場合にのみ許可される。

$$
H_t \rightarrow H_{t+1}
\iff
\text{Preimage一致}
\land
\text{明示承認}
\land
\text{新規異常なし}
\land
\text{回帰検証成功}
$$

外部横軸はAI内部記憶から独立した外部記録媒体上に固定される。  
これにより、会話の記憶やモデルの内部状態に依存しない拘束が可能になる。

## 2. 基本原則

1. **AIに正しさを認証させない**  
   監視AIは差異検出センサーに留め、正しさの認証・安全性の確定・実行権限の付与を任せない。

2. **合議結果を作らない**  
   複数Agentの出力を自然文で要約・統合しない。不確実性の洗浄を構造的に禁止する。

3. **出力をアトミックなデータ列として外部化する**  
   自然文による報告を禁止し、ASCII限定の構造化レコード（JSON Lines、パイプ区切りDSL等）に強制する。  
   不可視文字・制御文字は生出力せず、ASCIIエスケープ（`\u202E` 等）として出力する。

4. **差異があれば即時閉鎖（Fail-Closed）する**  
   不一致・証拠欠落・前提ズレ・副作用接触の瞬間に、該当主張をCLOSEDとし、下流へ渡さない。

5. **一致を正解認証として扱わない**  
   複数Agentが一致してもCORROBORATEDに留め、決定論的検証または人間の意味確認を経るまで昇格させない。

6. **exact baselineで正当な例外だけを継承する**  
   コードポイント全体や規則全体の全面許可を禁止し、確認済みの特定出現（パス＋SHA-256＋位置＋理由）のみをbaselineへ登録する。

7. **決定論的領域と確率的領域を分離する**  
   - 決定論的領域（ハッシュ、コードポイント走査、構文検査）→ 機械ゲートで完結  
   - 確率的領域（深い思考・仮説検証）→ 自由探索を許容するが、次の境界で例外なくCLOSEDする

## 3. 運用状態（エージェント層）

NRA-IDE正典境界状態とは分離して扱う。

| 状態 | 意味 |
|------|------|
| PROPOSED | Agentが提示しただけ |
| CORROBORATED | 構造化結果が一致した（未検証） |
| CONFLICT | Agent間で不一致 |
| EVIDENCE_MISSING | 再現可能な証拠がない |
| DETERMINISTICALLY_VERIFIED | 機械検証済み |
| HUMAN_APPROVED | 人間が意味または操作を承認 |
| CLOSED | 下流へ渡さない（記録は残す） |

CLOSEDは削除ではない。不一致・証拠不足の記録を保持したまま、その主張に実行権限を与えないことを意味する。

## 4. 二段階ワークフロー

```text
[ 第1段階 : アトミックな観測と外部固定 ]
エージェント群が独立して局所探索を実行
  ↓

  ↓

        │
        ▼ 確定ログの継承

[ 第2段階 : 履歴をアンカーとした構造化 ]

  ↓
```

ログは「振り返り日誌」ではなく「推論の暴走を縛る能動的な拘束具」として位置づける。

## 5. マルチエージェント汚染対策

### 5.1 汚染の四類型
- 文脈汚染：未検証の主張が共有プロンプトや共有メモリへ事実として入る
- 証拠汚染：存在しない結果・不正確な要約・誤った行番号が根拠として再利用される
- 作業ツリー汚染：共有ファイル変更が他Agentに元状態として誤認される
- 権限汚染：調査候補が承認済み操作判断として扱われる

### 5.2 非合議型LIST
各Agentは結論文ではなく主張単位のレコードを返す。  
別Agentの結果は同じ文章へ混ぜない。

```json
{
  "claim_id": "C-001",
  "agent_id": "agent-a",
  "snapshot_sha256": "...",
  "scope": "file.py:18",
  "claim": "U+202Eが存在する",
  "evidence": {
    "codepoint": "U+202E",
    "line": 18,
    "column": 27,
    "escaped_context": "abc\\u202Edef"
  },
  "status": "PROPOSED"
}
```

### 5.3 決定論的比較
- 全Agentに同一のFrozen Snapshotを与える
- 他Agentの回答を先に見せない
- 比較器がフィールド単位で機械比較する
- snapshot不一致の時点で閉鎖する

### 5.4 サブエージェントへの委譲条件
- 対象が狭く明示されている
- 他の仕事から独立している
- 読取専用で進められる
- 出力を機械検証できる
- 元証拠を返せる
- 失敗しても共有状態を変更しない

サブエージェント数は「起動可能数」ではなく「検証可能数」で上限を決める。

## 6. Unicode偽装対策（二重Gate）

Unicode偽装攻撃と実マルウェアは別層で扱う。

### 6.1 入口Gateと出口Gate
```text
外部入力・生成
    ↓
第1防衛線：入力時Unicode Gate
    ↓
IDE・AI・Compiler・テスト
    ↓
第2防衛線：pre-push Gate
    ↓
Remote Repository
```

### 6.2 検出結果の扱い
- 全検出事項をPENDINGから開始する
- AIが自動的にAPPROVEDへ変更することを禁止する
- 生文字ではなくASCIIエスケープで報告する
- 無条件削除と全面許可を禁止する
- exact baselineで正当な出現だけを保持する

### 6.3 実マルウェア検査
Unicode Gateとは別にMalware Gateを置く。  
検査不能は安全ではない（未検査 ≠ 脅威なし）。  
自動駆除は検査工程では無効にし、検出・隔離判断・修復を分離する。

## 7. NRA-IDE正典との接続

- LIST上の運用状態（PROPOSED / CORROBORATED / CONFLICT / CLOSED 等）は、NRA-IDEの正典境界状態とは別層である。
- 運用状態がCLOSEDになった瞬間、その主張に対する連続性は実質的に断絶（ω=0相当）として扱い、下流遷移を禁止する。
- 人間承認（\(D_t\)）が与えられた場合のみ、その主張が新しいbaselineとして \(H_{t+1}\) に継承される。
- 外部横軸はCause-Sideの監査経路を拡張する実践層であり、Effect-Side（LLM生成）にCause-Side権限を与えない。

Sandwich Architecture（`theory/SANDWICH_ARCH.md`）のLayer 01 / Layer 03と外部横軸は相補的である。  
Sandwichが単一LLMの入出力を隔離するのに対し、外部横軸は複数Agent間の証拠継承と差異閉鎖を担当する。

## 8. 実践原則（要約）

1. 単一Agentから始める
2. 追加Agentには独立した限定作業だけを渡す
3. 各Agentへ同じFrozen Snapshotを与える
4. 他Agentの回答を先に見せない
5. 結論ではなく証拠付き主張を返させる
6. 出力を混ぜずLISTへ追記する
7. 差異比較は決定論的に行う
8. 不一致と証拠不足は閉鎖する
9. 一致を正解認証として扱わない
10. 人間と機械の役割を分離する
11. 共有作業ツリーへの書込みを制限する
12. 実行後に同じsnapshot関係を再検証する
